本輪：B17 重審｜日期：2026-10-24｜狀態：**PARTIAL；B17 最終驗收 BLOCKED**｜評分：**65/100**

## 1. 大方向判斷

B17 的方向沒有證據顯示偏離核心，但它目前證明的是「模型介面契約已建立」，不是「AI 思考能力已有效、可靠地運作」。真實 adapter／Runtime 效果未驗證；目前最大的風險是**交付物版本身分對不上，以及新介面把自報欄位當成證據**。不能進入最終驗收。

## 2. 必須修正的漏洞（按影響排序）

### A-001｜ZIP 身分校驗不符 — 阻擋驗收

- **證據：** [B17 ZIP](ForAVAr-main_B17.zip) 實際大小 129,209 bytes；重新計算 SHA-256 為 `3af5194f88bb3d3a8090b0171c6f53ad5b5a9a0faadda0f22bd1951a19bf1702`。 [HANDOFF_B17.md](HANDOFF_B17.md) 卻宣稱前 16 碼為 `909f94267638d853`。
- **漏洞：** 交接不能證明自己描述的就是待驗收封包。
- **建議：** 以實際待驗收 ZIP 重新計算完整 SHA-256、大小、基線 commit 與分支；用同一個產物重新產生／校正 HANDOFF 和覆蓋報告，再回讀比對。不要只改摘要欄位後跳過重核。
- **驗收條件：** 三份檔案都綁定同一 ZIP 完整 SHA-256，且來源／版本一致。ZIP 內 38 項的 CRC 均通過，故目前證據是「身分不符」，不是「ZIP 損壞」或「遭竄改」的證明。

### A-002｜feedback／intake 把非空 ID 當成證據成立

- **證據：** ZIP 內 `adapters/model_adapter.py` 的 `parse_output("feedback")` 僅檢查根因證據 ID 清單非空；`parse_output("intake")` 對基線比較只檢查 `MEASURED` 與非空 ID，未確認 ID 是否存在、狀態是否有效、證據是否支持該主張。intake 也沒有強制核對 `existing_capability_ids` 是否存在於提供的能力清冊。
- **漏洞：** 模型只要填一個虛構、無關或過期 ID，就可能保留 `SUPPORTED`／`ADOPT`。這會污染根因規則與能力採納決策。
- **範圍界線：** 現有主流程 `runtime/foravar_vertical_slice.py` 的 evaluate 路徑已有 evidence ID 查核；本缺陷是新增 feedback／intake 介面未做同等查核，不能擴大說成整條主流程皆未驗證證據。
- **建議：** 將可信 evidence index 和 capability registry 作為輸入；在程式端查 ID、狀態、版本及適用性。缺失或不匹配時必須降為 UNKNOWN／DEFER。增加「不存在 ID、錯誤來源、UNVERIFIED／過期證據、未知 capability ID」負向測試。
- **驗收條件：** 上述四種反例均不能導致 `SUPPORTED` 或 `ADOPT`；每次降級都有可追溯原因。

### B-001｜路由契約前後不一致

- **證據：** `model_adapter.py` 的 route 提示要求至少兩個候選方法，但 adapter validator 及現有主流程只要求候選清單非空。主流程會檢查重複候選、所選方法是否在候選清單內，這部分已有防護。
- **漏洞：** 文件宣稱「比較替代方法」，程式卻允許只有一個候選，接受條件不一致。
- **建議：** 明確決定兩個候選是否為硬性要求。若是，validator 和測試一起強制；若某些任務可只有一個，按任務條件分支，不要只寫在提示詞。
- **驗收條件：** prompt、validator、主流程、測試對候選數規則一致。

### B-002｜覆蓋報告缺少產物來源指紋

- **證據：** [COVERAGE_REPORT.md](COVERAGE_REPORT.md) 列出 54 個問題、121 個功能、44 個流程，但沒有產生時間、來源 commit、ZIP SHA-256 或工具版本。
- **漏洞：** 清單內容看似完整，卻不能證明對應本次 B17 封包。
- **建議：** 報告記錄生成命令、來源 commit、ZIP 完整 SHA-256 與工具版本；失配時不得用來驗收。

### B-003｜測試結果可對帳，但本輪不可獨立確認

- **證據：** ZIP 內 12 個測試檔共有 131 個 `test_` 方法定義；交接聲稱執行 131 項。ZIP 內的 JSON 可解析，且內部 CRC 全通過。
- **限制：** 本輪沒有執行 Python 測試；封包未附可供本輪核對的原始測試 log。因此方法數相符不代表測試通過已被本輪驗證。
- **建議：** 修正 A-001 後重新執行測試，保存原始輸出、命令、Python 版本、來源 commit 與產物 SHA。

### B-004｜回復點尚未確認可取得

HANDOFF 指示以 B16 ZIP 回復，但在本輪檢查的可見檔案清單中未找到相應 B16 封包。這不證明其他位置不存在備份；目前只能標記 **NOT_VERIFIED**。下一次交付須提供確切路徑與完整雜湊，並確認可還原。
