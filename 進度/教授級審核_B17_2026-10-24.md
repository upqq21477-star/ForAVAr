## 1. 大方向

依使用者最新指示，整體專案目前仍處於**規劃階段**。此時只做模擬運行，以發現設計、依賴、狀態轉移與失敗路徑的漏洞；真實整合、Runtime 測試與正式驗收統一延後到最後的 FINAL_TEST。

因此，**目前沒有執行真實 Runtime／最終驗收不是缺陷**。真正的問題是：B17 交接卻把狀態寫成「建置完成、等待最終驗收」，並排入 B18 FINAL_TEST；現有材料只證明有介面範本、契約程式與清單，沒有證明整體規劃已完成。

## 2. 主要缺陷

### A-003｜階段錯置：規劃成果被標成建置完成

- **證據：** [HANDOFF_B17.md](HANDOFF_B17.md) 標示 `BUILD_COMPLETE_PENDING_FINAL_ACCEPTANCE`，並把 B18 指向 FINAL_TEST；但當前全局階段仍是 PLANNING。
- **漏洞：** 「有程式入口／adapter 範本／GAP=0」不等於完整規劃，也不能單靠批次編號把全局階段推到最終驗收。
- **影響：** 規劃缺口尚未處理，就可能要求使用者提前跑正式驗收，並把設計未定與實作失敗混在一起。
- **建議：** 將 B17 降回規劃／模擬材料，標記 `SIMULATION_ONLY`；暫停進入正式實作與 FINAL_TEST。先完成當前整體規劃，再由使用者明確確認階段轉換。
- **完成條件：** 全部必要功能、流程／SOP、接口契約、責任映射、依賴、權限、副作用、錯誤／UNKNOWN 出口、停止／回復方式及最後驗收矩陣均可追溯；所有未決項已裁決或明確排除。

### A-001｜ZIP 與交接檔身分不符

- **證據：** [B17 ZIP](ForAVAr-main_B17.zip) 實際 SHA-256：`3af5194f88bb3d3a8090b0171c6f53ad5b5a9a0faadda0f22bd1951a19bf1702`；[HANDOFF_B17.md](HANDOFF_B17.md) 聲稱前 16 碼為 `909f94267638d853`。
- **漏洞：** 無法確認交接文字與 ZIP 是同一個產物版本。
- **建議／完成條件：** 用同一 ZIP 重新計算完整 SHA-256、大小與基線 commit，校正 HANDOFF 及覆蓋清單；三者版本識別一致後再引用。ZIP 內部 38 項 CRC 均通過，因此已證明的是身分不符，不是 ZIP 損壞或遭竄改。

### A-002｜feedback／intake 把非空 evidence ID 當成證據成立

- **證據：** ZIP 內 `adapters/model_adapter.py` 的 feedback 僅檢查 evidence ID 清單非空；intake 僅檢查 `MEASURED` 加非空 ID，沒有查證 ID 是否存在、狀態／版本是否有效、證據是否支持主張，也沒有完整驗證 capability ID。
- **漏洞：** 虛構、無關或過期 ID 可能讓根因保留 `SUPPORTED`，或讓能力保留 `ADOPT`。
- **建議：** 將可信 evidence index 與 capability registry 作為輸入，於程式端查核引用；為不存在、無關、未驗證／過期 ID 加入模擬反例。
- **範圍界線：** 既有 `runtime/foravar_vertical_slice.py` 的 evaluation 路徑已做 evidence lookup；缺口在新增 feedback／intake 介面，不能擴大為整條主流程皆未查核。

### B-001｜路由規則不一致

route prompt 要求至少兩個候選方法，但 model adapter 只要求候選清單非空。主流程已有檢查重複候選及所選方法是否在清單內；缺口是候選數規則沒有一致定義。應明確決定單一候選是否允許，並讓規格、validator 與模擬案例一致。

### B-002｜覆蓋報告缺少產物來源指紋

[COVERAGE_REPORT.md](COVERAGE_REPORT.md) 列出 54 個問題、121 個功能、44 個流程，但缺少生成時間、來源 commit、ZIP SHA-256 與工具版本。補齊這些欄位，才能證明清單描述的是哪一份規劃／模擬產物。

## 3. 規劃期可做與不可做

| 現階段允許 | 現階段禁止 |
|---|---|
| 設計責任映射、契約、依賴與完整流程 | 把規劃材料宣告為正式建置完成 |
| 用 mock／fake adapter、確定性樣本模擬正常及失敗路徑 | 將模擬結果冒充真實 Runtime／獨立驗收 |
| 模擬檢查 UNKNOWN、拒絕、超時、錯誤、恢復及停止條件 | 要求使用者替未完成的規劃執行正式驗收 |
| 發現問題後修正規劃並重跑受影響的最小模擬 | 規劃未完成就推進 FINAL_TEST |
| 完成規劃後凍結範圍與最終驗收矩陣 | 把「GAP=0」或測試檔存在當成規劃完成證據 |

模擬每次都要標記 `SIMULATION_ONLY`，記錄假設、情境、預期、結果與未涵蓋範圍。模擬只支持指定假設下的設計判斷。
