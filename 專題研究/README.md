# 專題研究工作區

- 類型：PROJECT_WORKSPACE_INDEX
- 狀態：CURRENT_ENTRY / NEW-PROJECT-TRIAL-PENDING
- 唯一責任：列出採新規則開案的專題工作區；不取代 forAVAr 的全域文件索引或變更追溯表。

## 開案規則

每個新題目先建立唯一 ID 並完成資料准入判斷，再決定儲存位置；不得因既有資料夾模板較方便，就把預計退場的原始材料先提交進 forAVAr。若內容需要長期版本追蹤且可留在主庫，可沿用本資料夾模板；若原始材料只需短期處理且結案後應整批退場，參照[主／暫存 repository 分流提案](../參考資料/解析文檔/forAVAr_主專案與暫存專案分流設計提案_2026-10-23.md)與[開案卡／結案清單](../參考資料/解析文檔/暫存儲存庫開案卡與結案驗收清單_v0.1.md)。後者仍是候選流程，須在上傳前完成敏感度、授權與保留判斷。研究結案後才抽取可遷移屬性並比對 forAVAr 既有能力；不同題目可使用不同分析方法。

起始模板：[專題工作區資料夾與分類模板](./_模板/專題工作區資料夾與分類模板_v0.1.md)。設計與採納閘門：[專題隔離與基礎屬性歸因流程規劃](../參考資料/解析文檔/專題隔離與基礎屬性歸因流程規劃_2026-10-22.md)。

**儲存邊界提醒（候選未採納）：** 本入口描述的是 forAVAr 內的資料夾隔離，只能分開路徑與責任，不能分開 Git 歷史。短期原始資料若預計整批退場，另有[主儲存庫與暫存專案分流提案](../參考資料/解析文檔/forAVAr_主專案與暫存專案分流設計提案_2026-10-23.md)供比較。正式裁定前，本入口不代表已改用外部暫存庫。

## 新專題命名

建議格式：`PRJ-YYYYMMDD-短題目`，資料夾路徑為 `專題研究/PRJ-YYYYMMDD-短題目/`。開案時至少建 `README.md`、`00_開案契約與範圍.md`、`01_來源與證據清冊.md`；分析分支按實際題目與研究方法建立，結案時才建立屬性抽取與系統納入評估檔。不需預先建立空白的未用文件。

## 專題清單

目前尚未有按此命名規則新建並結案的專題。既有專題依各自現有位置管理，不為套用新規則而搬移或複製；清除範圍依已核准的退場程序處理。

## 邊界

本索引只負責專題工作區，不維護跨專題問題清單、系統能力登錄、SOP 狀態或完整參考資料索引。可遷移的候選屬性需回鏈專題與來源，系統狀態以 forAVAr 對應的唯一權威文件為準。
