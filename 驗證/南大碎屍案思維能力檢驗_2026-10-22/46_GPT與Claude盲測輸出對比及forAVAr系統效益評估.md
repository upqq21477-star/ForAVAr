## 4. 四份輸出的具體優劣

### 4.1 GPT-A

**優點**
- 摘要直接，對資料限制與結論界線交代完整。
- 日期競爭線和家屬事件拆分清楚。
- H-A／B／C 有支持、限制、替代解釋與區分性材料。
- 不將職業／地理推測轉成真實人物指控。

**不足**
- 來源依賴及主張的原子化不及 B 條件。
- 研究行動有優先方向，但資訊價值、存取成本與執行狀態的比較較粗。
- 雖然提出停止條件，仍比較偏總結式描述，第三方不容易逐列稽核每項關鍵主張。

**評價**：在固定資料包下，直接分析基線已達不錯水準；結構化流程不是從零開始改善推理，而是補強審核和重複執行的一致性。

### 4.2 GPT-B

**優點**
- 以原子主張 ID、來源、證據等級和衝突欄位固定主要結果。
- 把 T1／T2／T3 及發現點模型分開，並寫出反證條件。
- 研究行動有排序，並明確把未執行的行動標記為阻塞。
- 對官方狀態採「未找到可核驗資料」而非「已證明不存在」的表述。

**不足**
- 台帳雖可追溯，但來源獨立性仍主要是「可能同源」層級，沒有真正重建出完整引用依賴圖。
- 結構表較多，篇幅和維護成本高於 A；若沒有新增資料，重複台帳可能產生形式性工作。
- 仍需要人工檢查每個來源等級的定義是否一致，以及行動是否真的可執行。

**評價**：四份中，GPT-B 展示出較好的操作化與審核便利性；其增益主要是把分析結果轉成可驗收的研究工作單，而不是生成新的案件證據。

### 4.3 Claude-A

**優點**
- 自然分析較完整，對替代解釋的舉例較充足。
- 把「見認屍啟事可能表示身份確認程序仍在進行」明確標作推論，而不是定論。
- 指出發現點不能直接形成精確地圖或棄置時間線。
- 自評中列出來源同源、公告語義等潛在錯誤。

**不足**
- 某些來源標示仍依賴固定資料包的彙總段落，未必都能回指到單一上游報導。
- 研究行動排序與阻塞規格較概括。
- 相較 B，第三方不必然能從表格快速找到每一項主張的反證條件與停止條件。

**評價**：直接分析表現成熟，說明一般模型在明確、品質良好的資料包下，也可能自行產生相當健全的證據意識；不能把所有良好行為都算作結構化系統的獨有能力。

### 4.4 Claude-B

**優點**
- 原子主張台帳最完整之一，將時間線與發現點競爭模型分離。
- H-A／B／C 各列支持條件、反證條件、替代解釋、區分性資料和停止條件。
- 行動排序列出資訊價值、區辨力、成本及可執行性，明確聲明本輪沒有實際完成任何行動。
- 對傳聞中的私人個人採避免重述、不可作證據的處理。

**不足**
- 採用 E0–E4，且把 E0 定為原始證據、E4 定為匿名傳聞。這種反向於常見直覺的編碼本身可以使用，但必須反覆提醒「數字越低證據越強」，增加讀表負擔；若後續與另一份 E0–E3 定義不同的台帳合併，很容易發生語義衝突。
- 開頭將資料包概括為「2016–2022 年的媒體、回憶與傳聞」，但資料包 S2 描述的是 2008 年的南都回顧／後續重刊，因此時間範圍概括不夠準確。
- 對 S4／S5 同源的處理仍是可能性判斷，尚無完整引用鏈證明。
- 表格數量提升了追溯性，但也增加維護量；若下一輪不能取得新資料，繼續細分可能收益不高。

**評價**：Claude-B 的研究操作規格相當清楚，但有小型來源／框架精確性問題。結構化輸出不應因版面完整就免除事實核對。

## 5. 與 forAVAr 自身結論的比較

### 5.1 相同處

第 41 號綜合報告和四份 GPT／Claude 輸出，在核心案件判斷上沒有實質分歧：不選定失蹤日、不強行合併發現點、不將落網傳聞當真、不為匿名模型產生個人有罪百分比，並把原始證據取得列為主要下一步。

第 42 號已把「至少三個候選方向」轉化成三組可檢驗假說。這也與四份盲測輸出一致。這表示 forAVAr 的前置研究成果與一般模型直接分析的結論相容，但不代表 forAVAr 比其他模型更能判定真兇。

### 5.2 forAVAr 可能有的優勢

1. **跨輪次的長期記錄**：能保存哪些主張已處理、哪些仍衝突、哪些來源已查、哪些行動未完成，不必每一輪重新建立背景。
2. **主張狀態與研究歷史可回查**：第 37 號起已有 Claim／Source／Evidence／Action 台帳，第 39–42 號分別記錄時間線、發現點、歷史傳聞與候選模型，較容易避免重複研究。
3. **停止條件與資料阻塞**：能把「不能取得原件」與「已驗證不存在」分開，且設定原件不可得時的退出方式。
4. **文件化工作流**：適合長期、大量、多人或多輪研究，因為輸出不只是一份回答，而是保留版本、來源限制、下一步及驗收條件。

這些是從專案文件結構中能觀察到的設計優勢，不是已經由盲測數據證明的性能提升。

### 5.3 forAVAr 的劣勢與風險

1. **流程成本**：多層台帳、競爭模型、審計文件與版本維護會增加輸出量和處理時間。若任務本來簡單，直接分析可能更有效率。
2. **形式化偏誤**：一旦欄位固定，容易把資料硬塞進欄位或過早量化；結構完整不代表來源已核實。
3. **重複文件與狀態漂移風險**：若 README、台帳和綜合報告沒有同步，可能出現不同文件保存過時判斷。必須維持單一主張狀態源或對版本差異做驗收。
4. **依賴原始材料存取**：本案核心困難是尚未取得原始通告、同期現場資料及法醫／物證資料。再好的框架也無法替代這些材料。
5. **缺少端到端實測**：本次實驗沒有真的測試完整 Runtime，也沒有測試 P1／P2 的工具調用、持久化、來源記錄或自動驗收，所以目前無法確認這些能力是否穩定工作。

### 5.4 是否存在「明顯差異」？

要分三種差異回答：

- **案件結論差異：沒有明顯差異。** 四份輸出與 forAVAr 的核心結論一致，沒有證據顯示本系統在此資料包上得到更準確的案件結論。
- **可稽核結構差異：有初步差異。** B 條件比 A 更明確地列出主張台帳、反證條件、區分性材料、停止條件與阻塞狀態；這種差異可觀察、可解釋。
- **完整系統效能差異：尚未證明。** 此次只比較了固定資料包下的提示流程，沒有測試跨輪次記憶、原始文獻取得、Runtime 和自動驗收的端到端能力。

更準確的表述是：**這輪資料支持「結構化流程可能提升答案的審核便利性與研究行動可操作性」，但尚未支持「forAVAr 相對原始模型具有顯著、穩定、跨任務的整體性能優勢」。**

## 6. 本次盲測的有效性問題

這是本次最重要的限制，必須在評估增益之前先處理。

### 6.1 A／B 不獨立

GPT 表示先完成 A，再於相同對話完成 B；Claude 也明示 A、B 在同一次對話完成。因此 B 能看到 A 的分析內容，可能重用既有的時間線、假說、資料缺口及語句。B 的表現不再只反映結構化指令效果，可能包含順序和上下文污染。

### 6.2 隔離未完全驗證

GPT 說曾使用 GitHub 連接器讀取兩份題詞，Claude 也說使用題詞檔。它們均承認無法證明工具／記憶完全隔離。這不代表必然讀取了案件資料包以外的事實，但足以讓這次測試不能稱為嚴格失憶盲測。

### 6.3 執行環境資訊不完整

目前只知道 GPT 處理時間 1 分 5 秒。Claude 沒有對等處理時間，模型精確版本、溫度、輸出 token 數、是否同樣使用檔案工具及運行模式未統一。效率分數因此尤其不可靠。

### 6.4 評分並非盲評

本文件的四組分數由知道條件和模型名稱的評估者事後給出。這些分數可用於指出具體弱點，但不得當成無偏見的統計比較。

### 6.5 測試的不是完整 forAVAr

資料包要求兩個條件都不要搜尋外部資料。這對隔離比較有好處，卻也排除了 forAVAr 過往研究可能使用的來源查找、持續台帳、跨輪次版本管理與 Runtime 行動。因此本輪主要測的是「分析提示流程」，不是全系統。

## 7. 下一輪如何真正測出差異

### 7.1 最小修正實驗

1. 不再讓同一對話連做 A、B。A 與 B 必須使用兩個獨立的新對話。
2. 直接把完整題詞貼進對話，不需要為取得題詞而呼叫 GitHub 或外部工具。
3. 使用同一模型、同一版本、同一資料包與同等輸出上限；先完成 A、B，再由第三者隨機標成 X、Y。
4. 在揭盲前使用第 43 號量表評分，並記錄每個錯誤的具體原文及所在段落。
5. 至少三次獨立配對；一次 A/B 只屬初步結果。

### 7.2 真正測試 forAVAr 的系統能力

另外設置 C 條件（完整 forAVAr 流程），但必須確認測試環境可用且有執行收據：
- 同一份資料包進入系統；
- 系統生成 Claim／Source／Evidence／Action；
- 對衝突、同源轉載、缺失原件、反證及錯誤結案進行固定測試；
- 保留實際工具調用、來源 URL、文件提交紀錄、版本、延遲、失敗情況與人工修正；
- 以 A、B、C 三組盲評，而不是用輸出長度判斷效果。

若 Runtime 根本沒有執行，C 組須標記 BLOCKED，不能用專案文件設計取代實測結果。

### 7.3 預先定義何者算有增益

只有在重複測試中出現以下現象，才應認定有實際收益：
- 事實與來源錯誤穩定下降；
- 明示矛盾及事件拆分遺漏下降；
- 能提出更具區分力且可以執行的下一步；
- 阻塞條件與停止條件更正確；
- 審核成本降低，或品質增益值得其額外時間成本。

若只增加字數、表格和術語，錯誤率沒有下降，或直接分析已同樣正確，就不應繼續擴張流程。

## 8. 最終判斷

1. **結論一致性：高。** GPT-A、GPT-B、Claude-A、Claude-B 與 forAVAr 第 41／42 號的核心結論基本相同。
2. **結構化流程的可見優勢：中等、集中在可追溯性與行動規格。** B 更容易做第三方審核，對長期研究也更容易累積；但較長且更複雜。
3. **實質推理差異：小。** A 本身已能處理主要矛盾、避免不當指控並提出原件需求；B 沒有找到新事實，也沒有讓假說排序成為可能。
4. **forAVAr 系統優勢：具有合理設計依據，尚未被本次盲測證明。** 專案持久記錄、版本化、台帳和停止機制是可能優勢；需要與獨立的新對話及真正 Runtime 測試分開驗證。
5. **本次盲測有效性：不足以作強因果結論。** A／B 同對話、非完全隔離、無盲評、執行環境不齊是主要混淆因素。
6. **建議：不要因這次結果繼續新增架構。** 保留目前能帶來可追溯性的結構化流程，先修正測試方法，進行獨立、重複、匿名評分；只有在測出可重現的錯誤下降或行動價值提升後，才將其列為經驗證的系統優勢。

**總結：目前觀察到的是「B 條件讓相同的好結論更容易稽核」，不是「系統產生了更準確的真兇判斷」。最合理的下一步是重做乾淨的獨立盲測，並另行測試完整 Runtime，而不是增加更多框架。**
