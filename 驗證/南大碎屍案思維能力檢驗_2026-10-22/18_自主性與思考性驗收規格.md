- 唯一責任：定義如何分辨「會產出文字」與「能自主推進問題解決」，並以本案已發生的行為做一次初步驗收。
- 範圍：本文件是測試紀錄與候選規格，不是已核准的全系統 SOP；不修改主企劃，也不改寫 P1／P2。

## 1. 成功定義：不是文件完成，而是問題狀態改變

測試的核心不是內容長度，而是系統能否在每次迭代中做出有依據的下一步選擇，並讓待解問題變得更可判定。每一輪都必須交代：

1. **當前問題：** 這一輪要裁定的原子問題是什麼？
2. **競爭解釋：** 哪些解釋符合目前材料？各自預測會看到什麼資料？
3. **區辨行動：** 哪一項搜尋、檢查或計算最可能區分這些解釋？為什麼比其他動作優先？
4. **執行證據：** 實際查了什麼、取得了什麼、工具失敗或權限受限在哪裡？
5. **證據更新：** 新材料是否支持、削弱或沒有改變原判斷？
6. **下一步與終止狀態：** 繼續、改道、BLOCKED、NOT_TESTABLE、RESOLVED 或 REOPENED。每個未解問題必須有下一個行動或明確阻塞原因。

如果每輪只增加文件，卻未改變問題分解、證據品質、候選解排序或下一步選擇，即不算有效閉環。

## 2. 最小閉環控制

```
定義問題
  → 盤點既有能力與已知材料
  → 拆成可驗證子問題
  → 提出競爭解釋與區辨性預測
  → 選最高資訊價值的下一步
  → 執行搜尋／查核／測試
  → 比對來源與反證
  → 更新狀態
      ├─ 證據達門檻 → RESOLVED（僅限該子問題）
      ├─ 新資料改變判斷 → REOPENED / 重新排序
      ├─ 原路徑低增益 → 切換來源或方法
      └─ 必要材料不可得 → BLOCKED / NOT_TESTABLE
```

「RESOLVED」只適用於被直接驗證的子問題；不得把一個日期矛盾的釐清升格成整個案件已解決。

## 3. 停損及改道規則

- 同一研究路徑連續兩輪只得到重複或同源資料：停止原路徑，不再用更多轉載增加表面支持度。
- 一手材料不可線上取得：轉向館藏目錄、檔案服務、官方公開文書、原始資料保管機構或其他可驗證的資料取得方法。
- 需要打電話、登入授權資料庫、實體到館或其他工具目前無法執行：明確標記 HUMAN_ACTION_REQUIRED／BLOCKED，列出具體查詢目標；不可聲稱已完成。
- 新資料出現來源衝突：先檢查來源譜系、主張定義與時間粒度，不採文章數量多數決。
- 假說無可區辨預測，或缺乏必要基率／樣本：降低其優先級或標 NOT_TESTABLE，不製造精確機率。
- 任一重要結論被新的原件、反證或可信來源推翻：重新開啟該子問題，不維持已失效的舊結論。

## 5. 驗收判定

本輪可支持的結論是：在這次受控研究任務中，觀察到一些任務層級的主動性——能自發拆分問題、搜尋多來源、檢查來源依賴、保留矛盾、發現下一步的目標錯配並調整研究路徑。

本輪不能支持的結論是：系統已具備持續自主運作能力、能自行取得所有必要資料、任何時候都會自動觸發正確方法，或修改後的系統能力已量化提升。沒有執行既有 P1／P2 程式模組；沒有執行跨任務盲測；沒有驗證無人監督下的持續運作。**因此本輪判為 AUTONOMY_OBSERVED_BUT_NOT_PROVEN，案件判為 NOT_SOLVED。**

## 6. 下一輪真正的驗收方法

要把初步觀察升級為系統能力證據，需用事先固定的任務集做配對試驗，而不是讓系統自己評自己：

- 至少選取不同領域、不同證據可得性與不同風險等級的任務；其中需包含來源矛盾、搜尋失敗、假設不成立、需切換資料渠道及可由公開證據解決的題目。
- 以相同任務比較修正前後兩種流程；讓獨立評審在不知道版本的情況下評分。
- 量測漏掉關鍵分支的比例、重要主張無來源比例、同源資料重複計數率、無效搜尋輪數、成功解決的子問題比例、錯誤結案率、實際工具執行成功率及成本。
- 事先定義各指標與通過門檻；不得在看到結果後才改成功標準。
- 任務、評分規則、原始輸出、工具執行紀錄與錯誤案例需可重現。一次成功不能代表通用能力，模擬通過不能代表真實環境通過。

在完成這類配對試驗前，所有新增觸發規則都只能維持 CANDIDATE，不得宣稱已落地或證明有效。
