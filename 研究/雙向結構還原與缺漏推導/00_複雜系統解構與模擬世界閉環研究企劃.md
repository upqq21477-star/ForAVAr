## 摘要：本研究究竟要找出什麼

本研究要從現實世界、成熟領域模型和可觀察系統中，**總結可重複使用的規律，將它們壓縮成一份精簡、可推導的系統總覽，再用這份總覽反向檢查具體系統的缺漏。**

研究對象不是某款遊戲由 Demo 到成品的歷史，也不是開發者如何逐步修 Bug。過去資料、版本紀錄和來源位置只用於追溯既有資訊、確認採用哪個版本，以及辨明哪些結論已有依據；研究本身要做的是比較、歸納、抽象、形成規律與檢查方法。

以戰爭遊戲為例，不是把某款遊戲的兵種、公式、程式歷程逐項抄錄，而是先問：在什麼尺度和條件下，戰鬥結果主要受哪些因素影響？兵力數量、單位能力、士氣、訓練、組織、地形、部署、情報、指揮與補給各自如何作用？它們是直接加總、倍率修正、條件門檻、相互制約，還是會隨時間改變的狀態？把這些因素整理成一個簡化模型後，再回頭檢查具體設計：是否漏掉會改變結果的因素？是否把相關性誤當因果？公式是否忽略了部署、持續作戰能力或崩潰條件？

**最終產物應是一份「最小系統總覽」：它不列舉所有可能的功能，而是列出理解一類系統必須考慮的核心構成、常見作用機制、關係型態和缺漏提問。** 具體課題再依目標與尺度，從總覽中選取適用部分、定義變數和規則，並標記不適用、未知與尚待驗證的內容。

本研究的目標不是宣稱找到了所有系統的單一萬能公式，而是建立一種可靠的歸納方法：從現實或成熟領域的證據中找出簡潔規律，辨明規律的適用條件，再用它們發現具體模型內的重要缺口。

## 1. 範圍校正與研究邊界

### 1.1 歷史資料的角色

歷史資料可以回答「某項規則曾經被記錄在哪裡、目前採用的是哪個版本、舊結論是否有可追溯依據」。它不會自動成為研究主題。

因此，本研究不以重建某款遊戲的開發時間線、整理歷次 Bug、追蹤每次需求變更或復盤某個工作室的專案歷程為目標。除非某項歷史材料能為規律提供直接證據，否則不需要研究它如何隨時間發生。

來源追溯仍然重要，但責任限於來源識別、版本定位、主張依據和適用範圍；不得把追溯資料的產生歷程與本研究要歸納的世界規律混為一談。

### 1.2 遊戲開發經驗的正確用途

遊戲開發中出現的 Bug、數值漏洞、邏輯缺環和跨系統衝突，只能作為反向檢查的輸入或例子。它們可協助辨認某個模型可能缺少哪類因素，例如資源收支、狀態轉換、時間順序、資料所有權、環境條件或系統間作用。

但本研究不把「遊戲團隊如何處理 Bug」當成主體。真正需要歸納的是：為什麼會缺少這些因素？它們能否被提升為通用模型中的一種變數類別、關係規律或必要提問？下一個不相關的系統能否也用相同的規律找到缺漏？

### 1.3 與可視化課題的隔離

本課題獨立於「AI 理解可視化與框架編輯介面」。本課題研究如何抽象世界、建立最小規律模型、推導缺漏；可視化課題研究如何呈現和編輯已形成的理解。圖表可以幫助思考，但不是本研究的成果目標，也不能替代規律歸納。

P2 僅作為思考方法的唯讀參考；本研究不修改 P1、P2，也不把本課題合併成另一套思考核心。

## 2. 核心方法：從現實到規律，再從規律回推缺漏

本研究的基本方向可濃縮成一條雙向路徑：

**現實／領域證據 → 抽取關鍵因素 → 確認因素的作用機制 → 歸納可重用規律 → 壓縮成最小系統總覽 → 建立具體模型 → 由模型結果反向檢查缺漏。**

這不是按時間重建一項產品的開發流程，而是將多來源知識轉換成一套能被再次使用的抽象模型。

### 2.1 正向歸納：如何從多種材料得到共同規律

1. **先確定要解釋的現象。** 例如「為什麼一場戰鬥會勝敗」「為什麼人口會增減」「為什麼一個經濟系統會短缺」；不先固定輸出，就容易蒐集大量與問題無關的知識。
2. **找出改變結果的因素。** 不只列名詞，還要分辨哪些因素是狀態、環境、資源、能力、條件、行動、限制或外部輸入。
3. **抽取作用機制。** 每個因素如何改變結果？是直接作用、透過中介、改變可用能力、限制行動、改變機率，還是影響後續狀態？
4. **比較多個來源與情境。** 找出不同案例中反覆出現的結構，並辨認只在特定年代、技術、規模或環境下才成立的因素。
5. **壓縮成規律。** 把同義或功能相同的因素合併為抽象類別，但不能把機制不同的因素只因名稱相近就合併。
6. **寫出適用條件及反例。** 明確說明規律何時適用、何時失效；若證據只支持近似關係，就不可寫成必然定律。

### 2.2 反向推導：如何用規律找出具體模型的缺漏

1. 固定具體系統要達成的結果、範圍和抽象尺度。
2. 從「結果」向上回推：哪些因素和中介機制可能改變它？
3. 從「輸入與狀態」向前推演：它們經由哪些規則改變狀態，最後影響哪些結果？
4. 把兩個方向的推導比對，找出無法解釋的結果、沒有被承接的因素、缺少定義的狀態和不合理的關係。
5. 對每個疑似缺口判定：它是本目標下的必要條件、特定方案的依賴、可選設計，還是尚未證明的假說。
6. 只把有依據且會實質改變結果的項目保留在必要模型中；不將所有可能因素一股腦加入。

### 2.3 規律不等於通用公式

跨案例反覆出現的因素，不代表每個領域都用同一個公式。數量可能是加總項、乘數或門檻條件；士氣可能改變持續作戰能力、服從或潰退機率，而不一定直接增加攻擊力；地形可能限制可投入兵力、視線、機動和被打擊機會，也不一定適合只用一個固定倍率表示。

本研究要歸納的是「可重用的因素類型與關係型態」，然後依領域證據選擇具體方程式、規則表或狀態轉換。過早追求一條公式，會把未證明的假設藏進數學形式。

## 3. 最小系統總覽：理解一類系統要先看哪些面向

這份總覽是本研究的核心。它不是每個系統都必須實作的功能表，而是一組用來檢查是否漏看關鍵面向的通用分類。

| 面向 | 抽象意義 | 必要提問 | 典型例子 |
|---|---|---|---|
| 1. 目標與結果 | 系統試圖達成、維持或解釋什麼 | 如何判定成功、失敗、優勢、短缺或狀態變化？ | 勝負、存活、產量、人口、任務完成 |
| 2. 主體與實體 | 能採取行動、承受變化或被管理的對象 | 有哪些單位、個體、組織、物件？如何建立、合併、分裂或消失？ | 軍隊、角色、城市、商品、資產 |
| 3. 狀態與屬性 | 描述實體在當下的可變或相對穩定特徵 | 目前有多少、能力多強、處於什麼狀態？單位和範圍是什麼？ | 數量、等級、士氣、耐久、技術、健康 |
| 4. 能力與限制 | 決定主體能做什麼、做到什麼程度 | 有哪些能力上限、門檻、代價、資格或互斥條件？ | 攻擊力、射程、容量、行動點、法規 |
| 5. 環境與位置 | 改變行動成本、作用範圍或結果的外在條件 | 地形、距離、天候、空間、時間、可達性如何改變行為？ | 山地、道路、遮蔽、氣候、交通位置 |
| 6. 資源與流量 | 可累積、消耗、轉移、再生或損失的量 | 從何處產生、流向哪裡、何時消耗、是否守恆？ | 糧草、燃料、金錢、彈藥、工時、人口 |
| 7. 行動與過程 | 將狀態從一種情況轉成另一種情況的機制 | 什麼會觸發行動？輸入、前置條件、成本、結果和失敗分別是什麼？ | 移動、攻擊、交易、生產、繁殖、治療 |
| 8. 互動與關係 | 主體之間如何合作、競爭、依賴、交換或對抗 | 作用方向為何？誰影響誰？是否互相限制或協同？ | 戰鬥對抗、補給、貿易、聯盟、捕食 |
| 9. 資訊與決策 | 主體知道什麼、如何判斷並選擇行動 | 觀測是否完整？命令如何傳遞？錯誤情報、延遲和反應時間如何影響結果？ | 偵察、命令、路徑選擇、玩家決策、AI 行為 |
| 10. 規則與不變條件 | 系統允許、禁止或必須維持的關係 | 哪些條件必須一直成立？哪些轉移非法？何時觸發門檻或終止？ | 資源不可無故增加、狀態機、容量上限 |
| 11. 時間與尺度 | 決定變化的速率、順序、延遲和可觀察粒度 | 以秒、回合、日或更長時間計算？先後順序會改變結果嗎？ | Tick、回合結算、延遲生產、長期消耗 |
| 12. 回饋與適應 | 系統結果反過來影響未來的狀態、行動或規則 | 結果會不會改變士氣、供給、決策、人口或競爭條件？ | 損失導致士氣下降、短缺提高價格、獎勵改變行為 |
| 13. 不確定性與觀測 | 描述隨機、未知、誤差及可見程度 | 哪些是已知事實、假設、概率或觀測不到的狀態？如何知道模型是否合理？ | 命中機率、隨機事件、迷霧、估計值、資料誤差 |

### 3.1 如何使用這份總覽

不要把 13 個面向一律變成 13 個模組。它們是思考鏡頭，不是強制架構。具體課題只需採用會實質影響指定目標的面向；若某一面向不適用，簡短記錄理由即可。若面向適用但資料不足，標記未知，不能默認不存在。

總覽的價值在於避免只看到顯性的功能名稱。例如一份戰鬥設計寫了「攻擊力、防禦力、兵力」，仍可能漏掉環境、部署限制、持續補給、資訊誤差、目標差異、時間與潰退門檻。漏掉的不是另一個功能，而是讓既有因素能正確影響結果的必要機制。

### 3.2 必須分開的四種東西

- **因素／變數：** 系統當下具有什麼特徵，例如兵力 500、士氣 0.7、糧草 200。
- **參數：** 描述規則如何運作的設定，例如每時間單位的消耗率、地形修正、命中係數。
- **機制／規則：** 變數與參數如何造成狀態變化，例如消耗糧草、士氣低於門檻後撤退。
- **結果／指標：** 用來觀察系統行為的輸出，例如傷亡率、勝負、持續作戰時間或任務成功率。

若把這四者混在一起，就容易產生「把士氣列進清單了，卻沒有定義士氣怎麼影響戰鬥」這種假完整。

## 4. 關係型態總覽：因素之間如何作用

規律歸納最重要的部分不是因素清單，而是因素之間的作用方式。下面的類別是常見建模型態，不代表任一領域都必須使用所有型態。

| 關係型態 | 含義 | 典型用途 | 常見漏項 |
|---|---|---|---|
| 加總／扣除 | 多個來源或效果累加 | 收入減支出、總傷害、總產量 | 重複計算、漏算來源 |
| 比例／倍率 | 某因素改變其他能力的有效程度 | 準備狀態、地形適配、設備效率 | 把不獨立的因素重複乘算 |
| 門檻／狀態轉換 | 達到條件後行為或狀態突然改變 | 士氣崩潰、容量滿載、疾病惡化 | 只定義數值，沒定義跨越門檻後的行為 |
| 容量／瓶頸 | 整體輸出被最受限制的環節約束 | 道路通行量、部署寬度、產線瓶頸 | 把總量當成可同時投入的有效量 |
| 條件分支／分段規則 | 不同情境採用不同規則 | 武器克制、不同地形、資源不足 | 規則重疊、無預設分支、優先序不清 |
| 互補／匹配 | 效果取決於因素組合，不是單獨數值 | 兵種對抗、技能搭配、合作效應 | 只計算單一角色面板，忽略組合 |
| 競爭／對抗 | 一方的行動改變另一方的狀態或選項 | 戰鬥、交易、爭奪資源 | 只建模單邊行動，對方卻不反應 |
| 存量—流量 | 累積量由流入、流出及時間共同決定 | 糧草、資金、人口、耐久累積 | 流量單位錯誤、同一事件重複入帳 |
| 因果鏈／中介 | A 透過 B 影響 C | 補給不足→疲勞→移動下降→更難取得補給 | 直接連 A 和 C，漏掉中間機制 |
| 回饋循環 | 結果反向改變前因或後續決策 | 戰損降士氣、低士氣又增加潰退 | 靜態公式不能表現動態演變 |
| 延遲／排程 | 作用在一段時間後才出現 | 行軍、建造、疾病潛伏、情報傳遞 | 以即時效果取代時間過程 |
| 隨機／分布 | 相同條件仍可能有不同結果 | 命中、事件、談判、自然波動 | 把單次結果當必然規律 |
| 約束／不變量 | 某些狀態在所有合法演化中都必須成立 | 數量守恆、唯一所有權、合法狀態 | 欄位型別通過，但整體約束被破壞 |

### 4.1 因果閉環不是「所有線都連起來」

本研究中的因果閉環指：對指定目的與尺度，重要結果有可理解的作用機制；重要狀態變化有來源；必要的中介、時間延遲、條件、回饋和限制得到表示；模型產生的結果能由規則解釋。若只有連線而沒有機制，並不算閉環。

真正需要循環的地方才建模成回饋循環。一般依賴可以是無環的；不應為了讓圖形封閉，硬把每個關係連成一個圈。

## 5. 將現實壓縮成「最小充分模型」

完整現實的細節遠超任何遊戲或模擬能承載的範圍。本研究應追求的是對指定用途與尺度足夠的模型，不是複製所有細節。

### 5.1 保留哪些因素

一項因素在下列情況之一成立時，應優先保留或進一步研究：

- 在目標情境內會實質改變結果、選擇或結論；
- 是其他重要因素作用的必要中介；
- 會改變資源、狀態合法性、能力上限或系統邊界；
- 會改變主要因果路徑、時間順序或失敗行為；
- 影響跨系統接口、權威資料、存續／終止或重要不變量；
- 不保留就會使模型在已知案例或反例中產生可觀察的錯誤。

### 5.2 哪些細節可以合併或省略

若兩個細節在指定解析度與情境下，對重要結果、規則判定和系統交互沒有可辨識差異，可以考慮聚合成更高層的參數或狀態。這種合併必須明確記錄適用範圍；一旦解析度提高或新情境使差異變得重要，就需拆開。

不能因為一項因素難以量化就直接刪除，也不能因為現實中存在某個現象就自動納入。要衡量它在當前模型中是否足以改變目標結果。

### 5.3 用移除測試來檢查因素的重要性

對候選因素做有限的反事實檢查：

1. 在明確標示假設的條件下，暫時移除或固定該因素。
2. 比較模型預期結果、可行選項、狀態轉移或風險是否出現實質變化。
3. 若結果改變，說明該因素為何重要，以及是直接作用還是中介作用。
4. 若結果沒有可辨識變化，考慮聚合、降級為次要參數或暫不納入。
5. 重新檢查模型是否因本身缺少別的因素，才錯誤地判定該因素不重要。

這不是數學證明，也不能單獨證明因果；它是用來降低臆造與無效細節的有限方法。

## 6. 案例：如何從現實戰鬥歸納成可供遊戲使用的戰力總覽

此案例用來示範「因素歸納→規律抽象→具體模型→反向找缺漏」。它不是宣稱所有戰爭、所有時代或所有遊戲都使用同一條戰力公式。

### 6.1 先定義要解釋的結果

戰鬥結果不只是單一的「戰力分數」。依遊戲目標，至少可能包含：在某段時間內造成的有效損失、守住或奪取目標、可投入戰鬥的比例、己方剩餘戰力、補給持續時間、士氣崩潰或撤退機率。只有先定義結果，才能判斷哪些因素重要。

### 6.2 戰力因素的概念總覽

| 因素群 | 代表因素 | 可能改變的機制 | 缺少時容易出現的模型偏差 |
|---|---|---|---|
| 規模 | 兵力數量、可同時投入數量、預備隊 | 影響可執行行動的總量和持續能力 | 人數多但無法同時投入，仍被當成全員有效 |
| 單位品質 | 訓練、裝備、技術、經驗、等級 | 改變單位的個體效率或能力範圍 | 等級只加面板數值，卻未連到實際行為 |
| 準備與士氣 | 士氣、疲勞、紀律、凝聚力、傷亡狀態 | 改變持續作戰、命令服從、撤退或崩潰條件 | 士氣有數值，對戰場行為完全沒有影響 |
| 部署與位置 | 地形、掩護、坡度、射界、陣形、接戰面 | 限制投入量、移動、命中、暴露和防護 | 兵力總量直接等於可發揮的戰鬥力 |
| 火力與作用能力 | 武器、射程、精度、穿透、攻擊頻率 | 決定在特定目標和條件下造成效果的能力 | 攻防面板相同就假設所有對抗結果相同 |
| 指揮與資訊 | 命令、領導、情報、偵察、通信、反應時間 | 改變目標選擇、協同、部署和行動時機 | 單位永遠全知、同步且能完美執行命令 |
| 補給與持續性 | 彈藥、糧草、燃料、維修、醫療、增援 | 決定有效能力能維持多久、是否逐步下降 | 戰鬥可以無限持續，耗材和損傷不影響結果 |
| 對手與匹配 | 敵方兵種、戰術、裝甲、射程、反制能力 | 決定相對有效性、克制和損失交換 | 把己方能力視為固定，忽略對手行為與反制 |
| 任務與時間 | 攻守目標、要守多久、撤退條件、勝利條件 | 改變何種結果算成功、需要持續多久 | 只比較殲滅數，不看目標是否達成 |
| 不確定性 | 命中波動、誤判、隱蔽、通信失效、突發事件 | 改變結果的分布與風險 | 單一數字被當成無條件、必然的結果 |

上述因素不是一張不可更動的必備清單。美國陸軍的戰力框架將領導、資訊、任務指揮、機動、情報、火力、持續支援及防護等整理為作戰思考架構；作戰研究中的 Lanchester 模型則從兵力數量和單位效果出發，後續研究再納入目標識別、部署限制、士氣與承受損失等因素。這些來源各自代表不同的抽象層級，不能把任何一套分類直接當成所有戰鬥的唯一公式。[來源索引 R5–R7](./外部研究與技術標準索引.md)

### 6.3 從因素清單提升成規律

可以先建立分層的候選模型，而不是立即將所有因素乘在一起。

**第一層：基礎能力。**

基礎能力由可投入的數量、單位在特定任務下的能力，以及組織能否有效協同組成。這個層次回答「理論上有哪些能力」。

**第二層：當下可用能力。**

基礎能力再受到部署條件、地形與位置、準備狀態、資訊品質、指揮執行、補給和時間等條件限制。這回答「在當前情境下，多少能力能真正發揮」。

**第三層：交戰互動與結果。**

當下可用能力要與敵方的能力、部署和反制互相作用；其結果再改變兵力、士氣、耗材、位置、資訊與後續選項。這回答「經過一段時間後，戰場狀態會如何改變」。

作為簡化的概念表示，可以寫成：

- 基礎能力：可投入數量 × 單位有效能力 × 組織協同程度。
- 當下可用能力：基礎能力受到部署、準備、資訊、補給及環境條件的共同影響。
- 戰鬥結果：取決於雙方的可用能力、交互作用、任務目標、時間及狀態轉換。

這不是直接可用的平衡公式。某些因素可能是乘數，有些是上限、有些是狀態門檻、有些只在特定條件下生效。真正的數學形式需由目標情境、資料和可檢驗行為決定。

### 6.4 從概念總覽反推一個粗糙戰鬥模型的缺漏

假設現有設計只寫：

- 戰力 = 兵力數量 × 攻擊力；
- 防禦力用來減少傷害；
- 兵力歸零時戰鬥結束。

使用總覽後，能提出下列待核對問題：

1. 攻擊力代表單位效果，還是整支部隊的總效果？數量是否已經包含在攻擊力內，會不會重複計算？
2. 所有兵力是否都能同時接戰？地形、道路、陣形、射程和部署限制如何處理？
3. 士氣、訓練、疲勞、凝聚力是否影響命令執行、持續作戰或撤退？若不影響，是否符合本遊戲的目標與抽象尺度？
4. 彈藥、糧草、燃料及損傷是否限制持續作戰能力？
5. 情報、目標選擇、通信、反應時間和敵方反制有沒有被表示？
6. 傷亡如何改變後續可用能力？士氣下降是否形成潰退門檻？潰退後部隊如何退出戰鬥？
7. 地形效果究竟影響移動、部署、命中、暴露或防護？是否因不同兵種而異？
8. 勝利判定是否只看殲滅，還是也看時間、據點、撤退、任務和資源？
9. 同一批資源是否可能在不同系統被重複扣除？數值的單位、範圍和更新順序是否明確？
10. 哪些因素確實會改變本遊戲的目標結果？哪些可以在目前尺度下合併或省略？

這份清單不會自動把十項全加進遊戲。它先建立候選缺口，之後需要依遊戲目標、時代背景、玩法尺度和資料依據裁決。這正是「用總覽回推缺漏」，不是「堆疊功能」。

## 7. 從總覽轉成具體系統模型的固定產物

每次套用本方法，只需形成一組最小而穩定的模型內容；不為每個階段新增一份平行研究文件。

| 產物 | 用途 | 最低內容 |
|---|---|---|
| 目標與尺度聲明 | 約束模型要解釋什麼、忽略什麼 | 目標結果、使用情境、空間／時間／細節尺度、非目標 |
| 因素總覽 | 避免重要面向未被考慮 | 適用因素群、簡短理由、不適用項與未知項 |
| 變數與參數表 | 給每個量清楚語意 | 意義、單位、範圍、來源、更新方式、直接或派生狀態 |
| 機制與關係表 | 避免只列變數卻沒有作用規則 | 前置條件、輸入、作用方式、結果、限制、時間延遲 |
| 因果與狀態模型 | 解釋系統如何動態改變 | 重要因果鏈、狀態轉換、存量／流量、回饋、終止條件 |
| 缺漏候選與裁決 | 將總覽變成具體檢查工具 | 疑似缺口、來源或推導依據、必要性類別、接受／否決／未知 |
| 模型適用界線 | 防止把近似模型說成普遍真理 | 可用情境、失效條件、重要假設、尚未涵蓋內容 |
| 核對案例 | 判斷模型是否能解釋預期行為 | 初始條件、輸入、預期結果或性質、實際結果和差異 |

來源與版本可以用精簡的識別資訊追溯；無須重建每份資料如何在過去逐步形成。只保存足以回答「這個規律從哪裡來、採用哪個版本、適用條件是什麼」的資訊。

## 8. 如何判斷歸納出的規律是否可靠

### 8.1 不把單一案例當通用規律

一個戰役、一款遊戲或一個 Bug 只能提供有限證據。需比較不同情境，區分一般機制、特定條件和偶然現象。若規律只在特定條件下成立，就把條件寫進模型。

### 8.2 區分事實、抽象與設計假設

- **觀察／來源事實：** 有明確可定位來源或可重現觀測。
- **歸納規律：** 比較多個案例後抽出的共同結構，仍需要說明支持範圍。
- **模型假設：** 為了達成特定抽象或計算目標而採用的簡化。
- **設計選擇：** 為了玩法、成本或可理解性而刻意採取的規則。
- **未知／待驗證：** 目前證據不足，不能當成已確認的規律。

這些類別不能混成同一種「已確認」標籤。

### 8.3 驗證規律的方法

1. 用一個已知案例確認模型能解釋主要現象。
2. 換到條件不同的案例，檢查規律是否仍適用。
3. 用反例確認模型在什麼條件下會失效。
4. 調整或移除候選因素，觀察結果是否發生有意義的變化。
5. 檢查因果機制、單位、量綱、收支及狀態轉換是否互相一致。
6. 對預測性主張使用獨立資料或獨立評估；若無法核對，只能保留為假說。

測試的目的是判斷規律的用途與邊界，不是無止盡地對每份資料反覆檢驗。當沒有新證據、新情境或新區分能力時，應停止重複檢查。

## 9. 與思考核心的關係

P2 的思考核心僅提供一般方法原則：先固定目標與邊界，建立問題模型，分清已知／推論／未知，按問題選取方法，並由證據判斷結果。本研究把這些原則具體化為領域規律抽象和系統總覽，不建立另一套 Brain。

| 一般思考職責 | 本研究中的具體運用 |
|---|---|
| 任務定向 | 固定要解釋的結果、範圍和抽象尺度 |
| 問題表徵 | 把現實因素、狀態、機制、約束與未知顯式化 |
| 推理生成 | 比較不同來源與案例，歸納共同規律，提出缺漏候選 |
| 結果校驗 | 用已知案例、反例、敏感度、收支和狀態約束核對模型 |
| 認知調節 | 證據不支持時修正規律、縮小適用範圍或保留未知，而不是把假設固定成真理 |

P2 的參考文件保持唯讀。本研究不推斷其程式已完整實作，也不修改 P1／P2 的任何內容。

## 10. 研究評估與完成條件

本研究不能只以文件篇幅、因素數量或模型圖的完整程度評估。必須判斷「歸納出的總覽是否能在新案例中找到真正有影響的缺漏，同時避免過度新增因素」。

### 10.1 最小研究試驗

先選一個有足夠外部模型與可核對資料的領域，戰鬥系統可作第一個試驗：

1. 從多個可靠來源歸納因素群、主要作用機制與適用條件。
2. 把共同因素整理成最小系統總覽，不直接抄錄任何單一來源的完整分類。
3. 準備一個已知答案的簡化模型，保留部分關鍵機制不提供給分析者。
4. 使用總覽反向推導缺漏，將候選與預先封存的必要項對照。
5. 記錄找到的正確缺漏、錯誤候選、被省略的非關鍵細節，以及需要花費的成本。
6. 用另一個條件或不同類型的案例檢查總覽能否遷移，而不是只對第一個案例有效。

### 10.2 評估指標

| 指標 | 要回答的問題 |
|---|---|
| 必要缺漏命中率 | 預先標註且會改變結果的缺漏，有多少被推導出來？ |
| 候選誤報率 | 提出的因素中，有多少不必要、不成立或缺乏證據？ |
| 規律可遷移性 | 同一套抽象類別能否用於另一個案例，而不必重新創建整套概念？ |
| 模型簡約性 | 能否用更少的關鍵變數與規則解釋同一組重要結果？ |
| 因果可解釋性 | 能否指出因素如何透過機制改變結果，而不是只有因素清單？ |
| 數據一致性 | 單位、範圍、流量、權威狀態和更新規則是否互相一致？ |
| 適用邊界辨識 | 能否找出規律何時失效，而不是宣稱它處處有效？ |

若沒有獨立真值或可核對性質，結果只能是定性專家評議，不能宣稱客觀準確率或完整率。

### 10.3 何時可以說本研究方法有效

只有在有區分力的案例中，方法相較自由形式列舉或一般功能清單，能更可靠地找到重要缺漏、較少臆造非必要因素、清楚指出機制與限制，並且可以遷移到另一個案例時，才有理由認為它產生了實際價值。

若方法只讓總覽變得更長、分類更多，卻沒有提升必要缺漏的命中或降低誤報，就應簡化甚至否決這種方法。研究的完成標準是找到可重複驗證的歸納規律，不是把所有可能面向收集成一部百科全書。

## 11. 研究結論

雙向結構還原與缺漏推導應圍繞一個核心循環：

**觀察現實與領域證據 → 歸納主要因素 → 抽象作用機制 → 壓縮成最小系統總覽 → 將總覽套用到具體模型 → 反向推導缺漏 → 以反例與獨立依據核對 → 修正規律及其適用邊界。**

遊戲只是非常適合使用這套方法的應用領域。從戰力、經濟、人口、補給、政治或生態系統，都可以嘗試歸納核心因素和關係，再回推具體系統未定義的地方。

本研究不追求每次從零讀完整個世界，不追求無限增加功能，也不以開發歷史的順序作為研究成果。它要建立的是一套可重用的「世界規律總覽與缺漏推導方法」，使設計者在面對大型課題時，有一個簡明而有根據的參照框架，能知道要問什麼、哪些關係必須定義、何時可以簡化，以及哪些未知不能被假裝成已解決。

**目前版本仍為研究企劃；最小系統總覽是待實證的候選方法，不應宣稱已被證明涵蓋所有領域。** 下一步應以有可核對資料的戰鬥模型完成第一次規律歸納和反向缺漏試驗，再決定哪些分類可升格為通用規律、哪些只能保留為特定領域模型。
