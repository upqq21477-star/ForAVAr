## 5. 接手者下一步

**只做有限驗收，不開始 UI。** 按[下一輪有限驗收計畫](../下一輪有限驗收計畫.md)：

1. 在不使用付費遠端執行、不使用 GitHub Actions、也不新增 API 依賴的前提下，找出能同時讀取固定候選、Schema、規則與 fixtures 的 Python 執行方式。
2. 執行 Python 語法檢查與候選 CLI 的 --check-schema；保存精確命令、環境版本、stdout／stderr 與退出碼。
3. 重跑舊 18 項斷言，並逐項執行支持／反證、循環預算、錯誤輸入、發布閘門、修訂 SHA、Markdown marker、warning 完整性等定向測試。
4. 每項標為 PASS／FAIL／BLOCKED／NOT_RUN，記錄 validator、規則與 Schema SHA。不可借用其他基線的 PASS。
5. 若失敗，最多一輪針對性修正後完整回歸一次；仍失敗則記錄阻擋與決策選項，停止重測。

只有所有規劃案例都有狀態與可定位證據、且停止條件滿足，才可進入 UI／編輯器需求規格。那仍不等於正式 Runtime 或使用者驗收完成。

- 只在本資料夾新增／修改本企劃工作文件；不把工作副本散到其他目錄或儲存庫。
- 外部原始來源路徑僅供追溯，不覆寫、不搬移、不刪除。

- 不把靜態檢查寫成程式測試，不把舊版 PASS 轉移給新版本。
- 不引入付費外部執行服務、GitHub Actions 或新 API 作為必要依賴，除非專案負責人另行批准。
- 不因交接而重做全套研究；只處理具體的新缺陷、新證據或未解阻擋。
