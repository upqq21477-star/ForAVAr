> 狀態：STATIC_REVIEW_COMPLETED / CODE_NOT_EXECUTED。本文是程式碼閱讀結果，不是執行測試報告。

- 規則基線：cross-object-validation.default-v1.json，版本 0.3.0-draft，Git blob SHA：ca393b5761a4bf3c72c807770a56cc3aea6a8e39。

## 發現與處理

### SR-01：輸出版本標籤仍寫成 v0.1

**問題：** v0.2 程式輸出的報告欄位將 validator 標為 v0.1，造成測試產物無法可靠辨認實際程式版本。

**處理：** v0.2.1 輸出標籤改為 v0.2.1。

### SR-02：發布紀錄根型別未檢查

**問題：** 發布紀錄雖可成功解析為 JSON，但若根值是陣列、字串或其他非物件，後續對其呼叫 get() 會造成未受控例外，不符合 fail-closed 的要求。

**處理：** v0.2.1 要求發布紀錄根值為物件，並檢查 warnings、acknowledged_warning_ids 及警告項目的欄位型別；形狀不符就回報阻擋錯誤。

### SR-03：VLD-406 沒有真正核對警告內容與循環路徑

**問題：** v0.2 只核對相關物件 ID 的排序集合，且只要求 release warning 的 message 非空。即使 rule_id、severity 或循環路徑文字被改寫，也可能被接受。規則文件要求保存 warning_id、rule_id、severity、message、related_object_ids 與精確循環路徑。

**處理：** v0.2.1 對 rule_id、severity、message 進行精確比對，保留相關物件 ID 比對，並拒絕重複 warning_id。循環路徑嵌入 message；因此 message 必須與驗證器產生的原始訊息完全一致。

### SR-04：循環搜尋達到上限時可能過早判定為不完整

**問題：** v0.2 在每個新起點開始前，只要 explored 已達上限就立即設定 truncated，未先確認是否還有待探索的邊；恰好耗盡預算但沒有未探索邊時，可能產生保守但不必要的阻擋。

**處理：** v0.2.1 只在實際遇到尚待探索的轉移且預算已滿時標記 truncated。原本的遞迴搜尋上限 1000 也可能接近 Python 預設遞迴深度；原型候選將上限降至 500，以降低在回報 VLD-407 前先發生 RecursionError 的風險。這仍需執行測試確認。

### SR-05：輸入登錄檔根型別沒有明確契約檢查

**問題：** Schema、關係登錄與驗證規則即使是合法 JSON，但根型別或必要容器不符合程式假設，後續流程仍可能未受控失敗。

**處理：** v0.2.1 在建構驗證器前檢查三個輸入的根型別及必要的 relations/release_record 物件。

### SR-06：非 UTF-8 Markdown 匯出未納入診斷路徑

**問題：** Markdown 以 UTF-8 讀取時，UnicodeDecodeError 不屬於 OSError，v0.2 未攔截這個例外。

**處理：** v0.2.1 將 UnicodeDecodeError 納入 VLD-404 的可讀取性錯誤。

### SR-07：日期-only 字串可能被當成發布日期時間

**問題：** datetime.fromisoformat 可接受日期-only 值，與規則要求的 ISO-8601 date-time 不完全一致。

**處理：** v0.2.1 要求 published_at 為字串且含有 T 日期時間分隔符，再解析 ISO-8601 值。

## 尚未證實的事項

以上只根據程式碼閱讀提出修正，不代表修正正確或測試通過。v0.2.1 與規則 v0.3.0-draft 都是 NOT_RUN。仍需執行語法檢查、原有 18 項回歸、發布紀錄錯誤根型別、警告訊息/路徑改寫、重複警告 ID、循環上限邊界、長鏈圖、非 UTF-8 Markdown 與日期-only 輸入等定向測試。
