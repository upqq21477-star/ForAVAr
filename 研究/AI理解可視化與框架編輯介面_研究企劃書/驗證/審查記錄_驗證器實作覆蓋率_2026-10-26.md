# AI 理解可視化框架：驗證器實作覆蓋率與缺口審查

> **日期：** 2026-10-26  
> **狀態：** 靜態程式／規則對照完成；候選驗證器 v0.2 與規則集 v0.3.0 尚未執行  
> **舊測試基線：** cross-object rules 0.2.0-draft；18 個有限範圍原型斷言已記錄  
> **候選基線：** cross-object rules 0.3.0-draft + validator prototype v0.2；NOT_RUN  
> **目的：** 防止將舊版原型的 PASS 套用到尚未執行的新版程式／規則

---

## 1. 結論

驗證器原型 v0.1 並沒有覆蓋所有發布規則。靜態對照發現以下問題：循環探索上限未真正限制搜尋量；資料驗證失敗後，發布驗證仍可能繼續存取不完整欄位；已發布模型仍可能再次進入發布路徑；發布紀錄沒有可靠比對 JSON 與 Markdown 的修訂身分；循環警告 ID 從訊息字串反向解析，而不是由資料欄位明確傳遞。

已建立候選版 [validator_prototype_v0.2.py](../實驗/validator_prototype_v0.2.py)，針對上述問題加入 fail-closed 行為、內容 SHA-256 修訂綁定、Markdown 修訂標記、穩定警告 ID、VLD-302 來源缺失警告，以及 VLD-407 循環搜尋不完整錯誤。**v0.2 尚未執行，所有新增行為維持 NOT_RUN。**

同時調整規則登錄表：
- 把 VLD-107 從作用中的靜態規則中合併退場，因為最終模型裡的懸空來源／條件／邊端點已由 VLD-102、VLD-103、VLD-104 分別回報；真正的刪除前影響預覽必須有 before/after 變更事件，屬於編輯交易層。
- 保留 VLD-303 作人工審查規則，而非假裝可從兩個 enum 值自動推斷語意混用。
- 新增 VLD-407，若循環搜尋未完成就直接阻擋發布。
- 重新確認每個作用中規則 ID 恰好歸屬一個驗證階段。

## 2. 發現的缺口

| ID | 嚴重度 | v0.1 缺口 | v0.2／規則修正 | 新版狀態 |
|---|---|---|---|---|
| IMPL-001 | S | 循環搜尋計數只在找到循環時增加；密集但無環的圖仍可能耗費過多時間 | 改為計算探索的邊轉移；達到上限觸發 VLD-407 error | NOT_RUN |
| IMPL-002 | S | 發布檢查先呼叫一般驗證，但不會在已有 blocking errors 時立即停止；後續可能 dereference 缺欄位物件 | 發布閘門遇到基礎驗證錯誤時先返回，並加 VLD-402 阻擋 | NOT_RUN |
| IMPL-003 | S | 允許 `model_state=published` 再走發布路徑，與不可變修訂政策衝突 | 只允許 `proposed → published`；published 修訂必須另建新 draft | NOT_RUN |
| IMPL-004 | S | 發布紀錄的 `model_revision` 未與正在驗證的模型內容綁定 | 依輸入 JSON 精確位元組計算 SHA-256，發布紀錄必須相符 | NOT_RUN |
| IMPL-005 | S | VLD-404 沒有真正核對 Markdown 與 JSON 是否對應同一修訂 | Markdown 匯出必須包含 `<!-- foravar-model-revision: sha256:<64 hex> -->`，且與 JSON 修訂雜湊相同 | NOT_RUN |
| IMPL-006 | A | 循環警告 ID 從自然語言錯誤訊息以 regex 解析，容易因改寫訊息而失效 | `warning_id` 由規則結果明確傳遞；發布紀錄需保留 warning ID、訊息與相關節點／邊路徑 | NOT_RUN |
| IMPL-007 | A | 對沒有來源的外部事實／推論／假說缺少獨立提醒 | v0.2 加入 VLD-302；不自動修改輸入，也不把來源不存在時的主張升級為 supported | NOT_RUN |
| IMPL-008 | A | VLD-107 與三種引用解析規則重疊，容易重複報錯 | 由 VLD-102／103／104 覆蓋快照驗證；刪除預覽改由變更事件與 UI 交易檢查 | 規則已調整，尚待推演 |
| IMPL-009 | B | VLD-303 的條件無法單靠目前資料欄位可靠判斷 | 明確標記為 manual-review-only；除非模型新增可觀察的審查訊號，不宣稱可自動驗證 | 人工規則 |
| IMPL-010 | A | VLD-301 已由 Schema conditional 強制，但跨物件規則清單未註明重疊 | 明確標註由 Schema enforce；Schema 拒絕時回報 VLD-002，避免再發一條幾乎相同的錯誤 | 規格已註明，待回歸 |

## 3. 規則歸屬一致性

目前候選規則登錄表有 24 個作用中規則 ID，並分配到 L0–L5 階段。靜態檢查結果：

- 所有作用中規則 ID 都有對應階段。
- 沒有任何規則被重複分配到兩個階段。
- 沒有階段指向已退場的 VLD-107。
- L5 包含 VLD-401 至 VLD-407 中仍作用的發布規則，特別是 VLD-406（循環警告紀錄／確認）與 VLD-407（搜尋不完整時 fail-closed）。
- Schema 的 17 個 `relation_type` 與關係登錄表的 17 個 key 完全一致，值唯一，各類型均有 family、meaning、cycle_policy 和 impact 欄位。

以上只屬 JSON／規則結構的靜態一致性；候選規則與驗證器 v0.2 還沒有重新執行，不能標成測試 PASS。

## 4. 舊測試結果與候選版嚴格分流

舊測試報告所引用的規則基線是 v0.2.0-draft，對應驗證器 v0.1。原有 18 個原型斷言仍只代表該舊基線。

候選版 v0.2 與規則集 v0.3.0-draft 改動了循環終止條件、發布閘門及版本比對，因此必須重新跑回歸測試，不能把舊版 18 個 PASS 沿用為新版測試結果。
