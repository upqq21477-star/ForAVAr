# 有限驗收與人類互動層閉環計畫

> 更新日期：2026-10-28
> 狀態：唯讀可視化原型開始施工；驗證器候選仍 BLOCKED／NOT_RUN；編輯／發布／核心整合保持受限。
> 本文件是本研究唯一續作工作清單。規劃完成不代表程式、UI 或使用者成效已通過驗收。

## 0. 正式定位與範圍

圖形認知層是既有 AI 認知架構的人類使用者側延伸，不是需要與核心競爭的新機器推理核心。它可以有獨立的圖形表示、資訊架構、操作狀態機、引導式／固定的人類任務流程及復原機制，目標是降低使用門檻、改善理解與互動。

人類操作流程可以固定、逐步引導；AI 的底層推理路徑則仍按任務與風險適配，不能被 UI 的固定流程綁死。圖形層可以有自己的表示模型，但語意變更必須透過版本化資料契約回饋至既有認知核心，不能形成無法追溯的第二份語意真相。

閉環目標：

**使用者需求 → 既有認知核心建立初始理解 → 圖形層呈現與引導檢視 → 使用者修改／確認 → 驗證與版本化 → 將核准變更回傳核心 → 核心依新理解求解及驗證 → 更新結果／證據／差異 → 使用者再次檢視或結案。**

## 1. 當前基線與硬限制

- 研究資料契約、JSON Schema、關係規則、跨物件規則、狀態機、70 個案例、8 個可定位 fixtures 及驗證器原型已建立。
- 2026-10-27 的 7 項靜態前置檢查記錄為 PASS；這不等同現行驗證器成功執行。
- 現行驗證器候選、Python 語法／CLI、舊 18 項斷言回歸與定向測試仍為 BLOCKED／NOT_RUN。停止條件未達成。
- 8 個可定位 fixtures 中有 2 個有效／證據範例、6 個負向案例；歷史紀錄提及的第 7 個負向 fixture 尚未定位，不得假造。
- 不把舊基線的 PASS 借給現行 SHA；每個 PASS 必須有實際輸出、環境、命令、退出碼及受測檔案 SHA。
- 不以新增付費服務、GitHub Actions 或新 API 作為必要執行依賴，除非專案負責人另行批准。
- 候選驗收未通過前，不啟動寫回、發布、正式編輯及核心整合。安全的唯讀可視化原型是獨立施工軌，可在候選驗收受阻時繼續。

## 2. 階段 A：完成現行資料契約與驗證器候選驗收（受阻時暫停，不阻塞唯讀施工）

### 必做工作

1. 在可讀取現行研究檔案的 Python 3.10+ 環境執行現行候選語法檢查與 CLI `--check-schema`。
2. 載入並驗證現行 Schema、關係登錄表、跨物件規則、案例清單與所有可定位 fixtures。
3. 以現行候選重跑舊版 18 個原型斷言，逐項保留輸入、預期、實際及受測 SHA，不沿用舊 PASS。
4. 分別驗證 `is_evidence_for` 與 `refutes` 的方向、端點、來源條件，以及它們不會自動覆寫 `evidence_status`。
5. 測試循環探索預算、無環稠密圖、精確上限、長鏈與 VLD-407；不完整分析不得被當成完整結果發布。
6. 測試 fail-closed、重複發布限制、proposed 版本門檻、JSON SHA-256／Markdown revision marker、warning ID／內容完整性及錯誤輸入。
7. 每個測試記錄環境與相依版本、命令、stdout、stderr、退出碼、實際結果、受測 SHA 及 PASS／FAIL／BLOCKED／NOT_RUN 狀態。

### 放行條件 A

- 所有規劃案例均有狀態與可定位證據；
- 現行候選與現行規則版本已固定；
- 失敗最多一輪定向修正後完整回歸一次；
- 仍失敗或受環境阻擋時，停止並記錄決策，不能用靜態檢查代替執行。

階段 A 通過只表示資料契約／驗證器基線達到本階段接受條件，不代表 UI、整合 Runtime 或使用者成效完成。

## 3. 階段 B：人類使用者任務與交互需求

正式編輯／發布相關需求仍需候選驗收通過；唯讀原型的基本任務已在施工中，且可用原型收斂觀察，不代表已完成正式 UI 需求驗收。

### 最低使用者任務

1. 檢視 AI 對目標、限制、核心、主軸、骨架、關係、條件、來源與未知的理解。
2. 找到未確認、互相矛盾、來源不足或影響未明的內容。
3. 新增／修改／刪除節點與關係，並看見受影響的下游內容。
4. 對修改進行驗證、查看差異、處理衝突、確認、匯出、復原或回到既有版本。
5. 將核准的語意變更回傳既有認知核心，並能追溯後續輸出使用的是哪個模型版本。

### 必須定義的互動狀態

`viewing`、`editing`、`validation_failed`、`needs_review`、`conflict`、`ready_to_confirm`、`confirmed`、`published`、`reverted`、`blocked`。

每項操作都要列出前置條件、成功結果、錯誤結果、資料是否已提交、恢復方式及是否需重新確認。使用者沒有操作不等於已確認；無效或未完成修改不得悄悄覆蓋已確認版本。

## 4. 階段 C：圖形認知與操作原型

**C0 已獲准先行施工：唯讀框架瀏覽器。** 以手機優先、零外部相依、單一載入模型為原則，先交付樹狀／清單、局部關係圖、卡片、搜尋與詳細資料。C0 不寫回／發布，也不冒充驗證器。

後續正式互動功能仍以以下最小完整切片為目標：

- 主視圖：樹狀／清單；提供核心與重要層級的低負擔導航。
- 關係視圖：局部關係圖與條件／依賴／衝突，不要求同時顯示全圖。
- 詳細面板：節點與關係屬性、來源、證據狀態、確認狀態及未知。
- 差異視圖：相對明確基準版本的新增、刪除、修改及下游影響。
- 操作保護：撤銷／復原、刪除確認、衝突提示、驗證診斷及版本還原。
- 引導流程：用戶可依任務逐步走完；提供跳轉與返回，不把每次互動都限制成僵硬的單一路徑。

原型不需先引入 GraphRAG、圖資料庫、即時多人協作或事件溯源。只有在資料規模、查詢方式或驗收證據證明必要時，才重新評估技術選型。

## 5. 階段 D：與既有認知核心建立明確接口

這是正式整合前的強制設計交付物。

1. **輸入契約：** 核心輸出哪些問題理解、目標、限制、未知、關係、來源與版本欄位供圖形層顯示。
2. **圖形映射契約：** 圖形節點／邊／條件如何對應核心語意物件；新增／刪除／拆分／合併時如何保留穩定 ID 與來源。
3. **編輯事件契約：** 以版本化差異記錄使用者修改、修改原因、審核狀態及影響範圍。
4. **驗證回傳契約：** 驗證器回傳診斷、阻擋原因、需人工裁決項及可發布狀態。
5. **核心回饋契約：** 只把已提交且符合規則的變更傳回核心；明確指出核心需重新處理哪些結論，不暗示其他內容已自動重驗。
6. **結果回流契約：** 核心新輸出、證據與結果狀態可回填圖形層，並顯示相對前版的差異。

圖形表示模型與核心工作模型可以結構不同，但映射必須可檢查，更新必須版本化，兩者不能各自默默修改同一語意而沒有衝突檢查。

## 6. 階段 E：整體閉環模擬驗收

至少覆蓋以下端到端場景：

- 正常流程：初始理解 → 人類檢視 → 修改 → 驗證 → 確認 → 回傳核心 → 新結果回流。
- 錯誤理解：注入錯誤節點或關係，確認使用者可發現並修正，且變更實際回傳。
- 證據不足：來源缺失、來源不支持主張、證據互相衝突時，畫面與核心均不把內容升級為已證實。
- 版本衝突：編輯期間底層版本變更時，拒絕無聲覆寫並提供可處理的差異。
- 故障復原：中途關閉、格式錯誤、驗證失敗、匯出失敗及回復舊版本，確認不產生部分提交或不一致版本。
- 下游傳播：使用者修改核心條件後，所有依賴該條件的舊結論被正確標記為需重驗，而不是假裝已經更新。
- 手機操作：在小畫面下完成選取、編輯、關係檢視、差異查看、確認與復原，不把精準拖曳設為唯一操作方式。

### 放行條件 E

不得出現未經確認的語意覆寫、版本錯配、視圖間語意不一致或未授權發布。每一個失敗案例都需能定位原因、回復到已知版本並重現修正。純模擬只能證明模擬範圍內的行為，不得宣稱使用者效益已證明。

## 7. 階段 F：實際人類使用者驗收

在模擬閉環穩定後才進行。測試前先固定任務、基線、樣本、評分規則及停止條件，不得看過結果後調整通過標準。

評估維度：
- 使用者能否正確指出 AI 理解中的預置錯誤與未知；
- 修正準確度、錯誤修正率及重要遺漏率；
- 任務完成率、完成時間與需要的協助次數；
- 是否理解「來源存在」「證據支持」「人工確認」之間的差別；
- 修改、版本確認、差異查看與復原是否可正確完成；
- 與原有純文字／簡單清單基線相比，是否確實降低操作負擔。

定量目標須在測試前由負責人核定；不得因沒有既有數據就捏造效果。若實際使用者測試不可行，明確保持 BLOCKED／NOT_RUN，不能把專家審查或模擬當成使用者驗收。

## 8. 最終閉環與結案條件

本研究只有同時滿足下列條件，才可標記為 `RESEARCH_CLOSED_ACCEPTED`：

1. 現行資料契約、驗證器及規則基線通過階段 A。
2. 使用者任務、資訊架構、固定引導流程、錯誤狀態與復原方式均可驗收。
3. 圖形層能讀取、修改、驗證、差異比較、確認、匯出及還原版本。
4. 與既有認知核心的輸入／輸出／編輯事件／回饋映射契約已實作並通過端到端閉環。
5. 階段 E 的正向、負向、衝突、故障與復原案例均有實際結果及證據。
6. 階段 F 的人類使用者評估已完成，結論只涵蓋實際測試範圍。
7. 未通過或未執行項目均有明確狀態、影響、責任人及重開條件；不得把 BLOCKED／NOT_RUN 寫成 PASS。
8. 正式企劃、基線清冊、測試結果與實際實作 SHA 已同步；接手者只需一個權威入口。

若以上任一必要條件受環境或資源限制，研究可以在已完成範圍內結案為 `PARTIAL`，但不得標記 `ACCEPTED`。無新證據、新需求或驗收失敗，不重開相同研究；重開時只處理受影響部分。
