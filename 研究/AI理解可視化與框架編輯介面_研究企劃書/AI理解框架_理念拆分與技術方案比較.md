> 版本：0.6.0-digest　｜　日期：2026-10-27  
> 性質：主企劃的精簡決策附件；原 0.5.0 深度研究長文已由本文件蒸餾。Git 歷史仍保留原始版本的可追溯記錄。  
> 主入口：[研究企劃書](./AI理解可視化與框架編輯介面_研究企劃書.md)；完整來源：[外部研究來源與技術標準索引](./參考資料/外部研究來源與技術標準索引.md)。

## 摘要

本文件只保存會影響架構的結論，不重述主企劃的目標和完整資料欄位。核心判斷：在以人類確認、低成本、可移轉及版本可追溯為優先的條件下，先採用 JSON 正式模型、Git 版本基準、JSON Schema 加明確跨物件規則，搭配可切換的輕量視圖；不因為「圖」的概念就先引入圖資料庫或 GraphRAG。

## 1. 已識別的結構性缺口

| 缺口 | 若不修正的後果 | 決策 |
|---|---|---|
| 結構角色與物件類型混為同一欄位 | 核心／主軸等層級語意與需求／功能等物件語意互相污染 | 分開建模 |
| 來源、證據狀態、人工接受及發布狀態合成單一標籤 | 把「有來源」誤當「有支持」，把「人類接受」誤當「事實成立」 | 分開保存和判定 |
| 層級、流程、因果用同一套關係政策 | 不同語意套用錯誤循環與影響規則 | 按 relation_type 登錄政策 |
| 以圖形套件當成資料模型 | 視圖與正式內容分叉，修改不能可靠回寫 | 正式資料先行，視圖只是呈現層 |
| 只輸出 Patch 或文字比較 | 人難以判斷語意變更、衝突和影響 | 依穩定 ID 建立語意差異，再按需輸出 Patch |
| 每次修改都重審全圖 | 成本無限制上升、使用者疲勞 | 依關係政策做局部影響分析，人工裁決保留 |
| 未定義不完整／未知的合法狀態 | AI 會用猜測補齊，讓未確認內容看似確定 | 明確表達未知、待審與拒絕發布狀態 |

## 2. 架構取捨

| 能力／問題 | 建議起始方案 | 暫不選用或不視為替代品 | 原因 |
|---|---|---|---|
| 正式資料 | JSON + 穩定 ID | 直接以畫面狀態當真相 | 易檢查、可攜、可版本化 |
| 歷史與版本 | Git commit／明確 revision | 僅靠日期標籤或可變檔名 | 可定位確切基準與差異 |
| 結構驗證 | JSON Schema Draft 2020-12 | 只靠 LLM 自我檢查 | 可確定性判斷欄位與型別 |
| 跨物件驗證 | 明確規則集＋自訂驗證器 | 期待 Schema 自動涵蓋所有圖規則 | 引用、重複邊、循環與發布是跨物件問題 |
| 語意差異 | 穩定 ID＋欄位／關係分類 | 將 JSON Patch 當成完整語意比對 | Patch 描述操作，不解釋人的語意 |
| 影響分析 | 依關係類型採用 BFS／DFS 或局部遍歷 | 每次改動全圖重新審核 | 範圍有限、路徑可解釋 |
| 循環檢查 | 依關係政策檢查；需要時用 SCC／拓撲方法 | 無條件禁止所有類型的循環 | 有些語意允許循環；要按關係判定 |
| 人機互動 | 樹／清單為主，局部關係圖輔助 | 永遠只顯示一張全圖 | 大型圖會擁擠；不同任務適合不同表示 |
| 來源治理 | 參考 W3C PROV 的實體／活動／來源分離 | 把 URL 欄位當作真實性證明 | 可追溯不等於可信 |
| 後續 AI 取用 | 明確指定已發布修訂與輸出契約 | 讓下游自由讀取任意最新檔 | 避免版本漂移與上下文錯置 |

## 3. 核心資料與狀態決策

- 節點、關係、條件、來源、確認記錄與版本各有明確責任。
- 邊上只保存正式 `relation_type`；政策由 `rule_profile + relation_type` 查詢。
- 層級關係也以正式邊表達，不維護同步的 `parent_ids`。
- `review_status`、`evidence_status`、`model_state` 是獨立狀態軸。
- `is_evidence_for` 和 `refutes` 有明確方向；不因關係存在就升級主張可信度。
- 發布需固定 Schema／規則／驗證器基線，對精確模型修訂作綁定；無法判定時採 fail-closed。
- 影響分析只輸出「待重新檢視候選」，不得冒充對下游內容的真實性判決。

## 4. 驗收導向與停止規則

架構建議只有在下列案例可重現後才算具實證支持：引用／ID 錯誤、關係方向、支持與反證、循環上限、發布拒絕、已發布版本不可再發布、JSON revision SHA、Markdown revision marker、warning 穩定性、錯誤輸入及匯出一致性。

目前 2026-10-27 狀態是：靜態前置檢查 7/7 通過；候選 Python 程式、18 項回歸及新增定向測試仍 BLOCKED／NOT_RUN。不能因本附件完成精簡就把驗收標為完成。完整且唯一的下一步清單見[下一輪有限驗收計畫](./下一輪有限驗收計畫.md)。

規劃只重開於以下情形：新需求、新來源、新的可重現缺陷、驗收失敗或影響架構的決策改變。沒有新證據時，不重複同一輪研究。

## 5. 尚未證實的假說

1. 結構化的可視化校正，可能比純文字摘要更容易讓人發現 AI 誤解；需使用者任務比較證實。
2. 局部關係圖可能降低密集圖的認知負荷；需按圖規模與任務測量。
3. 以穩定 ID 產生語意差異可能提升變更理解；需測量錯誤數、任務時間與漏看率。
4. 版本綁定及發布閘門可能降低下游使用過期框架的機率；需實測。

上述皆為待測假說，不是已證明的效益。
