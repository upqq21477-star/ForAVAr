## 1. 搜尋方式與狀態定義

以事件 ID、操作代碼、問題 ID 或搜尋詞定位，再開對應分支。

- `VERIFIED`：所列範圍的提交、讀回及必要檢查已通過；不代表其他範圍也通過。
- `PARTIAL`：僅完成明列範圍，或仍有未驗證項。
- `BLOCKED`：因來源、權限或環境阻塞，不能判定完成。
- `SUPERSEDED`：該歷史狀態已被後續事件取代；保留歷史，不作現況依據。
- 歷史 VERIFY 狀態詳見各分支。

## 5. 更新規則

1. 事件 ID 單調遞增，不得重用；日期、來源、狀態不明時標 UNKNOWN。
2. 事件詳情僅存一個分支；本表供搜尋。
3. 新事件先判定類型與唯一責任分支，再新增事件明細及本表搜尋列。
4. 移動文件後修正相對路徑，驗收時讀回目標檔、驗證連結並檢查字元上限。
5. 保留原始證據、反例、限制和未驗證狀態；「未查到」不得解讀為「不存在」。
6. 本表供搜尋導航，不等於全庫引用已驗。
