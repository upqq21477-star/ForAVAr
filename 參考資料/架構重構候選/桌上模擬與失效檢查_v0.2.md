# 新版候選框架桌上模擬與失效檢查｜v0.2

- **狀態：** TABLETOP_SIMULATION_COMPLETED／候選設計層通過修正後推演；不是程式測試或 Runtime 驗收。
- **範圍：** 以舊版 F0–F7 條件式流程為基線，檢查新版 AX／KG／S0–S5 在代表任務上的路由完整性。
- **限制：** 舊版 F0–F7 不是已運行的可執行引擎；舊路徑是依文件責任推演的合理路徑示例，不是實測 trace。

## 2. 模擬中發現並修正的設計缺口

| 缺口 | 初始問題 | 修正 |
|---|---|---|
| 直接回答跳過產出狀態 | S1 直接到 S5 會讓驗收前沒有明確產出／執行狀態 | 改成 S1→S4（僅限低風險、無外部副作用的簡單解題），再由 S4→S5 |
| 澄清的等待狀態不明 | 重要歧義沒有明確路由時容易被默默假設 | 加入 S0→S0 的最少澄清／等待守衛 |
| 證據查核缺乏有界重複路徑 | S2 只出不進，未表達有限的定向檢索 | 加入 S2→S2；僅在預期資訊增益大於零且預算／重試限額允許時可重複 |
| 問題契約失效與模型失效混用 | 對反例造成的重框只回到模型階段不足以改寫目標／範圍 | 區分 S5→S1（契約／範圍失效）和 S5→S2（證據／模型失效） |
| 部分來源功能映射的軸／節點不一致 | 個別映射的主責軸不等於目標 KG 節點的 owner_axis | 修正 P1-F10/F33/F42/F43、P2-F19/F27 的候選歸位，使可比對節點的軸責任一致 |

## 3. 模擬結果摘要

- **代表性路由：** 8 類行為案例均在修正後模型中找到明確路徑、回流或終態。
- **結構覆蓋：** P1 48、P2 30、SOP／流程 27、PR 54 共 159 個候選映射 ID，結構檢查無缺項或重複。
- **關係一致性：** 可比對到 KG 節點的 78 項 P1／P2 映射，主責軸與節點 owner 已對齊；L4 狀態、I1–I8 與 SP7 映射屬非 KG 節點責任。
- **仍未通過的部分：** 完整語意歸位、PR 根因映射、正式 SOP 採納、執行測試、自動產生／差異檢查，以及 Runtime 行為。
- **結論：** 桌上模擬確認新版候選的狀態路由已比初稿完整，但只能證明規格內部一致性有所改善；不能證明它比舊版思考品質更高或執行更可靠。

## 4. 下一步驗收閘門

1. 人工審核 P1/P2 78 項的完整來源、輸入／輸出、依賴和接受條件。
2. 人工複核 54 個 PR 路由，優先處理由摘要關鍵詞形成的候選分類。
3. 對澄清、證據重試、重框、阻塞、局部修正、部分完成和停止建立可重現測試案例。
4. 以同一組案例及等同的來源、權限、工具與資源上限，進行舊版／新版對照；記錄品質、錯誤、返工、時間與操作成本。
5. 只有在必要正確性／安全指標不退步，且至少一個預先指定指標有可重現改善時，才建議正式化。
