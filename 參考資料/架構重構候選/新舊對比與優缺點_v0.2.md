# 新舊架構對比與優缺點｜候選 v0.2

- 舊版基線：2026-10-22 四層施工藍圖與細項矩陣。
- 新版候選：四層彈性骨架與狀態路由架構 v0.2。
- 證據狀態：文件比較及設計推理；尚未完成桌上模擬、新舊公平對照或 Runtime 驗收。
- 限制：以下判斷是結構性分析，不是已量測結果。

## 1. 新舊架構對照

| 設計面向 | 舊版 | 新版候選 | 改動理由 |
|---|---|---|---|
| 核心 | 12 條思考不變量候選 | 歸併為 8 組，保留舊 ID 語意映射 | 集中責任，降低重複表述 |
| 主軸 | A1–A6 六軸 | AX1–AX6 六軸，新增責任邊界與不負責事項 | 不擴軸，先消除交界模糊 |
| 骨架 | N01–N18，每軸固定 3 個 | KG-01–KG-26 初始能力契約；節點數可變 | 不以對稱數量決定能力切分 |
| 框架 | F0–F7 條件式流程 | S0–S5 狀態路由、守衛條件及合法終態 | 區分能力歸屬、工作狀態與流程轉移 |
| 支援平面 | 有原則性分類與圖示 | SP1–SP7 定義服務、限制和關係型別 | 能把支援功能歸位但不冒充認知主軸 |
| 功能歸位 | P1/P2 功能樹與四層規格分開 | 78 項逐項候選映射；保留 SOP／PR 原始 ID | 區分列入盤點與新架構已吸收 |
| 關係圖 | 概念展開與回饋箭頭 | 分類、依賴、資料流、授權、證據及驗收分開標示 | 避免把視覺連線當成已驗證契約 |
| 人機版本 | JSON manifest／Markdown HUD 已起步 | 新架構採機器規格＋人類圖表與清單 | 降低人機版漂移；自動同步仍未實作 |

## 2. 舊版的優點與代價

**優點：**四層直觀、交接容易；六軸、十八節點、八個流程標籤提供清楚基線；已納入未知、反證、重框、條件式深度、停止和證據狀態；已有語意審核、映射、節點契約與實驗規劃。

**代價與風險：**
- 每軸三節點的對稱安排可能影響節點切分，讓規格為了整齊而非責任存在。
- L3 是能力分解，L4 是任務流程；若直接連線，容易被誤解成固定一對一。
- F0–F7 雖聲明非強制全走，但短路、回流、終態與守衛條件仍須逐項形式化。
- 四層規格本身不證明 P1／P2 78 項、SOP 和 PR 已完整吸收。

## 3. 新版候選的預期優點與代價

**預期優點（尚未經實驗證實）：**
- 骨架依責任、契約與失敗模式拆併，不固定節點數。
- 能力圖與工作狀態機分工，概念模型不再直接等同流程階段。
- 可明確表達局部修正、方法重選、模型重框、阻塞、未知、拒絕與停止。
- Current、來源、權限、工具、驗收、文件與呈現各有支援平面。
- 每項原始能力保留 ID；候選映射和正式驗收不混為一談。
- 節點契約、關係型別、狀態守衛和來源 ID 可成為後續機器檢查的基礎。

**新增代價與風險：**
- 狀態、節點與關係型別更多；未精簡時容易造成治理膨脹。
- 狀態機需要可判定的條件，否則更難預測或陷入反覆回流。
- 依功能名稱作初步歸位只是假說，仍需核對來源語意和操作契約。
- N01–N18 與 F0–F7 的舊引用需保留別名與對照，避免斷鏈。
- 結構更細不代表正確性更高；新版的淨收益未知。

## 5. 必須測試的新版反例

| 反例 | 新版必須表現出的行為 | 失敗所代表的問題 |
|---|---|---|
| 簡單任務也走重型路徑 | 依低風險守衛走短路徑 | 適應式深度失效 |
| 不確定問題無限回流 | 有重試上限、進展判據及合法停止狀態 | 狀態機可能無限循環 |
| 原功能只因名稱相似便歸位 | 維持候選／未驗證，等待契約核對 | 矩陣製造假覆蓋 |
| 支援平面開始取代思考核心 | 支援只服務、限制或記錄認知責任 | 核心再次偏移 |
| 圖、JSON、Markdown 不一致 | 差異未解決前不宣稱同步完成 | 雙視圖產生多份真相 |
| 只有文件存在卻標記 DONE | DONE 必須綁定接受條件和執行證據 | 證據層級沒有落實 |

## 6. 新舊對照實驗

測試提案，不是已執行結果。兩版使用相同任務、來源、工具權限和資源限制。任務至少涵蓋：簡單問答、意圖歧義、來源衝突、根因診斷、反例引發重框、多檔案施工、權限／成本阻塞、部分成功後結案。

每例記錄目標符合率、來源支持正確性、未知／衝突保留、路由錯誤、必要 Gate 漏過、修正後復發、耗時、工具操作及返工。安全、權限和證據品質不得由速度分數抵銷；測試集、量測口徑與否決條件須在實驗前固定。

## 7. 重構裁定

先保留舊版作 baseline，測試新版的能力契約與 S0–S5 狀態機。若守衛、失敗出口或終態無法明確判定，先縮減新版；若成本上升而品質無改善，簡化或退回舊版。只有在必要安全／正確性指標不退步，且至少一個預先指定品質或效率指標有可重現改善時，才進一步正式化。

**結論：**舊版較簡潔直觀；新版候選在能力伸縮、狀態路由和功能追溯上更有表達力，但複雜度與維護成本增加。現階段不能宣稱新版思考品質或 Runtime 可靠性更高。
