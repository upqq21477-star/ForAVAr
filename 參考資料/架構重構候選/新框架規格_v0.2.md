# 四層彈性骨架與狀態路由架構｜候選 v0.2

- **狀態：** CANDIDATE_FOR_REVIEW；未核准正式化、未執行 Runtime。
- **設計目的：** 保留「核心 → 主軸 → 骨架 → 框架」的渲染方式，修正固定節點配額、概念層與執行層耦合、跨功能歸位不足三個問題。
- **核心變更：** L1/L2 保留；L3 改為可變能力契約圖；L4 改為條件守衛控制的任務狀態路由；支援平面提供橫向服務與限制。
- **圖形視圖：** [四層樹、狀態轉移與關係圖](./新框架結構圖與關係圖_v0.2.md)。

## 1. 設計原則

1. **保留四層語意。** 四層是抽象與責任展開關係，不等同固定執行步驟。
2. **以責任決定拆分。** 不因每個主軸要整齊就固定三個節點；每個節點必須有存在理由、主要責任及驗收條件。
3. **區分歸屬與依賴。** 父子歸屬、資料流、控制流、授權約束、證據支持及驗收連結採不同邊型。
4. **流程由狀態與守衛決定。** 狀態機不等同強制線性 SOP；低風險任務可走短路徑，必要 Gate 不可跳過。
5. **來源功能不因重構而消失。** 保留來源 ID；每項功能須有主要責任歸屬、支援平面、採納決策及驗收狀態。
6. **文件存在不是運行證據。** INVENTORIED、DESIGN_SPECIFIED、MAPPED、IMPLEMENTED、WIRED、TESTED、RUNTIME_OBSERVED 必須分開。
7. **失敗有合法出口。** UNKNOWN、CONFLICT、BLOCKED、NOT_PROVEN、REJECTED、PARTIAL、STOPPED 等狀態不可被「流程已走完」覆蓋。

## 2. L1｜核心 Core：8 組思考不變量

| ID | 不變量 | 主要避免的失效 | 最低驗收證據 |
|---|---|---|---|
| I1 目標忠實 | 先確認結果目標、成功條件、限制及非目標，再選方法 | 把文件、工具或流程完成誤當目標達成 | 原始目標與接受條件可對照 |
| I2 知識誠實 | 區分來源、觀察、主張、推論、假說、未知與衝突 | 幻覺、錯引、把猜測寫成事實 | Claim–Evidence、UNKNOWN／CONFLICT 記錄 |
| I3 模型可修正 | 問題框架是暫定模型；替代框架及框架外訊號可以保留 | 錯框架被後續細化放大 | 候選框架、反例與重框觸發紀錄 |
| I4 方法適配 | 根據問題類型、可觀測性、風險與成本選方法 | 所有任務硬套單一流程 | 路由理由、替代方法與停止規則 |
| I5 行動有界 | 外部行動符合權限、範圍、成本、安全與可逆性限制 | 認知判斷越權轉成副作用 | 授權決策、資源 Gate、行動收據 |
| I6 可區辨驗證 | 重要假說須有可區分預測；執行成功不等於結果正確 | 自我重述被誤當獨立證明 | 預先接受條件、反例／測試結果 |
| I7 受控更新 | 新證據可局部修正或依條件重框；下游結論須重驗 | 只改圖不改結論，或拒絕新證據 | 變更差異、影響集合、重驗證據 |
| I8 誠實收口 | 保留未知、可合理拒絕或停止；評估自身架構，不預設最優 | 無限研究、虛構閉環、草案冒充定律 | 合法終態、未解項、成本與否決條件 |

**舊版 C-01–C-12 的處理：**保留所有原始語意，重新歸併至 I1–I8。C-02／C-08 合入模型可修正與受控更新；C-05／C-06／C-07 合入可區辨驗證；C-10／C-12 合入誠實收口與架構可否決性。歸併只是候選分類，正式接受前須逐項核對原文及反例。

## 3. L2｜六個認知主軸 AX1–AX6

| ID | 主軸 | 唯一主要責任 | 輸出 | 明確不負責 |
|---|---|---|---|---|
| AX1 | 意圖與問題契約 | 將要求轉成目標、限制、成功條件、非目標及候選框架 | Task Contract、Frame Candidates、Open Questions | 不預先決定工具；不代表取得外部行動授權 |
| AX2 | 證據與知識狀態 | 判定每項主張的來源、支持範圍、時效及知識狀態 | Source Ledger、Claim–Evidence Links、Knowledge State | 不自行把衝突合併成單一結論 |
| AX3 | 問題模型與解釋 | 表示對象、變數、關係、條件、因果候選、競爭假說及未知 | Problem Model、Hypothesis Set、Discriminating Tests | 不把分類樹當完整世界模型；不直接授權操作 |
| AX4 | 方法與決策規劃 | 選擇方法組合、下一個高價值步驟、成本預算與停止條件 | Route Decision、Method Plan、Budget、Stop Rule | 選中方法不等同已執行或有權執行 |
| AX5 | 求解與產出 | 依核准路徑分析、計算、設計、施工或綜合，記錄實際產出 | Result、Execution Record、Deliverable | 不自行裁定結果已驗收 |
| AX6 | 驗證、修正與結案 | 對照成功條件，區分錯誤類型，決定局部修補、重選方法、重框或終止 | Verification Result、Correction／Reframe Decision、Terminal State | 不以主觀信心替代證據；不強迫無限迭代 |

六軸沿用舊版名稱與概念方向，以輸入／輸出契約及「不負責事項」降低交界模糊。

## 5. L4｜狀態路由器 State Router

L4 不再將 F0–F7 當成所有任務都要依序經過的固定清單，而是依狀態、證據與守衛條件，選出本次需要的能力節點。

| 狀態 | 進入條件 | 允許離開的方向 |
|---|---|---|
| S0 INTAKE | 接收新任務或新證據事件 | S1；輸入不足則要求必要資訊或 BLOCK |
| S1 CONTRACT_READY | 目標、成功條件、限制及範圍足以選路 | S2、S3；低風險簡單任務可進 S5 |
| S2 MODEL_READY | 證據／問題模型足以決定下一步，關鍵未知已標記 | S3；必要證據不足則回檢索或進 T_NOT_PROVEN／T_BLOCKED |
| S3 PLAN_READY | 方法、預算、停止條件與必要授權檢查完成 | S4；不允許的操作進 T_REJECTED／T_BLOCKED |
| S4 WORKING | 按計畫執行認知操作或授權行動 | S5；依失敗類型回 S2／S3 或進終態 |
| S5 VERIFYING | 有可核對的輸出或觀察結果 | T_DONE、T_PARTIAL、T_NOT_PROVEN、T_REJECTED、T_BLOCKED、T_STOPPED、T_FAILED；必要時返回 S2／S3／S4 |

### 狀態轉移守衛

- **S0→S1：** 識別目標與輸出；關鍵歧義若會改變結果、風險或授權，不能默默假設。
- **S1→S2：** 需要查證、診斷、因果推理或處理不確定性時才進入；已足夠的簡單任務可按明確低風險規則短路。
- **S1／S2→S3：** 必須說明下一步有何價值，以及停止和成本界線。
- **S3→S4：** 外部動作需要獨立權限與範圍確認；方法選擇不是授權。
- **S4→S5：** 保存實際觀察，不得只保存預計完成的狀態。
- **S5→回流：** 按失敗類型選回入口：證據不足回 AX2，方法不適配回 AX4，模型前提失效回 AX1／AX3；不能一律重新走全流程。
- **任一狀態→終態：** 保留原因、證據與未完成部分。安全／權限／成本硬性 Gate 不可由效率偏好覆蓋。

### 終態

T_DONE＝接受條件已被證據支持；T_PARTIAL＝明確完成與未完成範圍；T_NOT_PROVEN＝證據不足；T_BLOCKED＝必要輸入、依賴或權限不滿足；T_REJECTED＝方案／操作因限制不採用；T_STOPPED＝符合停止規則；T_FAILED＝已觀察到執行或驗收失敗。終態不得互相冒充。

| ID | 支援平面 | 服務與限制 |
|---|---|---|
| SP1 | 治理、權限與信任 | 角色／使用者授權、來源信任、範圍、不可逆操作及控制面隔離；可阻擋行動，但不決定認知結論 |

| SP6 | 持久化、生命週期與文件治理 | SOP、問題登錄、版本、封存、唯一責任文件、索引、交接及退場 |

支援平面不升格成新的認知主軸。它們可服務、限制或記錄認知責任；關係需標為 SERVES、GUARDS、RECORDS、PROVES 或 DEPENDS_ON，不可只畫無語意箭頭。

## 7. 舊功能、SOP 與問題清單的保留規則

- **P1 48 項、P2 30 項：** 保留原始 ID，逐項映射至 AX／KG 與 SP。歸位是候選，不等於實作。
- **SOP／固定流程：** 以現行 SOP 權威清單管理；只把流程責任掛到狀態轉移及支援平面，候選內容不可升格。
- **PR-001–PR-054：** 保留原 ID、根因與來源狀態；建立候選控制位置，將文件有對策與驗收有效分開。
- **新增便利功能／方法：** 先查重複責任，記錄建立原因、功能、邏輯、觸發、輸入／輸出、依賴、成本、權限、來源和驗收。
- **人類／機器雙視圖：** JSON 保存穩定 ID、關係型別、狀態及來源；Markdown 供人閱讀。自動生成與差異檢查未實作，未完成前須在同一變更集人工對帳。

## 8. 最小驗收條件

1. 六軸沒有責任空洞；26 個初始節點均有契約，且可按證據拆併。
2. 每條關鍵轉移都有 guard、成功／失敗出口、原因碼與可核對證據。
3. P1/P2 78 項每項都有唯一主要歸位或待裁定狀態；不能用名稱相似取代語意映射。
4. PR 問題與 SOP／控制／測試保留雙向連結；未解問題不能因架構重排而遺失。
5. 簡單低風險任務不被強迫走重型路徑；高風險、外部寫入及不可逆操作不跳過硬性 Gate。
6. JSON、Markdown、圖表和原始權威文件沒有未標示的狀態矛盾。
7. 桌上模擬通過後才做同任務新舊對照；Runtime 仍須用實際執行證據裁定。

此版是供反證與比較的候選模型。任何架構優勢均須以案例及成本／品質證據驗證，不能從圖表完整度推導。
