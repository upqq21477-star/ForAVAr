# 去重與初步蒸餾規範

## 1. 目的

讓多批次、多格式、多來源的文件累積成可追溯、低重複的知識庫。去重是保留來源並消除重複摘要，不是任意刪除原始檔案。

## 2. 四類資料要分開

1. 原始證據：ZIP、來源程式、原始交接與輸入文件。保留原貌，不直接刪改。
2. 解析副本：為搜尋、比較而從來源抽取的文字、清單或 XML。必須記錄來源檔名及格式。
3. 分析文件：逆向判讀、風險、映射、驗證結果與未知項。
4. 蒸餾知識：不重複的核心原則、架構事實、交互關係、限制和決策；每項必須回指來源。

## 3. 每個項目的最低登錄欄位

- DOC_ID：穩定文件 ID。
- canonical_path：目前唯一存放位置。
- original_path／original_name：原始位置與檔名。
- source_version／commit 或來源版本。
- git_blob_sha：Git 物件識別。
- file_size、format。
- analysis_status：未讀、已盤點、已抽取、已分析、已驗、阻塞。
- duplicate_group：可能重複的群組 ID。
- canonical_role：原始證據、詳細研究、蒸餾摘要、映射草案等。
- claims、evidence_level、source_locations。
- open_questions：未解項，不以猜測補齊。

## 4. 去重判定流程

1. 同一位元組：比對 SHA-256 或 Git Blob SHA。相同內容只保留一份 canonical 實體；其他路徑可保留相容連結或索引，不再複製全文。
2. 同一內容、不同格式：抽取文字，正規化換行、空白、表格與頁首頁尾，再逐段比較。若完全等價，標為同內容多格式；保留原始輸入，解析與蒸餾只指定一個 canonical 文字來源。
3. 部分重疊：建立重複群組，標出共用主張和獨有資訊。只從摘要中刪除重複敘述，獨有證據與限制仍需保留。
4. 概念相似、責任不同：不當成重複。例如「架構提案」和「功能歸位映射」可能用詞相似，但回答不同問題，不可直接合併。
5. 不同版本：保留版本鏈，指出變更與棄用狀態，不把最新版當成唯一真相，除非來源授權規則如此定義。

## 5. 蒸餾規則

每個主題先保留：
- 一句核心結論。
- 必要的機制／因果關係。
- 適用條件與不適用條件。
- 前置條件、失效條件、回退／替代路徑。
- 可執行驗收或反例。
- 證據來源與證據強度。
- 未知項及下一步。

刪除重複背景、空泛形容詞、沒有可驗收含義的宣稱、重複結論、與任務無關的過程敘述。不得刪除限制、例外、反例、版本資訊或負面證據。

## 6. 證據等級

- DIRECTLY_INSPECTED：直接讀取原始檔或已解析的封包成員。
- PROGRAM_EXECUTED_PASS：實際執行命令並保存可重查的成功結果。
- SIMULATED_PASS：模擬測試；不可升格為實際執行。
- HANDOFF_CLAIM：旁側交接文件聲稱，尚未由主來源核實。
- INFERRED：由明列事實推論；必須標示推論依據。
- NOT_VERIFIED：未取得足夠證據。
- BLOCKED：已識別阻塞及嘗試過的方法；須保留替代路徑。

## 7. 分批處理的防漏流程

每批先登記預期成員數，再解析內容；結束時核對「預期項目＝成功解析項目＋明確阻塞項目＋格式不支援項目」。任何不相等都代表批次未收口。對 ZIP 至少記錄中央目錄成員、大小、壓縮方法、CRC32，以及實際解壓結果；對 DOCX 至少記錄文檔 XML 抽取範圍與對應文字版的差異。未核對欄位明標未知。

## 8. 研究文件互相引用

先查 參考資料/README.md 與重複群組表。如果內容已存在：
- 補證據到既有分析；
- 新來源只追加差異；
- 不再複製整份既有摘要；
- 若存在不同結論，保留各自依據並列出衝突，等待核實；
- 所有結論必須能沿「蒸餾項 → 分析文件 → 原始來源」逆向追溯。


## 9. 通用根因屬性蒸餾與納入門檻

本節定義跨題目重用的蒸餾方法，不保存任何單一研究題目的事實或推論，也不建立新的問題 ID、能力登錄或並行台帳。

### 9.1 分開資料類型，避免從症狀直接跳到結論

- **來源／事件**：實際收到的要求、可觀察偏差、來源位置與覆蓋限制。
- **問題／症狀**：交付差異或失敗表現；相同問題的多次發生沿用既有問題 ID。
- **根因假說**：解釋失效機制的可反駁主張，須列支持證據、反證、替代解釋與信心界線。
- **控制／修正**：可執行的預防、偵測、回復或責任接線措施。
- **驗收／成效**：分別保存規格、寫入、讀回、測試、Runtime 與實際效益；不得相互替代。

### 9.2 可重用的根源屬性

下列是供檢索與根因分析使用的描述標籤，不是新問題編號；只在證據符合時使用，可同時標記多種屬性。

| 根源屬性 | 可觀察失效模式 | 優先控制方向 | 既有責任參照 |
|---|---|---|---|
| 目標漂移 | 工作量增加，但交付未回答原始目標或成功條件 | 每輪對照原始目標、必交產物與驗收條件 | PR-001；CF-001／004 |
| 症狀修補、根因未證實 | 局部修正後同一問題復發，或因果只靠推測 | 比對既有問題、列替代根因；以原故障與回歸案例驗證 | PR-006／011；CF-005／009 |
| 既有能力未調用／責任未接線 | 規則或模組已存在，但任務仍重新規劃或無法觸發 | 先查現有 PR、CF、SOP、能力登錄與唯一權威；分清缺失、未觸發、未接線、未執行、無權限 | PR-021／053；CF-001／009 |
| 方法與問題屬性不匹配 | 將同一程序套用所有任務，或在資料不足時只反覆採用同一來源／方法 | 根據目標、來源結構、未知、風險、可逆性、交付類型選擇最小有效方法 | PR-012／013／027；CF-001 |
| 完整性審查封閉 | 只用既有分類檢查既有分類，沒有以目標及外部基準尋找分類外缺口 | 從最終用途倒推需求，建立需求—責任—操作—驗收映射；高風險時做反方與負向空間檢查 | PR-034／047；CF-004／009 |
| 來源覆蓋／引用不足 | 以摘要冒充逐字來源、重刊冒充獨立來源，或無法回查主張根據 | 記錄實際可讀來源、版本、主張範圍、來源譜系及未取得項；主張須能逆向追溯 | PR-043／054；CF-008 |
| 跨文件更新不同步 | 正文已變更但索引、回鏈、狀態或下游依賴未同步 | 先列變更集，再按唯一責任寫回；集中讀回檢查雙向引用與受影響文件 | PR-028／043／054；CF-004／008 |
| 文件成果冒充實際能力／效益 | 因規格、文件或一次成功就宣稱功能可運作或效率改善 | 分開設計、實作、讀回、測試、Runtime 與成效；無實測則標未驗證 | PR-039／042；CF-009 |
| 校正未轉成防再犯控制 | 已指出偏差，但沒有觸發條件、回歸案例或後續可觀察指標 | 對帳既有問題；把重複／高影響校正映射到最小控制和回歸測試 | PR-053／054；CF-009／010 |
| 低增益驗證循環 | 沒有新證據、判斷或行動變化，仍重複搜尋、覆核或重寫 | 預先設定資訊增益門檻、升級條件與停止規則；保留未知或阻塞，不用重複分析掩蓋 | PR-008／012／031／039；CF-001／009 |
| 專題材料污染全域知識 | 把局部事實、假說或專用流程原樣複製成通用規則 | 先隔離來源；結案後只抽取失效機制、觸發條件、控制、例外、反例與證據成熟度 | PR-034／035／047；CF-003／004／007／010 |

### 9.3 從觀察到採納的最小路徑

1. 確認原始目標、範圍、授權、必交產物與成功／停止條件。
2. 將具體來源、事件、問題、根因假說、修正及測試結果分欄，不把推論寫成事實。
3. 對帳既有能力與權威文件；處置優先順序為重用、修正、接線、融合重複責任、擴充既有節點，最後才是有證據支持的新增候選。
4. 檢查外部要求、反例、來源覆蓋、下游依賴及負向空間；只有風險或資訊增益足夠時才升級完整性審查。
5. 在修改前定義可觀察的回歸條件，寫入後從實際儲存位置讀回，核對正文、索引、引用和狀態。
6. 把單次觀察標為候選；在獨立情境中重現後再提升通用性信心；通過代表性測試仍不等於已證明跨任務效益。
7. 依唯一責任更新既有 PR／CF／SOP／台帳／索引，不複製全文，不產生同義 ID 或第二套清單。

### 9.4 風險分層與停止條件

- **輕量檢查**：短任務、低風險、可逆且沒有跨文件影響；只核對目標、交付與必要引用。
- **完整整合**：明確要求整合、發生重複偏差、資訊需寫入多個權威位置，或出現明確未交付項。
- **完整性閘門**：重大目標／架構變更、重複高影響失敗、關鍵前提被推翻、宣稱完整、測試失敗或既有分類無法承載重要需求時才啟動。

如新增檢查未可能改變判斷、風險處置或下一步，且沒有新證據來源，應停止循環並明列未知、阻塞或待驗證事項。任何未執行的控制維持未驗證；不得從「文件寫好」推導「控制已運作」，也不得從單次案例推導「規則普遍有效」。


## 10. 版本、彙整與分支治理

依[版本治理與分流規範](./版本治理與分流規範.md)執行；本文件不重複保存全套版本流程。

- 同一邏輯文件只保留 1 個 CURRENT 與最多 2 個完整 BACKUP；不同分析角度使用不同 BRANCH_ID，各分支分別計算版本上限。
- 同一上下文的多場對話彙整進唯一 MASTER；各場原始對話是獨立 SOURCE，可保留作不可變備份，但一般索引只顯示 MASTER。
- MASTER 目標 ≤6,000 字元；MASTER／BRANCH／INDEX／LEDGER／AI 可讀規範硬上限 8,000 字元。超限需按語義分流，並保留所有證據、限制、反例和未知。
- 新增、改名、移動、分流、取代或刪除前，先更新 MASTER 的摘要／分支索引及雙向引用草案；完成寫入後回讀驗收，再記錄事件並輪替備份。
- 每條引用必須可由來源查到目標，也可由目標反查來源；全域引用索引為[文件與分支索引](./文件與分支索引.md)。未掃描部分標記 PARTIAL，不宣稱全庫完成。
- 舊版本只作備份、恢復和差異核對，不是現行知識入口。日常分析只引用 MASTER 或 CURRENT BRANCH。
- 不得把原始來源、分析分支、主軸彙整和備份當成同一類版本。原始證據不得因蒸餾而丟失，正式企劃的正文分流仍受明確更新授權限制。
