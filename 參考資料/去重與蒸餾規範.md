# 去重與初步蒸餾規範

## 1. 目的

讓多批次、多格式、多來源的文件累積成可追溯、低重複的知識庫。去重是保留來源並消除重複摘要，不是任意刪除原始檔案。

## 2. 四類資料要分開

1. 原始證據：ZIP、來源程式、原始交接與輸入文件。保留原貌，不直接刪改。
2. 解析副本：為搜尋、比較而從來源抽取的文字、清單或 XML。必須記錄來源檔名及格式。
3. 分析文件：逆向判讀、風險、映射、驗證結果與未知項。
4. 蒸餾知識：不重複的核心原則、架構事實、交互關係、限制和決策；每項必須回指來源。

## 3. 每個項目的最低登錄欄位

- DOC_ID：穩定文件 ID。
- canonical_path：目前唯一存放位置。
- original_path／original_name：原始位置與檔名。
- source_version／commit 或來源版本。
- git_blob_sha：Git 物件識別。
- file_size、format。
- analysis_status：未讀、已盤點、已抽取、已分析、已驗、阻塞。
- duplicate_group：可能重複的群組 ID。
- canonical_role：原始證據、詳細研究、蒸餾摘要、映射草案等。
- claims、evidence_level、source_locations。
- open_questions：未解項，不以猜測補齊。

## 4. 去重判定流程

1. 同一位元組：比對 SHA-256 或 Git Blob SHA。相同內容只保留一份 canonical 實體；其他路徑可保留相容連結或索引，不再複製全文。
2. 同一內容、不同格式：抽取文字，正規化換行、空白、表格與頁首頁尾，再逐段比較。若完全等價，標為同內容多格式；保留原始輸入，解析與蒸餾只指定一個 canonical 文字來源。
3. 部分重疊：建立重複群組，標出共用主張和獨有資訊。只從摘要中刪除重複敘述，獨有證據與限制仍需保留。
4. 概念相似、責任不同：不當成重複。例如「架構提案」和「功能歸位映射」可能用詞相似，但回答不同問題，不可直接合併。
5. 不同版本：保留版本鏈，指出變更與棄用狀態，不把最新版當成唯一真相，除非來源授權規則如此定義。

## 5. 蒸餾規則

每個主題先保留：
- 一句核心結論。
- 必要的機制／因果關係。
- 適用條件與不適用條件。
- 前置條件、失效條件、回退／替代路徑。
- 可執行驗收或反例。
- 證據來源與證據強度。
- 未知項及下一步。

刪除重複背景、空泛形容詞、沒有可驗收含義的宣稱、重複結論、與任務無關的過程敘述。不得刪除限制、例外、反例、版本資訊或負面證據。

## 6. 證據等級

- DIRECTLY_INSPECTED：直接讀取原始檔或已解析的封包成員。
- PROGRAM_EXECUTED_PASS：實際執行命令並保存可重查的成功結果。
- SIMULATED_PASS：模擬測試；不可升格為實際執行。
- HANDOFF_CLAIM：旁側交接文件聲稱，尚未由主來源核實。
- INFERRED：由明列事實推論；必須標示推論依據。
- NOT_VERIFIED：未取得足夠證據。
- BLOCKED：已識別阻塞及嘗試過的方法；須保留替代路徑。

## 7. 分批處理的防漏流程

每批先登記預期成員數，再解析內容；結束時核對「預期項目＝成功解析項目＋明確阻塞項目＋格式不支援項目」。任何不相等都代表批次未收口。對 ZIP 至少記錄中央目錄成員、大小、壓縮方法、CRC32，以及實際解壓結果；對 DOCX 至少記錄文檔 XML 抽取範圍與對應文字版的差異。未核對欄位明標未知。

## 8. 研究文件互相引用

先查 參考資料/README.md 與重複群組表。如果內容已存在：
- 補證據到既有分析；
- 新來源只追加差異；
- 不再複製整份既有摘要；
- 若存在不同結論，保留各自依據並列出衝突，等待核實；
- 所有結論必須能沿「蒸餾項 → 分析文件 → 原始來源」逆向追溯。


## 9. 版本、彙整與分支治理

依[版本治理與分流規範](./版本治理與分流規範.md)執行；本文件不重複保存全套版本流程。

- 同一邏輯文件只保留 1 個 CURRENT 與最多 2 個完整 BACKUP；不同分析角度使用不同 BRANCH_ID，各分支分別計算版本上限。
- 同一上下文的多場對話彙整進唯一 MASTER；各場原始對話是獨立 SOURCE，可保留作不可變備份，但一般索引只顯示 MASTER。
- MASTER 目標 ≤6,000 字元；MASTER／BRANCH／INDEX／LEDGER／AI 可讀規範硬上限 8,000 字元。超限需按語義分流，並保留所有證據、限制、反例和未知。
- 新增、改名、移動、分流、取代或刪除前，先更新 MASTER 的摘要／分支索引及雙向引用草案；完成寫入後回讀驗收，再記錄事件並輪替備份。
- 每條引用必須可由來源查到目標，也可由目標反查來源；全域引用索引為[文件與分支索引](./文件與分支索引.md)。未掃描部分標記 PARTIAL，不宣稱全庫完成。
- 舊版本只作備份、恢復和差異核對，不是現行知識入口。日常分析只引用 MASTER 或 CURRENT BRANCH。
- 不得把原始來源、分析分支、主軸彙整和備份當成同一類版本。原始證據不得因蒸餾而丟失，正式企劃的正文分流仍受明確更新授權限制。
