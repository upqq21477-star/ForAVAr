## 1. 用途、適用範圍與邊界

本文件回答兩個問題：

1. 一份完整的 SOP 應有哪些固定欄位，每個欄位應記錄什麼。
2. 如何從對談、重複操作、錯誤案例和已知結果中，抽出可重複使用的根源流程。

本文件是 SOP 的「建檔與蒸餾規格」；[SOP 固定流程與演化管理](./SOP固定流程與演化管理.md)仍是 SOP 狀態、試行、驗證、定版、改良及退役的權威。流程目錄只負責導航，執行台帳只記錄每次執行，對談紀錄只保留來源脈絡；四者不可互相取代。

適用於：同類任務反覆出現、對話中已形成可重用做法、需要將個人操作轉成交接規則、多來源流程需整合，或既有 SOP 需要系統性重寫時。

不適用於：沒有可重複操作的純一次性答案、僅有未證實猜想且無法定義驗收方式的構想。這些內容可以保留為研究假說或案例紀錄，不得偽裝成標準流程。

## 2. SOP 文件必要欄位清單

### 2.1 必備欄位

每份 SOP 都必須具備下表欄位。若某欄不適用，需寫「不適用」並說明判定理由；不得無聲省略，造成讀者無法判斷是刻意排除還是遺漏。

| 欄位 | 必要性 | 應記錄的內容 | 驗收方式 |
|---|---|---|---|
| 名稱 | 必備 | 用動詞或任務對象命名，能與其他流程區分 | 名稱不含多重模糊任務，且能辨識主要產出 |
| SOP ID／文件 ID | 必備 | 穩定唯一識別碼；文件移動或改名時識別碼不隨路徑改變 | 全專案不重複，索引和正文一致 |
| 版本與狀態 | 必備 | 版本號、生命週期狀態、是否暫行、已驗證範圍 | 狀態符合生命週期規範，不把草案標成 CURRENT |
| 簡述 | 必備 | 以一至三句說明解決何種問題、產生什麼成果 | 不複製整段背景，讀者可快速判斷是否適用 |
| 目的 | 必備 | 這個 SOP 要降低的錯誤、保證的結果或控制的風險 | 目的可對應到輸出與驗收條件 |
| 功能 | 必備 | SOP 提供的具體能力或控制作用 | 每項功能可在步驟、輸出或驗收中找到對應 |
| 適用範圍 | 必備 | 適用對象、環境、任務類型、規模與明確邊界 | 範圍內外情況均可判斷 |
| 觸發條件 | 必備 | 何時必須啟用此 SOP，以及足以判定啟用的條件 | 用可觀察條件表達，不寫「視情況」 |
| 不適用／不觸發條件 | 必備 | 什麼情形不得啟用，或應交給哪個其他流程 | 能避免錯誤路由和不必要的重型流程 |
| 必要輸入與前置條件 | 必備 | 所需來源、權限、工具、版本、資料格式、先決狀態 | 開始前可逐項核對；缺項有明確處置 |
| 角色與權限 | 必備 | 誰執行、誰核准、誰提供來源；可讀／可寫範圍與禁止操作 | 不把執行權、核准權或資料權限混為一談 |
| 預期輸出 | 必備 | 交付物、格式、保存位置、狀態欄位及完成條件 | 可透過讀回、測試或明確證據判斷是否產出 |
| 標準流程 | 必備 | 有序步驟；每步說明輸入、動作、判斷、產物或下一步 | 他人可按步驟執行，不需猜測缺失動作 |
| 邏輯與判斷規則 | 必備 | 條件、先後依賴、決策表、優先級、衝突處理原則 | 同一條件能導向明確決策；例外不靠含糊措辭 |
| 分支與例外 | 必備 | 條件成立／不成立、來源缺失、衝突、失敗、重試及替代路徑 | 每個重要分支有進入條件、處置及返回／結束方式 |
| 注意事項與禁止事項 | 必備 | 不可違反的規則、常見混淆、風險及不應採取的做法 | 每條規則說明限制對象；不能只用「小心處理」 |
| 停止／回復條件 | 必備 | 何時中止、升級、尋求授權、回滾或保留阻塞狀態 | 危險或無法驗證的情況不會被流程推進掩蓋 |
| 驗收標準 | 必備 | 可觀察、可重做的通過／不通過條件及所需證據 | 不以「看起來合理」「已處理」作為唯一標準 |
| 參考資料與相依文件 | 必備 | 原始來源、權威文件、技術依賴、版本、相關案例與限制 | 連結可定位；可區分來源、分析、假說和執行證據 |
| 紀錄與交接 | 必備 | 執行結果寫到哪裡，什麼情形需建立詳細案例，如何讓下一位接手 | 不把執行台帳、追溯表和完整對談混作同一份文件 |
| 已知限制與驗證狀態 | 必備 | 已驗證／未驗證範圍、樣本限制、未知、衝突和未解問題 | 不誇大成功案例或將未檢查項目寫成通過 |
| 維護與版本歷史 | 必備 | 負責文件、修改原則、變更摘要、前版替代關係 | 重大流程變更可追溯，不靜默覆蓋歷史證據 |

### 2.2 條件式欄位

以下欄位依風險、任務與工具環境加入；若不適用，需在 SOP 內留下不適用判定。

| 欄位 | 何時需要 | 必須記錄的內容 |
|---|---|---|
| 時間／資源預算 | 任務有時限、工具額度或成本上限 | 預算、停止點、優先順序及超出時的降級方案 |
| 安全與隱私控制 | 涉及個資、機密、外部帳號或敏感操作 | 最小必要資料、授權、保留期限、遮蔽與禁止外傳規則 |
| 外部副作用／回滾 | 會提交程式、發送訊息、付款、刪除或影響外部系統 | 影響範圍、使用者核准點、回復方法和不可回復風險 |
| 自動化／工具契約 | 有 API、腳本、Agent 或整合工具 | 工具名稱、輸入輸出格式、錯誤碼、權限及重試規則 |
| 量測指標 | 需要比較速度、成本、正確率或返工量 | 基線、量測方法、樣本、指標定義；未測時標 UNKNOWN |
| 回歸測試案例 | SOP 變更會影響既有工作結果 | 測試輸入、預期輸出、失敗條件及版本對照 |
| 角色矩陣 | 多角色／部門需交接或核准 | 負責、執行、諮詢、知會及最終核准職權 |
| 國別／版本／環境限定 | 規則依地區、軟體版本或執行環境變動 | 適用版本、有效日期、環境條件與重驗觸發點 |

## 4. 對話與操作紀錄的蒸餾流程

一般流程：

**授權與界定 → 來源盤點 → 操作抽取 → 類型分類 → 根源建模 → SOP 編寫 → 反向批判 → 案例試行 → 分流保存 → 索引與驗收**

| 步驟 | 執行動作 | 產出 | 通過條件 |
|---|---|---|---|
| 1. 授權與界定 | 確認可讀／可寫位置、使用者目的、輸出、保密要求和禁止事項 | 任務範圍與授權條件 | 寫入範圍明確；權限不足時停止寫入 |
| 2. 來源盤點 | 找出原始對談、已有 SOP、相關檔案、既有執行紀錄及最新版本 | 來源清單與引用 | 不以摘要代替可取得的權威原件；未知來源明確標記 |
| 3. 操作抽取 | 按時間或因果順序提取目標、判斷、動作、輸出、錯誤及回復過程 | 操作事件清單 | 重要動作、失敗證據與結果均有來源定位 |
| 4. 類型分類 | 區分使用者要求、可觀察事實、決策、通用規則、假說、失敗案例與未知 | 分類表／主張—證據映射 | 推論不升格為事實；個案經驗不直接等同通用規則 |
| 5. 根源建模 | 合併語義重複項，找出共同控制問題、觸發條件、最小必要步驟和決策門檻 | 候選流程／根源模型 | 模型能解釋至少一個成功案例；例外或反例仍可定位 |
| 6. SOP 編寫 | 用第 2 節欄位及第 3 節模板撰寫；每步明確輸入、動作、判斷、產物和驗收 | SOP 候選版 | 必備欄位完整；不存在只寫「依情況處理」的關鍵步驟 |
| 7. 反向批判 | 測試缺資料、來源衝突、權限不足、重複內容、步驟失敗、回復不可用等情況 | 反例及修訂清單 | 重要風險有停止／分支規則；不能處理的限制明確暴露 |
| 8. 案例試行 | 用一個獨立任務依 SOP 執行，不靠記憶補上 SOP 未寫的隱含步驟 | RUN_ID、輸出與驗收證據 | 按書面流程能完成或能正確阻塞；偏差被記錄 |
| 9. 分流保存 | SOP 只放標準規則；對談紀錄保留需求與形成脈絡；台帳保存執行結果；追溯表保存檔案變更 | SOP、SOURCE／對談紀錄、RUN 紀錄及事件 | 每類內容有唯一責任位置，相互連結而不大段複製 |
| 10. 索引與驗收 | 更新流程目錄、全域索引、權責矩陣及追溯事件；讀回檔案並核對連結和長度 | 可定位的交付及驗收結果 | 新文件可被找到；連結目標存在；所有未執行檢查清楚標出 |

## 5. 決策邏輯與分支規則

1. **是否可重用？**
   - 同一控制問題在不同任務中反覆出現，或步驟可以明確重做：建立 SOP 候選。
   - 只出現一次且沒有可泛化機制：保留案例紀錄，不急於新增 SOP。
   - 只有構想，尚無可判斷步驟和驗收：標 HYPOTHESIS／DRAFT。

2. **是否有足夠證據？**
   - 可觀察步驟及輸出可重現：可進入 TRIAL。
   - 根因未證實或來源互相衝突：保留 UNKNOWN／CONFLICT，不將推測寫成強制規則。
   - 失敗案例只支持「此條路徑在某情境失敗」時，不可推出它在所有情境都失敗。

3. **失敗路徑如何處理？**
   - 保存發生條件、失敗位置、影響、根因證據與回復結果。
   - 已證實可預防的根因，轉成一條前置檢查、判斷分支、停止條件或回復規則。
   - 根因未知、無法重現或是外部偶發事件，留在台帳／案例文件，不把失敗步驟加到標準路徑。

4. **何時升級為 CURRENT？**
   - 依 [SOP 固定流程與演化管理](./SOP固定流程與演化管理.md)的生命週期與回歸驗收規則辦理。
   - 單一案例成功只證明該案例在已列範圍內完成，不證明普遍有效。
   - 高影響流程須有明確授權、失敗／回復案例與必要的獨立檢查。

5. **是否另存對談紀錄？**
   - 本輪對話形成新 SOP、重大決策、根源模型或權限／範圍裁定時，建立獨立對談紀錄。
   - 一般重複任務沒有新決策時，只更新執行台帳，不為每個成功案例建立長篇對談文件。
   - 可取得完整原文時，按專案來源規範保留或引用；只有摘要時，明確標為摘要，不宣稱逐字完整。

## 6. 注意事項與禁止事項

- 不把名稱相似視為同一流程；先比較唯一責任、觸發條件、輸入輸出與驗收。
- 不將「對話中提過」視為已驗證；分清使用者要求、已執行行為、觀察結果與假說。
- 不把工具回報成功等同內容正確、連結完整或功能已執行。
- 不把失敗路徑逐次疊加成 SOP 主流程；先找根因，只有可證實且能降低風險的規則才寫回候選。
- 不因追求短小而刪除反例、限制、未知、必要來源或停止條件。
- 不為了欄位完整而填寫沒有證據的資訊；標為 UNKNOWN 或 NOT_VERIFIED。
- 不把完整對談、逐次日誌、變更歷史及標準程序混寫在一份文件。
- 不以一次成功、主觀印象或未比較的數據宣稱 SOP 是最優或已提升效率。
- 不改寫唯讀參考專案；不跨越使用者授權範圍；正式企劃仍須遵守專案的明確授權規則。
- SOP 文件只是文件化標準，不自動代表 AI Runtime 會載入、強制或自動執行。

## 7. 驗收清單與狀態轉換

每次建立／修改 SOP，至少逐項核對：

- [ ] 名稱、ID、版本、狀態與唯一責任齊備。
- [ ] 簡述、目的、功能、適用範圍與觸發／不觸發條件明確。
- [ ] 輸入、前置條件、角色／權限、輸出與存放位置可核對。
- [ ] 步驟具備順序、動作、判斷點、產物與下一步。
- [ ] 分支包含觸發條件、處置、返回／停止方式。
- [ ] 失敗、未知、衝突與不可回復情況有明確標記。
- [ ] 注意事項不是泛泛提醒，而是可遵循或驗收的限制。
- [ ] 驗收條件可以重做，不以「完成」作唯一依據。
- [ ] 參考資料、引用路徑與版本正確；新文件已有導航入口。
- [ ] 對談紀錄、執行台帳、SOP 正文和追溯事件各司其職。
- [ ] 已執行的檢查與尚未執行的檢查分別標記。
- [ ] 將本次執行結果追加到 [SOP 執行與演化台帳](./SOP執行與演化台帳.md)。

流程狀態依生命週期規範轉換。此文件目前為 TRIAL；完成本次靜態文件驗收不等於通過多任務通用性驗證。

## 8. 參考資料與相關文件規則

參考資料分層管理，至少區分：

1. **原始來源**：使用者對談、提供檔案、原始資料或具體工具輸出。
2. **權威規範**：定義現行規則的 SOP 或治理文件。
3. **分析／蒸餾文件**：從來源歸納出的判斷、分類與候選模型。
4. **案例／執行證據**：某次實際執行的輸入、結果、失敗、測試及驗收收據。
5. **索引／追溯**：負責定位文件、引用和變更，不取代原始內容。

每筆參考至少保留可定位的名稱或 ID、相對路徑／URL、版本或日期（若可得）、與 SOP 的關係，以及可支持的結論邊界。引用只證明該來源實際包含的內容；不得由摘要連結推論未讀取的原件已完整。
