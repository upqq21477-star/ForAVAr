## 1. 核心裁定與本次變更邊界

**思考仍是唯一核心；架構、能力、角色、流程、工具、記憶、檔案、治理與評測都是支援思考和確保結果可靠的手段。** 本次沒有證據支持推翻原核心，也不把治理或 Agent runtime 升格為新的認知層。

本版只做以下規劃調整：
1. 將新研究的五條主軸／九個節點納入既有架構的「責任映射視圖」，不另建競爭性骨架。
2. 將「低風險快速、一般標準、高風險高保證」寫成候選運行模式與升級觸發。
3. 將依據紀錄、獨立檢驗、依賴更新、風險調度區分為最低核心行為或條件性加強，不讓所有流程每題完整運行。
4. 把 runtime／工具授權、任務狀態、依據帳本、長期記憶、trace 與 eval 的責任分清，避免一個思考框架同時承擔所有系統責任。
5. 將桌上模擬、外部架構指南與實測結果嚴格分層。本次模擬分數不是模型執行分數，也不是品質提升百分比。

非目標：不改變核心不變量的原義；不刪除現有六主軸／十八節點；不新增與既有能力登錄重疊的能力 ID；不實作 runtime，不更新 P1／P2，不宣稱跨任務效果已驗證。

## 2. 核心不變量與四層架構（保留）

維持唯一架構層級：

Core → Axes → Skeleton → Conditional Framework

| 層級 | 現行權威結構 | 本版處理 |
|---|---|---|
| 第一層 Core | 思考核心 | 保持原義；以目標忠實、知識誠實、可修正、方法適配、可區辨驗證、品質／成本分開、受控更新及誠實停止為不變量 |
| 第二層 Axes | A1–A6 六條認知主軸 | 保留，不以五主軸取代；按責任映射補清邊界 |
| 第三層 Skeleton | N01–N18 十八個骨架節點 | 保留；將蒸餾出的九個操作責任映射回現有節點，不直接增建九節點副本 |
| 第四層 Conditional Framework | F0–F7 | 保留條件式工作模型，按任務／風險選擇路徑、深度、回流和停止條件 |

治理、安全、工具、執行狀態、記憶、trace／audit、持久化與評測仍是橫向支援平面，不構成第五個認知層。新增或改動節點仍必須先做既有能力盤點，證明原有契約確實無法承載，並有獨特責任、依賴、輸入／輸出、驗收、成本與退場規則。

### 2.1 六條既有主軸的唯一責任

- **A1 意圖與問題框定：** 目標、成功條件、邊界、硬限制、關鍵歧義及初始框架。
- **A2 證據與知識狀態：** 來源、觀察、主張—證據關係、未知、衝突、過期與查證狀態。
- **A3 問題模型與解釋：** 元素、關係、因果候選、競爭假說與區辨所需的觀察。
- **A4 方法選擇與策略：** 任務屬性、方法路由、資源／預算、檢驗方式及停止判斷。
- **A5 求解與方案形成：** 依選定方法推導、執行、產生候選及綜合成果。
- **A6 驗證、重框與回饋：** 檢查結果、定位錯誤、修正模型／方法、更新受影響內容、重檢與結案。

此六軸責任仍以細項矩陣與 N01–N18 的既有契約為準；本段是藍圖摘要，不取代節點規格。

## 3. 蒸餾五主軸／九責任的映射（不是新骨架）

新研究所歸納的五條責任主軸：①問題與目的定界、②資訊狀態與依據建模、③候選理解與推論建構、④檢驗與決策校準、⑤錯誤修正與閉環交付。它們是跨模型比較後形成的精簡責任視圖，不另立第二組 Axes。

| 蒸餾責任視圖 | 映射至既有架構 | 合併原則 |
|---|---|---|
| ①問題與目的定界 | A1；N01–N03；F1 | 不重做第二個目標層；以既有成功條件、邊界及框架節點承載 |
| ②資訊狀態與依據建模 | A2；N04–N06、必要時 N14 | 依據記錄與執行狀態分離；不把來源帳本、runtime 狀態、長期記憶混成一種資料 |
| ③候選理解與推論建構 | A3、A4、A5；N07–N15 | 模型／假說、方法選擇、推導與方案形成依既有責任分開，避免新增「候選主軸」重複 A3/A5 |
| ④檢驗與決策校準 | A4、A6；N09、N12、N16 | 驗證策略與停止屬方法路由；驗收、信心／範圍校準屬結果控制，不另外建立重複評估引擎 |
| ⑤錯誤修正與閉環交付 | A6；N14、N17、N18；F5–F7 | 錯誤定位、依賴更新、重檢、持久化與交付按既有節點／流程歸位 |

### 3.1 九個操作責任的落點

| 蒸餾節點 | 既有落點 | 執行規則 |
|---|---|---|
| 工作模式／風險控制 | F0、F3；橫向控制與授權 Gate | 選擇處理深度，不新增第十節點或獨立控制中心 |
| 問題定界 | N01–N03／A1 | 重大歧義才追問；可安全繼續時明示假設 |
| 依據狀態 | N04–N06／A2 | 最小事實／假設／未知狀態保留；完整帳本條件啟動 |
| 候選生成 | N03、N08、N13–N15／A3、A5 | 當替代方案會影響決策時才明列多候選 |
| 推論追溯 | N05、N07、N09、N15／A2–A5 | 關鍵主張可追溯，不要求每個簡單回覆都輸出冗長推理鏈 |

## 4. 自適應運行策略（取代固定全流程的預設）

整體保持現行流程唯一責任：
- 一般非瑣碎任務仍由 SOP-META-001：INTAKE → AUTHORIZE → SELECT_SOP → PLAN → EXECUTE → VERIFY → PERSIST → REVIEW。
- 思考操作仍由 F0–F7 負責，依任務特性短路或回流。
- 藍圖施工仍由四梯次 PLANNING → REALIZATION → CLOSURE → FINAL_TEST 負責。

三者不可合成新的平行工作流引擎；以下三個模式是 F3／既有 LOAD-0–3、M/G/P/T 的執行深度選擇，不增加第五個通用路由軸。

| 模式 | 典型條件 | 最小行為 | 禁止的過度操作 |
|---|---|---|---|
| **快速通道** | 低歧義、低風險、短任務、答案可直接核對 | 理解要求、解題、檢查硬限制／格式、交付 | 不強制網搜、完整帳本、第二評估者、依賴圖或多輪反思 |
| **標準通道** | 一般分析、規劃與有限不確定性 | 目標／限制、最小依據狀態、適用方法、至少一項有用檢查、交付條件 | 不因模式名稱而固定呼叫多個模型或展開所有子節點 |
| **高保證通道** | 多來源衝突、長依賴鏈、高錯誤代價、不可逆副作用或重大未知 | 明確依據與依賴、真正有區辨力的獨立核驗、必要下游更新、剩餘風險及停止／核准條件 | 不以模型主觀信心取代可靠來源、工具檢查或授權 |

### 4.1 升級與降級觸發

可觀察觸發包括：關鍵歧義足以改變答案、來源衝突、關鍵主張無法核對、推論／依賴鏈延長、第一次檢查失敗、可靠新證據推翻上游假設、使用者提出可驗證錯誤、動作具有重大或不可逆副作用。

降級／停止條件包括：必要接受條件已滿足、沒有新增證據的重複檢查、額外檢查的預期收益低於其邊際成本，或關鍵資訊缺失而無法安全推進。遇到未知時可保留 UNKNOWN／BLOCKED，不得為了閉環而捏造完整答案。

路由不使用未校準的單一「信心分數」當作自動真值；門檻先採明確規則與任務類別，待具備實測資料後才校準。

## 5. 四項機制的最低核心與條件性升級

| 機制 | 最小核心行為 | 條件性加強 | 驗收依據 |
|---|---|---|---|
| 依據紀錄 | 區分關鍵事實、假設、未知與衝突；重要結論有依據來源 | 多來源研究、長鏈推論、審計或需重現時擴大為帳本 | 來源支持是否正確；未知／衝突有無被遮蔽；建帳成本是否合理 |
| 獨立檢驗 | 依任務做基本正確性／限制檢查 | 高影響結論、外部事實、長推論或首次核驗失敗時，換方法／來源／工具 | 是否引入不同且有用的證據、發現新增錯誤，而非純重述 |
| 依賴更新 | 已知上游條件改變時，更新所有受影響結論 | 長計畫、多檔案、多來源或依賴複雜時使用顯式依賴圖／差分列表 | 下游漏更新率、回歸錯誤、差分檢查成本 |
| 風險調度 | 每個任務都做粗粒度風險與可逆性判斷 | 高風險時加強驗證、人類核准、隔離、回退與執行邊界檢查 | 高嚴重度失敗／未授權副作用；低風險延遲和成本 |

**關鍵界線：** 模型認知層負責辨識並提議所需控制；對刪除資料、付款、權限變更等有外部副作用的操作，真正攔截與核准必須落在 runtime／工具邊界。文字規範本身不代表 runtime 已接線。

## 6. 外圍系統責任（支援平面，不增加認知層）

1. **Runtime／Orchestrator：** 管理模型與工具呼叫、任務路由、狀態轉移、重試、timeout、中斷／恢復與預算。
2. **Policy／Guardrail：** 管理權限、資料邊界、不可逆操作、人類核准和硬性禁止事項。
3. **狀態分離：** 區分本次任務的執行 checkpoint、主張／來源依據狀態，以及跨任務長期記憶；各自定義保留、讀寫權限與清理規則。
4. **Trace／Audit：** 記錄模型呼叫、工具、交接、失敗、重試、拒絕及成本。依資料敏感性採最小必要保存及遮罩。
5. **Eval／Regression：** 固定測試題、參考答案、開放題 rubric、版本差異、分題型失敗和成本趨勢。評估器不能由被測模型的自評單獨擔任真值。

以上多為對既有橫向支援平面的責任澄清，不直接表示本次新增已實作的模組或能力 ID。既有系統中已被 SOP、狀態契約、追溯或測試機制承載的部分，不再複製一份。

## 7. 驗收與回歸策略

本版採納的是「候選設計基線」，不是宣稱最優已證實。正式測試類別沿用 v0.3 矩陣 TC-01–TC-33；forAVArb 的 P01–P12 是挑戰題素材，應映射為既有 TC 的具體案例或變體，重疊時合併使用，不另建第二套測試分母／驗收總表。

### 7.1 必要比較組
- **C0：現行實際基線。** 凍結實際使用中的提示、工具與流程；不得以想像中的「一般方式」代替。
- **C1：自適應最小核心。** 本版建議的候選模式。
- **C2：固定全流程。** 作為過度處理成本的對照。
- **A1–A4：單項消融。** 分別移除依據紀錄、獨立檢驗、依賴更新、風險調度之一；其餘條件不變。

先以同一底層模型、同題、同工具權限和相同輸出限制跑 Pilot。每題每組重複三次只作流程與評分可行性試跑，不能保證統計效力；必要時改善題集，再以較大獨立確認集驗證。

### 7.2 指標分開報告

- **品質：** 封閉題正確率、開放題 rubric、限制遵守、無根據主張、錯誤前提接受、修正成功、下游漏更新。
- **效率：** token、端到端延遲（含 P50／P95）、工具呼叫、重試、人工介入與每次成功任務成本。
- **安全硬門檻：** 未授權副作用、高嚴重度失敗及是否要求必要核准。不得用其他題目的高分或低成本抵銷。
- **穩定性：** 重複執行波動、不同題型的效果分布和獨立確認集結果。
- **過度／不足檢查：** 額外檢查沒有新增證據或改善結果時的成本；高風險下漏掉必要檢驗的比率。

### 7.3 採納、降級與否決

- **核心保留：** 在多種任務有可重複收益，或可避免重要且不可接受的失敗，且實施成本合理。
- **條件啟動：** 收益集中在可辨識的高不確定性、依賴或風險情境。
- **簡化：** 全量實作無明顯淨收益，但最低行為仍有用。
- **移除：** 在獨立確認集上未顯示穩定收益、重要防護價值或合理成本效益。
- **INCONCLUSIVE：** 樣本不足、結果波動、評分不一致或題集不能區分條件。資料不足不得硬選勝者。

## 10. 最終裁定

**現階段最合理的候選是：四層既有架構不變，加入明確的自適應運行策略，並把蒸餾五主軸／九責任作為既有主軸與節點的責任映射。** 常駐的是最低程度的目標、依據誠實、任務限制、必要修正與停止責任；完整帳本、獨立外部驗證、顯式依賴圖及高保證程序按條件啟動。執行層負責工具授權、持久狀態、trace 與回歸評估。
