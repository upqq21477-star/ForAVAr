# 重複比對與錯誤／錯漏標記登錄

- **稽核日期：** 2026-10-20
- **範圍：** 封包 B 原始 ZIP 與四個成員、兩份 Markdown／DOCX 配對、ZIP A 來源狀態、forAVAr 現有解析文件、清冊、唯一職責矩陣、解析流程及 README 索引。
- **標記原則：** 原始 ZIP 保持不變。已確認的內容矛盾、可證明的格式損失、已知來源缺口、尚未完成的驗收與工具誤報分開登錄。
- **結論：** 本輪發現 1 項來源內容內部矛盾、1 項格式功能損失、2 項已知／未結案缺口、1 項文件範圍陳述需澄清、1 項已排除的檢查器假陽性。ZIP A 仍屬來源讀取阻塞。

## 1. 標記等級

| 等級 | 意義 |
|---|---|
| `CONFIRMED_ERROR` | 來源內容內部矛盾或可直接證明的錯誤。 |
| `CONFIRMED_FORMAT_LOSS` | 轉換後的格式功能未保留；不代表文字內容必然消失。 |
| `KNOWN_GAP` | 來源本身已記錄缺失，或必要驗收尚未完成。 |
| `SCOPE_CLARIFICATION` | 舊報告的範圍描述應標明基準時間，避免被誤讀成現況。 |
| `FALSE_POSITIVE_CLOSED` | 曾被初步比對標示為疑似錯漏，但經格式正規化再查證後排除。 |
| `BLOCKED` | 未取得原始證據，不能判定內容正誤。 |

## 2. 錯誤與錯漏標記

### ERR-001｜對話紀錄的訊息總數與範圍句互相矛盾

- **狀態：** `CONFIRMED_ERROR`
- **來源：** 封包 B 的 `P2_封包式問題解決架構_對話原文紀錄.md` 與 `.docx`。
- **直接證據：** 兩種格式都能找到訊息編號 1–15；完整性初核寫「主訊息共 15 則（8 則使用者、7 則助理）」，但範圍句寫「本輪主題對話共 13 則訊息」。同一文件又寫訊息 1–13 是核心設計討論、14–15 是文件交付／保存檢查。
- **判定：** 來源文字的總數與範圍措辭不一致。這不是 ZIP 解壓錯誤，也不是兩種格式少了訊息編號。
- **可能解釋：** 「13」原本可能指核心設計討論，不含後兩則交付／保存訊息；此解釋標為 `INFERRED`，不能當成原作者已確認的修正。
- **影響：** 不能只依「共 13 則訊息」宣稱已覆蓋所有編號訊息；文件摘要和引用必須指出這個矛盾。
- **處置：** 保留原始 ZIP，不直接改寫成員。若日後取得原作者確認或平台原始匯出，再產生有版本紀錄的更正副本。

### GAP-001｜訊息 1 前的助理回覆只有結尾片段

- **狀態：** `KNOWN_GAP`
- **來源：** 封包 B 的對話紀錄 Markdown／DOCX。
- **直接證據：** 兩種格式都明確說明訊息 1 之前有一則較早助理回覆，但只保存可見結尾片段，完整前文無法從目前可檢索來源取得。
- **判定：** 已知來源缺口；ZIP 內現有兩種格式不足以恢復缺失的原文。
- **影響：** 文件可供上下文回查，但不能當作已證明零遺漏的完整聊天原文。
- **處置：** 保留缺口標記。只有取得更早的原始聊天匯出或可驗證的原始記錄後才能補齊；不得由摘要反向編造全文。

### FMT-001｜Markdown 的五個歷史 sandbox 連結未保留 DOCX 可點擊超連結

- **狀態：** `CONFIRMED_FORMAT_LOSS`
- **來源：** 封包 B 的對話紀錄 Markdown 與 DOCX 主文件。
- **直接證據：** Markdown 有 5 個歷史 sandbox 連結；DOCX 主文件未保留相應的 Word 外部超連結元素。
- **判定：** 已確認「可點擊連結功能」未保留。這不等於連結文字一定完全缺失，也不證明歷史 sandbox 目標現在仍可使用。
- **影響：** 讀者在 DOCX 中可能無法直接透過連結開啟歷史交付物。
- **處置：** 不改動原始封包。若要提供新版文件，須先確認目標是否仍有效，再決定保留純文字、轉為可用 URL，或標註為歷史連結失效／未知。

### GAP-002｜Markdown／DOCX 的非表格正文語意等價尚未完全驗收

- **狀態：** `KNOWN_GAP`
- **來源：** 封包 B 的兩組 Markdown／DOCX 配對及 OOXML 內容。
- **已通過：** 外層 ZIP 四個成員的解壓大小與 CRC32 均通過；兩份 DOCX 的內層 OOXML 各 17 個成員逐項解壓、大小及 CRC32 核驗均通過；Markdown 標題覆蓋 147/147；13 張表、137 列、379 格正規化文字比對無差異。重新比對並去除 Markdown 行內標記後，對話紀錄 75 個標題、企劃書 72 個標題均找到對應文字。
- **已補驗通過：** 每份 DOCX 的 14 個內部 relationship targets 均存在；每份 `[Content_Types].xml` 的 Default／Override 對帳通過，缺少型別宣告為 0、孤立 Override 為 0；兩份文件共 28 個內部目標、缺失目標為 0、外部 relationship 為 0。
- **未通過／未完成：** 非表格正文尚未逐段完成語意裁定；主文件以外的註腳、註解、頁首頁尾等部件雖已通過結構與關係檢查，尚未逐部件與 Markdown 做語意對帳。
- **判定：** 目前沒有證據支持「全文已證明零遺漏」或「兩種格式完全等價」。
- **處置：** 逐段對齊兩端正文，對每個實質差異保留原文、位置、差異類型及判定依據；另明定是否把頁首頁尾、註解、文字方塊、關係檔和其他 OOXML 部件納入完整性範圍。

### DOC-001｜跨文件重複掃描的歷史樣本數需標明時間範圍

- **狀態：** `SCOPE_CLARIFICATION`
- **來源：** `參考資料/解析文檔/跨文件重疊與唯一職責矩陣.md` 的重複檢查記錄。
- **直接證據：** 矩陣保留一次歷史檢查「11 份既有 Markdown」的樣本數；在新增本登錄前的掃描樣本為 13 份參考資料 Markdown；加入本登錄後，現行完整 tree 有 14 份參考資料 Markdown（全庫共 15 個 Markdown，另含 2 個 ZIP）。
- **判定：** 11 份是舊批次範圍，不應被當成現況全量掃描數。新增本登錄前對 13 份參考資料 Markdown 的掃描是歷史基準；新增後已對現行 14 份參考資料 Markdown 重掃，未發現跨文件完全相同且長度至少 180 字元的段落。此結果不排除較短、表格內或語意改寫的重複。
- **處置：** 矩陣應將 11 份明確標為歷史基準，並引用本次 13 份的更新結果。

### FALSE-001｜企劃書 12.1 標題曾被字面比對誤判為缺失

- **狀態：** `FALSE_POSITIVE_CLOSED`
- **來源：** `P2_封包式問題解決架構企劃書_v0.1.md` 與相應 DOCX 主文件。
- **直接證據：** 初步字面比對曾將 Markdown 標題 `12.1 `FAIL` 與 `BLOCKED` 的差異` 標為未匹配。再次比對時移除 Markdown 反引號及其他行內標記後，DOCX 中找到「12.1 FAIL 與 BLOCKED 的差異」。
- **判定：** 這是比對正規化不足造成的假陽性，不是已確認的章節遺漏。
- **處置：** 標題比對必須先正規化 Markdown 呈現標記；不得以此項要求修改來源文件。重新比對結果為對話紀錄 75/75、企劃書 72/72 標題覆蓋。

### BLOCKED-001｜封包 A 原始位元組仍無法取得

- **狀態：** `BLOCKED`
- **來源：** `參考資料/原始檔案/壓縮檔/P2-relay-R3d130j.zip`。
- **直接證據：** GitHub tree 可確認檔案存在、大小 1,885,519 bytes、Git Blob SHA `0e58526bd35c30a25f3b27033a4952ec5f25bf10`。本輪重試 Contents Base64 模式仍回傳長度 0；Blob fetch 以 UTF-8 解碼二進位失敗；raw URL／瀏覽抽取路徑未回傳 ZIP 位元組；執行環境直接下載另遇 DNS 解析失敗。可用外部解析服務當時亦因帳戶額度不足而無法執行。
- **根因判定：** 目前可用的內容讀取工具只交付文字或無法保留該檔的二進位位元組；替代 raw 頁面抽取器對所試 URL 回傳 404，但 GitHub tree 的精確路徑仍存在。這些都是取得管道失敗，尚無證據判定 ZIP 本身有問題。無法檢查 ZIP 內部目錄、成員數、CRC、程式、工具及測試。
- **處置：** 保留原始檔與阻塞記錄；下一次解阻必須使用能下載／輸出原始二進位位元組的管道，而非 HTML／文字抽取。取得位元組後，先驗證檔案大小與 SHA-256，再核對 ZIP 結構、成員清冊及 CRC。
