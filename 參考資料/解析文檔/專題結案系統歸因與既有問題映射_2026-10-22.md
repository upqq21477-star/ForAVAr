## 摘要

結案時只把可跨題重用的流程控制與問題歸因寫入系統；專題事實、案件時間線、人物假說、原始來源及專題專用藍圖不搬入全域系統。當前所識別的通用失效模式已可由既有 PR-001／006／011–013／021／027／028／031／034–036／039／042／043／047／053／054 與 CF-001／004／005／008／009／010 承載；不另建立同義問題 ID 或平行登錄。

本紀錄用於說明如何歸位、哪些控制仍待驗，以及專題原始材料清除的驗收邊界。它不保留來源案件的具體案情、時間線、涉案人物、證據細節或犯罪假說。

## 2. 可遷移的基礎屬性候選

下列內容只作工作方法層的候選，不是新的全域功能，也不自動修改正式企劃：

1. **專題隔離**：在研究開始前建立獨立 PROJECT_ID、範圍與來源入口，防止不同題目共用未經判斷的假設。
2. **延後抽象化**：先完成專題內論證，再把局部事實分開於可跨題重用的問題屬性、方法條件及控制機制。
3. **依問題屬性路由方法**：至少考慮目標、來源結構、未知程度、風險、可逆性、跨文件程度與交付類型。
4. **單一權威歸位**：問題、方法、執行紀錄、追溯事件與能力狀態各由既有權威文件承擔，不另建同義清冊。
5. **證據成熟度分層**：規格存在、內容寫入、讀回、測試、Runtime 和實際成效分開標示。
6. **校正形成可追溯控制**：使用者校正或重複偏差須先對帳既有 PR，再連結最小控制與回歸，不把單次補文視為修復。
7. **風險比例與停止規則**：只有在新的檢查可能改變判斷或風險處置時才升級驗證；沒有新證據與新行動時停止重複分析。

這些候選是否適用其他領域，須由獨立專題的實際結果、反例及成本資料判斷。單一專題不構成通用性驗證。

## 3. 唯一責任與實際寫回

- 問題 ID／嚴重度／狀態：由既有《問題清單主軸》及對應分支唯一維護。

- 能力覆蓋與功能狀態：使用既有能力登錄及原始領域權威；本次不新增能力節點。
- 方法路由：參照 CF-001／《通用問題屬性導向方法選擇框架》。
- 結果保存、引用與索引：沿用 CF-004／CF-008／版本治理。
- 可重複方法才可進入 CF-010／SOP-DOC-001 的候選程序；本次不因此改寫 SOP。
- 重大語意變更與正式企劃修改仍受既有授權、前置盤點、影響評估及回歸規則限制。

## 4. 專題原始材料的清除邊界

本次清除的是已結案專題的活動資料夾與其中原始／案件專用文件。系統只保留本文件中的通用問題歸因、既有 ID 映射、限制與清除追溯；不將個案事實、人物、時間線、證據細節或專題專用藍圖轉存到全域知識庫。

清除驗收需另記：清除前檔案數與大小、實際從目前分支移除的檔案數、殘存路徑／引用掃描範圍，以及 Git 歷史是否被處理。從目前分支刪除不等於從過往提交、其他 clone、快取或外部備份永久抹除。
