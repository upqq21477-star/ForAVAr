## 3. 系統架構與職責

### 3.1 核心定位

來源中的 docs/architecture/P2-System-Blueprint-v1.0.md 實際標題為「P2 系統總體藍圖 v4.0」，並標示 P2_TARGET_BLUEPRINT / DESIGN ONLY。P2 的設計目標是通用 AI 工程大腦：理解目標、研究未知、選擇方法與能力、組建工程工作群、建造／修補系統，再於有限上下文內檢查結果。這是目標架構聲明，不是所有功能已完成的證據。

藍圖與 README 描述的核心分工如下：

- **Brain／認知決策：** 理解意圖、建立問題模型、比較方案、作出語意決策並分類變更。
- **Central／協調器：** 依契約進行接納、授權、路由、狀態轉移與交接；不取代 Brain 作語意判斷。
- **Role／Executor：** 在有界 Work Unit 內施工，按指定輸入、輸出、失敗語義與接受條件交回結果。
- **Current／Runtime Evidence：** 記錄目前有效狀態與執行事實；不得用規劃、檔案存在、靜態掃描或舊執行結果代替目前版本證據。
- **Knowledge／Librarian：** 按需取得並保留來源與上下文，避免全庫或完整對話成為每次啟動的固定讀取集合。
- **System Factory：** 支援受契約約束的建造、修補與重建流程。
- **Assurance／Verifier：** 依預先定義的驗收條件獨立查核施工結果與證據。
- **Evolution／Distillation：** 把已證實且可重用的根因修正蒸餾為契約、能力、規則或必要測試，不把全部 Trace 永久留在活動資料。

藍圖列出的主要不變量包括 Current-first、最小充分資料、UNKNOWN 不等於 MISSING、職權與狀態所有權、證據不得越級、資料退場、最低環境以 AI 對話加 GitHub 為基線、思考與施工分隔、系統間以契約交接、根因改進機制、成本閘門，以及高影響變更的授權與驗收控制。
