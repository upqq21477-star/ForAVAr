## 1. 核心修正：通用的不是固定流程，而是方法選擇能力

前一版把本次對談中使用的「先定核心、建立框架、首輪逆向批判、列出方案、逐輪記錄」整理成一套通用流程。它保留了有價值的做法，但犯了抽象層級不夠根源的問題：**它把特定情境有效的操作模式，直接當成所有問題都需要的共同程序。**

例如，測量長度、估計重力、判斷系統故障、證明數學命題、選擇企業方案與設計遊戲策略，表面上是不同領域；更根本的差異，是它們要求的認知操作、可用證據、未知的來源、成功判準及可接受風險不同。

因此，新框架不是「所有問題都走同一條流水線」，而是：

**辨識問題屬性 → 找出當前真正的知識／決策缺口 → 選擇適配方法 → 用證據或可檢驗結果更新判斷 → 必要時重新界定問題。**

固定流程可能在簡單問題上浪費成本，在特定學科上選錯方法，也可能讓錯誤框架越做越精細。通用性應來自共同的問題描述與方法選擇規則，而不是強迫所有任務遵守相同步驟。

## 2. 外部方法比對

| 來源／領域 | 可核對的做法 | 對本框架的啟示 | 外推限制 |
|---|---|---|---|
| NASA 系統工程決策分析 | 區分決策目標、評估標準、替代方案、評估方法、假設、不確定性與結果紀錄；分析深度依決策的重要性及不確定性是否可能改變選擇調整 | 先定問題和判準，再選方案與分析工具；不確定性只有可能改變決策時，才值得投入額外成本降低 | 是工程決策程序，不是所有知識問題的唯一方法 |
| National Academies：科學實踐 | 指出不能把科學簡化成單一固定的「科學方法」；不同研究採用不同的觀察、建模、實驗、批判和溝通方法 | 保留共同的證據與檢驗原則，但方法需要依問題和領域調整 | 支持方法多樣性，不直接驗證本文件的具體分類 |
| NIST：量測與不確定性 | 先定義 measurand（欲量測的量），建構量測／觀察模型，辨識輸入與不確定性，才計算或報告測量結果 | 先釐清「究竟要知道什麼」以及如何觀察，不要直接套用一般研究或方案選擇流程 | 主要針對量測；其他類型需要不同的專門方法 |
| Smith & Shaw（2019）：問題結構化方法文獻回顧 | 用本體論、認識論、價值論、方法論四個面向辨識問題結構化方法的假設與特徵 | 可用「研究對象和邊界是什麼、什麼算知識、依據誰的價值、使用何種方法」作跨領域檢查 | 是一個分析框架，不等於所有問題皆由四個面向完整涵蓋 |
| National Academies：科學可重現性與可複製性 | 強調方法、資料、分析、變異／不確定性及限制要能被檢查；不同學科的具體技術可以不同 | 重要結論必須保留可追溯依據、方法與限制；驗證方式不能只靠模型自我宣稱 | 可重現與可複製的適用形式依研究設計而異 |

### 外部比對裁定

這些來源支持三項設計原則：

1. **共通抽象層與專門方法層必須分開。** 共通層描述問題與選擇方法；量測、因果推斷、數學證明、最佳化、工程決策等保留不同專門程序。
2. **流程深度依決策需要調整。** 不確定性若不會改變答案、行動或風險處理，額外分析可能沒有價值；若可能改變重要決策，就值得進一步查證。
3. **方法的正確性須由它所處理的問題決定。** 不能因一種方法在某領域成功，就推論它適用於其他所有領域。

本文件是把這些原則整合成的工作模型，並非任何單一來源已經驗證的標準。尤其「下列屬性分類是否足夠」「如何最佳化方法選擇」仍需測試。

## 3. 原始問題屬性：先描述問題，不先指定流程

問題可被視為一組特徵，而不是只用「物理題、遊戲題、工程題」等領域標籤識別。以下維度應分開記錄，不合併成一個籠統的難度分數。

### P1｜所需的認知操作

最先判斷使用者實際要得到什麼。常見目的是：

- **描述／分類**：弄清楚現況、屬性或所屬類別。
- **測量／估計**：推算某個量、參數或範圍。
- **解釋／診斷**：解釋為何發生、辨識原因或故障。
- **預測**：估計在指定條件下會發生什麼。
- **決策／最佳化**：在限制下選擇行動或配置資源。
- **設計／干預**：創造或修改系統，使其達到目標。
- **形式化／證明**：確認命題在明確前提下是否成立。
- **探索／問題界定**：目前不知道真正問題、目標或適用邊界。

一項任務可能同時包含數種操作。例如，工程故障處理可能先量測，再診斷根因，最後比較修正方案。此時應組合方法，不強迫歸入單一類別。

### P2｜問題定義與結構成熟度

檢查目標、對象、邊界、變數、限制、方法或成功條件是否明確。

- **結構成熟**：問題與成功判準已清楚，方法或比較空間大致可定義。
- **部分結構化**：主要問題已知，但部分限制、因果或評估方式仍待查。
- **未充分結構化**：問題邊界、目標、利害關係或解決路線仍有重大歧義。

問題越未結構化，越需要先做界定、探索、建立候選框架與邊界檢查；問題越明確，越適合直接採用相應的專門方法。不可把「先建框架」硬套於已經明確的簡單任務。

### P3｜未知與不確定性的來源

至少要區分：

- **語義／定義不確定性**：關鍵詞或問題本身有多種解讀。
- **資訊不足**：所需資料尚未取得。
- **觀測／量測不確定性**：測量方法、儀器、樣本或資料品質有限。
- **隨機變異**：系統本身存在波動，重複觀察可能不同。
- **模型／因果不確定性**：多種機制都能解釋現有資料。
- **價值／偏好不確定性**：成功條件、權重或利害關係人偏好未明。
- **環境／未來不確定性**：條件可能在執行期間改變。
- **執行不確定性**：即使方案可行，實際實施仍可能失敗。

這些來源可能同時存在，但需要不同的處理方式。增加網路搜尋不能直接解決價值衝突；增加反思輪數不能代替量測校準；提高測量精度也不能解決錯誤的問題定義。

### P4｜可觀測性與可檢驗性

確認是否有：
- 直接觀察、可靠來源或可取得的資料。
- 可執行的實驗、計算、模擬、測試或證明。
- 能區分不同解釋的觀測結果。
- 可重複性、基準或獨立檢查方式。
- 清楚標示無法直接觀測、不可重複或只可間接推斷的限制。

若有可檢驗方式，就應盡量設計可區分候選的測試；若沒有，結論必須降低確定性，說明依賴何種假設以及哪些部分目前無法驗證。找不到測試不等於命題為假，也不等於命題為真。

### P5｜目標、限制與價值結構

- 是否有明確的成功標準？
- 是否有不可妥協的硬限制？
- 是單一目標，還是效能、成本、安全、時間、可維護性等多目標權衡？
- 各目標能否量化？若不能，如何作定性比較？
- 不同利害關係人是否對「好」有不同定義？

在選擇方案前，先區分硬限制與可權衡標準。多目標衝突時，不應用未說明的權重製造看似客觀的單一排名。

### P6｜候選解的結構

問題可能是：
- 有一個明確解法，重點在執行或驗證。
- 有數個離散選項，重點在比較。
- 存在大量或近乎無限的候選組合，需搜尋／最佳化。
- 有數個競爭假說，重點在區分哪個更能解釋資料。
- 解法仍未知，需要先探索候選空間。

只在確實存在多個有意義的候選時，才需要候選方案表；若搜尋空間很大，應先定可行範圍、排除條件和搜尋策略，不能假裝已經列出「所有方案」。

### P7｜系統互動與時間結構

- 靜態或隨時間變動。
- 因果鏈清楚或互相依賴。
- 線性／可分解或存在強非線性回饋。
- 單一決策者或多個有自身目標的參與者。
- 對手會否觀察並反制策略。
- 當前選擇會否改變未來環境或可選行動。

有回饋、時序依賴或策略性對手的問題，需要動態模型、情境／對手分析、模擬或連續監控；不可只比較一組靜態平均值。

### P8｜失敗代價、可逆性與資源限制

判斷錯誤後果、行動是否可回復、時間期限、預算、資訊取得成本及延遲成本。

- 低風險且易回復：可先採快速、低成本的處理方式。
- 高風險或難以回復：提高證據門檻、獨立檢查、驗收及安全措施。
- 時間急迫：先完成最低必要的安全／有效行動，再補足完整分析。
- 資源有限：只深入那些可能改變決策的關鍵未知。

這些屬性決定程序的嚴謹度，但不應與問題本身的複雜度混為一談。

## 4. 四個根本檢查面向

P1–P8 是操作性分類；另以四個較根本的問題作完整性檢查，參考問題結構化方法文獻中的概念。

1. **對象與邊界（Ontology）**：我們認為問題中的對象、系統、狀態、關係和邊界是什麼？有沒有不合理排除？
2. **知識與證據（Epistemology）**：哪些觀察或來源能支持主張？什麼算驗證？如何表示不確定？
3. **價值與成功（Axiology）**：誰的目標被優先？什麼算好結果？不同價值是否衝突？
4. **方法與檢查（Methodology）**：哪種研究、計算、量測、證明、實驗或決策方法能回答這個問題？其適用條件和限制是什麼？

這四個面向是檢查透鏡，不是四個必須逐項寫成長文的階段。只有當某個面向可能影響問題定義或決策時，才展開。

## 5. 方法選擇矩陣：由問題屬性選方法

| 問題主要屬性 | 優先考慮的方法模組 | 不應用什麼取代 |
|---|---|---|
| 對象／術語有歧義 | 定義澄清、操作化、邊界檢查、不同問題框架比較 | 不應直接用模糊名詞進行精算 |
| 需要量測／估計 | 定義被測量量、單位／基準、量測模型、校準、資料品質、不確定性與誤差傳遞 | 不應以多輪討論代替真實測量及不確定性分析 |
| 需要描述現況／查事實 | 查找權威且合時效的來源、核對原始材料、交叉來源、標示證據範圍 | 不應把模型記憶或單一搜尋摘要當成已驗證事實 |
| 多個原因可解釋現象 | 競爭假說、預測差異、反例、診斷測試、因果分析 | 不應只挑支持初始假說的資料 |
| 需要預測 | 建立基線、明確預測範圍、訓練／測試分離、比較誤差與不確定區間、外部驗證 | 不應以樣本內表現或敘事合理性直接推斷泛化能力 |
| 需要選擇方案 | 硬限制篩選、評估準則、候選比較、敏感度與風險分析、必要時試點 | 不應在未定判準前宣布某解「最好」 |
| 數學／形式問題 | 定義與前提、形式推導、證明、反例、數值解或演算法正確性檢查 | 不應把經驗性支持當作形式證明 |
| 設計／建構／施工 | 需求、設計候選、介面與限制、原型、驗收標準、實作測試與回歸 | 不應只靠方案討論而不驗證產物 |
| 動態／策略互動 | 時序模型、不同對手／環境情境、模擬、穩健性、實戰／執行後監控 | 不應假定單一靜態局面代表所有環境 |
| 多方價值衝突 | 利害關係人與邊界分析、偏好／約束澄清、情境權衡、透明的決策依據 | 不應把價值判斷偽裝成純客觀事實 |
| 問題尚未界定 | 問題結構化、探索、候選問題框架、短週期研究與重新界定 | 不應過早固定唯一題目或方案 |

任務常包含多種屬性。方法選擇可以組成依賴鏈，例如「定義被測量量 → 量測／取得資料 → 分析原因 → 比較介入方案 → 驗收結果」，而不是只能選一列。

## 6. 重建後的適應式流程

這是依問題屬性選方法的元流程，不是一套要求每個階段都必須執行的通用流水線。

### M0｜建立最小問題描述

提取核心操作、對象／邊界、期待輸出、判準／限制、已知狀態、未知來源、可用證據、風險與資源。若問題很明確且低風險，允許直接進入專門方法；若目標或邊界不清楚，先做問題結構化。

### M1｜選擇主要方法模組

依 P1–P8 選擇一個或多個合適方法模組，並說明為何適用、其假設與限制。方法不匹配時，須能改選，不能為了流程一致而使用錯誤工具。

### M2｜決定是否需要建立框架或候選集

- 問題定義不清楚：先比較可能的問題定義，保留合理分支。
- 結構複雜或高風險：建立精簡問題地圖，並檢查邊界。
- 存在多個有意義選項／假說：列出少量代表性候選，包含基線或「不採取新行動」。
- 單一路徑且有成熟方法：不要硬造多方案或完整框架。

### M3｜決定要不要啟用反證／逆向思考

反證不是所有任務的固定獨立階段。當初始假設、框架或選擇可能造成重大方向錯誤，或任務屬研究、診斷、多方案決策、高影響情境時，優先進行反方審查。

批判必須連接到可檢查事項：哪個假設可能錯、會觀察到什麼、哪一項資料能區分解釋，以及什麼結果會改變結論。簡單事實題不需要為了滿足程序而製造反方論述。

### M4｜選擇下一個最有價值的行動

問：「哪一項可取得的證據、計算或測試，最可能改變下一步或降低重大風險？」

若答案可能改變選項排序、核心解釋、安全措施或是否繼續投入，則優先執行；若不會改變決策，除非有其他明確價值，否則不再增加研究成本。

### M5｜檢查結果與更新狀態

依對應方法模組的標準檢查結果。把已確認、來源主張、推論、假說、未知、衝突與阻塞分開。記錄新資料改變了哪些判斷、候選或限制；不能以多輪重述或多個代理的同一結論代替獨立證據。

### M6｜決策、行動或保持未決

結果可以是：
- 目前已足夠回答／採用方案。
- 採取可逆的小規模試驗以獲得資訊。
- 保留多個候選，等待更有區辨力的證據。
- 修正問題定義或模型。
- 因限制／矛盾進入 BLOCKED 或 UNKNOWN。
- 暫時停止，因進一步研究的預期價值低於成本。

不必強迫每個問題產生單一「最優解」。當前證據不足時，範圍受限的結論比虛假的確定性更合適。

### M7｜監控、重框與停止

當新證據推翻前提、關鍵結果無法解釋、條件改變、測試失敗或使用者目標改變時，回退至受影響的步驟，重新選擇方法並檢查後續結論。

只有需要跨輪記憶、協作、施工、決策追溯或交接時，才維持持久工作紀錄。簡單一次性問題不必強制建立封包或詳細紀錄。

## 7. 紀錄是共通支援層，不是核心認知流程

前一輪強調「邊討論邊紀錄」有價值，但要避免把它提升為所有簡單任務必須執行的步驟。

建議將紀錄啟用條件限定為：長期／多輪討論、會改變正式方案、涉及多個候選或外部證據、需要交接、需要追蹤風險，或需要事後驗收。

最小紀錄只包含：
- 當前問題描述與版本。
- 使用的方法模組及其選擇理由。
- 關鍵證據、未知與假設。
- 候選比較／本輪裁定。
- 新增、推翻或變更的內容。
- 剩餘風險與下一個有價值的行動。

紀錄重點是可追溯的狀態變更，不是逐字抄寫所有對話。來源與測試結果保留在各自權威位置，紀錄只引用和濃縮。

## 8. 科學性驗收：如何知道分類與流程是否夠好？

不能只因架構看起來全面就宣布通用。應建立跨類型的測試集，至少涵蓋量測、現況查證、根因診斷、預測、數學形式問題、多方案決策、設計／施工、探索界定、動態策略及時間敏感任務。

### 比較候選

- **A｜單一固定流程**：所有任務使用同一套全流程。
- **B｜按領域分流程**：先由領域標籤選擇專門工作流程。
- **C｜按問題屬性選方法**：先辨識認知目的、問題結構、未知、可驗證性、判準和風險，再組合方法模組。
- **D｜簡單基線**：不強制正式框架，只採用該任務通常需要的基本處理方式。

### 評估指標

1. 目標是否被正確理解，方法與問題屬性是否匹配。
2. 重要事實／因果／限制是否被漏掉。
3. 假說、方案及核心前提是否由適當證據檢驗。
4. 結論是否超出證據支持範圍。
5. 是否正確承認未知、衝突與無法驗證。
6. 時間、工具、Token、人力介入及返工成本。
7. 是否在新證據出現時適當更新，而非過早鎖定或無理由重開。
8. 在不同情境和問題類型間能否維持有效性。

採用盲評或多評估者、預先定義的評分規準與未用於調整流程的保留案例，以減少只對既有案例調整的偏差。每類問題需要不同品質基準；不能用同一個「答案字面相似度」評估所有任務。

### 採納規則

只有在可量測的任務品質或風險改善，足以抵銷額外時間與複雜度時，才啟用更重的模組。若某模組沒有改善相關錯誤，也沒有帶來其他明確效益，就簡化或停用。測試樣本與量測方式需依問題變異及欲偵測的改善幅度規劃，不能預先宣稱某個固定小樣本就證明通用性。

## 9. 本輪裁定

- **保留為通用核心**：先描述問題屬性、識別知識缺口、選擇合適方法、用適當證據更新判斷、依後果調整嚴謹度、必要時重框與明確停止。
- **改作條件式模組**：核心／框架展示、首輪逆向批判、候選方案清單、外部研究、多角色／獨立審查、敏感度分析、完整紀錄與正式驗收。
- **從通用規則移除**：所有任務必須先建框架；所有任務都必須列多個方案；每次都必須逆向批判；每輪都必須保存完整紀錄；步驟愈多便愈科學。
- **尚未宣稱**：此屬性分類已經完備、方法選擇器已經最佳化，或整套程序已證明比專門方法更有效。需要跨類型試驗後才可裁定。

## 11. 與 Skill／Agent 的關係

未來 Skill／Agent 不應只是背誦「先核心、再框架、再反證」；它應做到：

1. 將請求表示成一組基本問題屬性。
2. 根據屬性與風險，選擇、組合或省略方法模組。
3. 解釋關鍵方法選擇及其假設，不把模型推理過程假裝成外部證據。
4. 優先尋找能改變結論或降低重大風險的資料與測試。
5. 持續更新必要紀錄，讓長期任務可交接。
6. 在方法無法適用或證據不足時明確標示限制，不硬湊流程或結論。
7. 使用跨問題類型的評估集持續驗證方法選擇品質。

這才是可泛化的技能核心：**通用屬性描述器＋方法路由器＋專門方法模組＋證據／結果評估器＋可選紀錄層**。它比固定的一串提示詞更適合往 Skill／Agent 發展，但仍需原型測試證明工程效益。
