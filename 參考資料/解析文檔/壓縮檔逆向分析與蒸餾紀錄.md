## 3. 封包 B 的內容蒸餾

企劃書自標示為 v0.1、PROPOSAL／尚待確認；不能當成 P2 已核准藍圖、Current 或實作證據。

### 3.1 核心流程

H0：解決問題。H1 五環節為：

**理解問題 → 決定做法 → 執行做法 → 檢查結果 → 修正與結案**

H0–H2 維持穩定；只有在能力選擇、條件判斷、策略分歧或回退位置需要分支時，才在 H3 展開。規劃、藍圖、施工、驗收及修正應共用流程原則，而不是各造一套生命週期。

### 3.2 單一權威底圖、多種視圖

樹狀位置表達「功能屬於哪裡」；前置條件、因果關係與封包引用表達「何時能做、結果交給誰、失敗回到哪裡」。功能樹、因果圖與角色圖若存在，應由同一份權威資料衍生，不能分別維護成多個真相來源。

### 3.3 最小封包契約

每個需持久化或交接的工作單位至少包含：

1. **定位與目標：** 封包 ID、所屬步驟、要解決的問題。
2. **輸入與條件：** 必要資料引用、前置狀態、權限及資源限制。
3. **動作與責任：** 允許執行的工作及負責角色／能力。
4. **結果與證據：** 產物、接受條件的核對結果、來源證據。
5. **狀態與下一步：** 當前狀態、下游或回退位置、阻塞／失敗原因。

### 3.4 中控最小責任

中控只負責：定位封包和合法下一步、檢查前置條件／權限／資源、派送已授權工作、接收結果和證據、依結果推進／回退／阻塞／停止。中控不取代語意決策、角色執行或獨立驗收。

### 3.5 狀態、啟用條件與證據

企劃書提出的初步狀態為 WAITING、READY、RUNNING、PASS、FAIL、BLOCKED。這是待與 P2 現有狀態機對帳的提案，不能直接新增成權威狀態。

能力啟用需同時檢查觸發、輸入、權限、資源、安全與衝突條件。可程式判定的硬條件由驗證器檢查；意圖與方法適用性屬語意判斷，必須保留來源、推論及假設。

狀態與證據分開：狀態說明工作走到哪；證據說明為何可相信結果。文件存在、靜態掃描、推論或模擬不能自動升格為真實執行通過。閉環後保留核心結果、決策、必要證據及下游所需資料，按規則封存或清理無用暫存。

## 5. 封包 A：已知內容、未驗主張與阻塞

來源：參考資料/原始檔案/壓縮檔/P2-relay-R3d130j.zip  
Git Blob SHA：0e58526bd35c30a25f3b27033a4952ec5f25bf10  
儲存庫大小：1,885,519 bytes。

### 5.1 讀取阻塞與本輪重試（2026-10-20）

- GitHub Contents API 的 Base64 讀取對此大型二進位檔回傳空內容。Git Blob／一般 fetch 嘗試將二進位資料當 UTF-8 文字解碼時失敗；直接查詢 Git Blob 的讀取工具亦回覆只接受 UTF-8 文字的 400 錯誤，沒有交付原始位元組。
- 先前執行環境直接下載曾遭 DNS 失敗。
- 本輪替代 raw 頁面抽取器對 forAVAr 與 P2 的已知 ZIP 路徑都回報 404，未取回位元組。GitHub API tree 仍確認 forAVAr 的精確路徑存在，大小 1,885,519 bytes、Git Blob SHA 為 `0e58526bd35c30a25f3b27033a4952ec5f25bf10`。該 404 是頁面抽取器的取得結果，不能推翻 API tree，也不能認定檔案不存在。
- 沒有從上述重試取得 ZIP 位元組；成員清單、CRC、壓縮方法及內容仍未知。

**根因：讀取管道不支援或未成功交付二進位位元組。狀態仍為 BLOCKED。** 目前沒有任何可用位元組供 ZIP 驗證，不能推論封包損壞或不存在；取得原始二進位後才能核對內部程式、工具、測試、版本及完整性。

### 5.2 跨儲存庫來源核對（直接讀取 GitHub 檔案樹）

- P2 唯讀儲存庫的 `參考資料/P2-relay-R3d130j.zip` 與 forAVAr 的封包 A 具有相同 Git Blob SHA：`0e58526bd35c30a25f3b27033a4952ec5f25bf10`，大小均為 1,885,519 bytes。這代表兩個儲存庫引用同一個 Git blob，不是第二份可解阻的副本。
- P2 的 `main` HEAD 為 `4be3a6fe6fdea00f54821e76f1cfbf9605e4e4fe`（2026-10-17）；這一提交將該 ZIP 以「Add files via upload」加入參考資料。
- 在 P2 目前完整檔案樹中，未找到交接所指的精確路徑：`docs/plans/P2-Relay-Update-Plan.md`、`tools/pack_handoff.py`、`tools/session_start.py`、`tools/slice.py`、`tools/close_session.py`。針對這些精確路徑的 GitHub 檔案提交歷史查詢也沒有返回記錄。
- **判讀邊界：** 這些路徑在目前 P2 repo/tree 中缺席，不代表它們不在 ZIP 內；交接明確指示規程和所需附件在壓縮檔內。因此一旦取到 ZIP，這五個路徑應作為優先檢查項。
