## 1. 目前討論的主框架

**先確認核心，再建立框架；第一輪先批判框架，不急著填滿細節；通過後再逐輪細化。**

1. **核心與目標**：目前真正要解決什麼？成果如何判定成功？
2. **粗略框架**：列出主要問題、依賴、候選分支、限制與未知。
3. **第一輪逆向批判**：找漏項、錯誤前提、替代框架、因果跳躍及能推翻整張地圖的反例。
4. **暫定工作框架**：若沒有已知的重大漏洞，先當作工作基線，不宣稱永久正確。
5. **逐輪細化**：一次處理一個重要缺口；每輪更新證據、判斷、未解問題與下一步。
6. **必要時重框**：新證據推翻核心前提、目標改變或重要原因被漏掉時，修正地圖並檢查受影響的舊結論。

**原因**：先建立骨架能維持主軸、顯示缺口；先批判可以降低「在錯誤問題上越做越精細」的風險；允許重框則避免第一輪的假設變成永久邊界。

**例子**：研究遊戲策略前，先確認目標是提高平均勝率、降低被反制風險，還是針對特定對手取勝。若目標未定義，直接比較策略排名就沒有可靠意義。

## 2. 流程不能強制套用於所有問題

先判斷任務型態，再決定框架和研究深度。

| 任務型態 | 建議方式 |
|---|---|
| 直接、低風險、答案明確 | 直接處理，不強制建立完整框架 |
| 範圍清楚的研究／比較 | 簡化框架，直接比較選項與證據 |
| 目標大致清楚的複雜問題 | 建立粗略地圖，首輪逆向批判，再逐輪深入 |
| 目標不清楚、問題尚未成形 | 先探索與界定問題，保留多個候選框架，不急著定唯一答案 |
| 根因診斷、架構建設或高影響決策 | 增加替代假說、外部查證、反例、測試與敏感度分析 |
| 時間緊迫或高風險事件 | 先採取必要的安全／止損措施，再補完整分析 |

研究深度可由輕到重調整，但不把複雜度、不確定性、失敗代價壓成單一分數。**框架的作用是協助決策，不是讓每個任務都承受同一套儀式。**

## 3. 不同領域如何處理未知與多個方案

| 領域 | 常見方法 | 如何分辨方案優劣 |
|---|---|---|
| 企業／工程 | 先定目標與限制，列替代方案，建立評估標準，使用試驗、原型、模擬與成本風險分析 | 比較實際效益、成本、風險、時程與不確定性；做敏感度分析，確認未知是否會改變排名 |
| 數學／最佳化 | 將問題形式化，定義可行集合、目標函數與限制；使用證明或可驗證的數值演算法 | 區分「有可行解」「找到較好解」與「證明全域最優」；多目標問題可能只能得到 Pareto 最優候選集合 |
| 物理／科學研究 | 提出競爭假說，推導各自的可觀測預測，以觀察、實驗、控制變因及重複驗證來檢驗 | 優先找能區分假說的證據；未通過預測的假說需修正或放棄，結論依證據強度暫定更新 |
| 遊戲／策略分析 | 明確化局面、規則、資源、效用、對手類型與可能反制；以推演、模擬、自我對弈或實戰測試評估 | 同時看平均表現、最壞情境、對手分布、可被利用程度與成本；理論均衡不必然等於對特定對手最有效的策略 |

**共通原則**：不靠方案數量取勝，而是找出少數有代表性的候選方案，再設計能區分它們的測試。企業常用的權衡研究、科學的競爭假說、數學的形式化與證明、遊戲的對局評估，方法不同，但都需要明確判準及可檢驗的結果。

## 4. 綜合後的候選決策流程

1. **定義成功**：目標、限制、時限，以及哪些條件不可妥協。
2. **建立問題地圖**：分開已知事實、來源主張、推論、假設與未知。
3. **提出少量不同方向的候選框架／方案**：不只微調同一個想法，也保留合理的替代解釋。
4. **先做框架批判**：問「是否選錯問題、漏掉重要因素，或把假設當成事實？」
5. **選擇高區辨力測試**：優先取得可能改變決策的證據，而非累積更多相似資料。
6. **比較並檢查穩健性**：依相關標準比較效益、成本、風險與不確定性；測試假設或權重稍變時，排名是否改變。
7. **作出有條件的決策**：記錄選擇理由、被淘汰方案、尚存風險與重開條件；證據不足時保留多個候選，而非硬選唯一答案。

### 例子：服務反應速度變慢

不要直接把問題框成「資料庫需要最佳化」。先定義觀測指標，例如第 95 百分位延遲（p95）、負載與成本限制；候選原因可包括資料庫、網路、快取、部署設定與外部 API。第一輪檢查有沒有把關鍵層排除，再用追蹤、指標或受控測試區分原因。找到原因後才比較修正方案，最後確認在不同負載下仍有效。

## 5. 「最優解」必須先定義

沒有目標、限制、情境與風險偏好，就不能嚴謹地宣稱某方案是最優。

- **單一目標、模型與限制明確**：可能求得數學上的最優解，但仍須檢查模型是否符合現實。
- **多個互相衝突的目標**：通常需要呈現取捨或 Pareto 候選，不應用未說明的權重硬造單一排名。
- **結果受未知情境影響**：應檢查預期效益、最壞情境、後悔值或穩健性；方法需依機率資訊與風險偏好選擇。
- **遊戲或競爭情境**：必須說明對手模型與評估分布；一種策略可能對平均對手有效，卻容易被特定反制。
- **證據不足**：結論應標註暫定、待驗證或無法判定，而不是用自信語氣代替證據。

## 6. 第一輪框架批判：最小檢查表

第一輪重點是審查框架，不深入填寫所有分支。

- 核心目標和成功標準是否正確？
- 哪些前提已被證實，哪些只是推測？
- 有沒有另一種本質不同、同樣合理的問題定義？
- 哪些重要因素、跨領域依賴或利害關係可能被排除？
- 哪個反例最可能推翻目前框架？
- 什麼新證據會迫使我們重開框架？
- 若暫時不選唯一框架，是否應並行保留兩個候選？

批判結果只做四種裁定：**暫時通過、修改框架、並行保留多框架、目前無法判定**。通過代表可以開始細化，不代表框架已被證明完整。

## 7. 後續討論應留下的最小紀錄

每次全面討論只需更新這幾項，避免建立重複長文：

- **目前核心／目標**
- **現行框架與版本**
- **候選方案及比較判準**
- **已確認／假設／未知**
- **最重要反例或反證**
- **目前裁定及理由**
- **尚存風險與重開條件**
- **下一個最有價值的驗證步驟**

判斷討論是否進步，不能只看文字或節點變多；要看未知是否減少、關鍵假設是否被驗證或推翻、候選範圍是否合理縮小，以及決策是否更有證據支持。
