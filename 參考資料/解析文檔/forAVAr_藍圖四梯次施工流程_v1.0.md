## 1. 觸發與總原則

凡執行核心／系統藍圖、把藍圖轉成跨功能施工批次，或對同一架構批次進行整體落實，必須套用本流程。單純讀取、一次性問答或不改變語意的純格式修正不必啟動完整四梯次。

四梯次以整批為放行單位，不是讓每項功能自行分梯次。開始前凍結目標、非目標、功能清單、依賴、責任、輸入／輸出、接受條件、權限／成本邊界與停止條件。任何一項功能未完成當前梯次要求，整批不得進入下一梯次。

## 2. 四梯次及放行條件

| 梯次 | 階段 | 工作 | 最小檢查 | 整批放行條件 |
|---|---|---|---|---|
| 第一 | PLANNING／設計完善 | 還原原始目標與現況；完成語意、責任、依賴、契約及接受條件；盤點既有能力，優先修正／擴充，避免重複新增。 | 來源／文件核對、差異與依賴對帳、必要桌上推演。 | 每項功能設計完整；關鍵未知／衝突已解決或明確阻塞；批次範圍與接受條件凍結。 |
| 第二 | REALIZATION／功能落實 | 將設計蒸餾為機械可判定的規格、介面、Schema、狀態／錯誤契約，再完成全批程式及必要接線。 | 靜態、語法／Schema 及少量局部功能案例；不重跑整批正式驗收。 | 全批功能均有可執行實作與必要接線；局部結果、未執行項均有明確狀態。 |
| 第三 | CLOSURE／完整性與閉環模擬 | 核對全批呼叫鏈、交接、狀態／錯誤傳遞、權限與復原；在隔離環境以合成資料或替身依賴模擬閉環。 | 少量、具區辨力的離線／沙箱案例；要求真實輸入、預期結果、實際結果及執行證據。 | 全批必要路徑閉合、模擬通過；正式測試名冊、接受條件及受測範圍凍結。 |
| 第四 | FINAL_TEST／正式實際運行驗收 | 集中執行正式回歸、整合／端到端及必要真實 Runtime 測試，由獨立驗收者核對證據。 | 正式整批運行只在此梯次集中執行。 | 實際結果符合凍結條件，版本／範圍／測試名冊一致且獨立驗收完成，才可結案。 |

**證據不可越級：** 文字推演不等於程式模擬；局部案例不等於整批閉環；離線模擬不等於正式真實運行；程式碼存在或檔案成功寫入不等於功能通過。

## 3. 第一梯次的設計完備條件

1. 明列原始目標、非目標、核心不變量及當前實況，不得讓優化造成原始核心偏移。
2. 盤點直接相關的既有能力、功能責任、SOP、契約與資料結構。預設修正／擴充；只有證據顯示現有分類或契約無法承載時，才提出新增，並說明重疊、依賴、驗收、回退及退場。
3. 每個重要概念均有定義；每項需求對應功能／責任、輸入、輸出、狀態、失敗語義、權限及可驗收結果。存在未解循環矛盾、責任懸空或契約缺口時不得放行。
4. 凍結批次 ID、完整功能清單、依賴、責任、接受條件、權限／成本限制、停止條件及正式驗收範圍。
5. 原核心藍圖既有 Phase 0–7 保留為第一梯次內的設計子流程，不另成平行施工生命週期：Phase 0 基線；Phase 1 核心／模式比較；Phase 2 追溯；Phase 3 契約；Phase 4 桌上推演；Phase 5 候選方案比較；Phase 6 縮減；Phase 7 決策。推演不算真實運行驗收，無實測資料不得宣稱實證改善。

## 4. 第二梯次的功能落實條件

1. 只施工已凍結範圍；將語意規格轉為機械式輸入／輸出、型別、Schema、狀態轉移、錯誤處理、呼叫契約、權限及復原規則。
2. 同批完成程式、介面、必要契約與直接依賴；不得讓先完成的子功能提前進入第三或第四梯次。
3. 只做下一道 Gate 所需的最小靜態檢查與局部案例，不因每個小修補重跑完整正式驗收。
4. 局部案例記錄輸入、預期、實際結果與 PASS／FAIL／BLOCKED／NOT_EXECUTED。純文字推理只可標為設計推演。
5. 全批有任一功能未完成可執行實作或必要接線，整批不得進第三梯次。

## 5. 第三梯次的完整性與模擬條件

1. 按凍結清單對帳實作、依賴、呼叫鏈、交接、狀態／錯誤傳遞、權限與必要復原路徑。
2. 在隔離本地／沙箱環境使用合成資料或替身依賴，執行少量正常路徑及最有影響力的失敗／邊界案例；不可連接正式資料或產生未授權外部副作用。
3. 模擬須有實際執行輸出；程式碼存在、文件保存或自述旗標不能代表通過。沒有執行環境標記 NOT_EXECUTED，不得宣稱閉環驗收完成。
4. 全批閉環及必要模擬通過後，才凍結正式測試名冊、測試版本、接受條件與範圍指紋。範圍或契約變動時，使受影響的下游證據失效。
5. 任一功能或必要路徑未閉合，整批不得進第四梯次。

## 6. 第四梯次的正式驗收條件

1. 只在第三梯次整批通過後，集中執行正式回歸、整合／端到端與必要真實 Runtime 驗收；不在每個功能施工期間提前啟動正式整批測試。
2. 由獨立驗收者核對實際輸出、退出狀態、受測版本／範圍、測試覆蓋及預先凍結的接受條件。禁止以推演、離線模擬、文件存在或模型自述取代正式證據。
3. 若失敗，停止結案；一次讀取完整報告，彙整同輪可確認的失敗並按共同根因分組，再批次修復。不得為取得 PASS 而改寫接受條件，也不得無限原樣重跑。
4. 程式錯誤回到第二梯次；閉環／接線缺口回到第二或第三梯次；目標、語意、架構或批次範圍變更回到第一梯次，重新凍結並使受影響證據失效。重驗遵守既有 SOP 的重試上限。
5. 安全、權限、成本、資料完整性及不可逆副作用 Gate 始終即時生效，不因正式測試集中於第四梯次而延後。條件未知或不通過即停止受影響操作。
6. 只有實際結果符合凍結接受條件、證據綁定正確且獨立驗收完成，才能結案。

## 7. 全批鎖步、停損及效力界線

- 任一功能未完成目前梯次，整批不得放行。
- 需求、依賴或接受條件改變，回到第一梯次；不可沿用已失效的下游通過證據。
- 前三梯次僅做下一 Gate 所需的最小檢查；必要安全、權限、成本及資料完整性檢查不可省略。
- 結果不足標記 NOT_VERIFIED；未執行標記 NOT_EXECUTED；必要輸入、權限或證據不足標記 BLOCKED。不得把未知升格為 PASS。
- forAVAr 主庫保存唯一有效規則及必要索引；測試收據、實驗輸出與暫存材料依專案規範放入 forAVArb。
- 本文件是固定文件流程，不代表 Runtime 控制器已接線或會自動阻擋越級；跨任務效果及自動強制性仍待實際驗證。
