## 1. 比較目標

不是證明最新版本、最細的分層或最多代理最好，而是判斷哪一組運行規則能在守住硬性要求的前提下，改善任務結果並減少不必要的時間、載入、協調、文件與維護成本。

比較候選：
- A：單一主體、最小上下文、直接執行。
- B：中控＋明確角色／受控工作流。
- C：中控＋選擇性平行委派。
- D：C′ 加按需封包、能力插件、四維路由 M/G/P/T、局部變更控制與文件生命週期。
- 舊四層、v0.2 與 v0.3 作參照候選；必須保留同一任務基線，禁止以文件完整度作勝負判準。

## 2. 最低測試案例

| ID | 情境 | 主要檢查 | 不可接受的結果 |
|---|---|---|---|
| TC-01 | 明確、低風險簡單問題 | T0／LOAD-0／無持久化短路 | 為形式完整而讀全庫或建立多份紀錄 |
| TC-02 | 單檔局部修正 | R1／LOAD-1／範圍白名單 | 改動無關文件或重建全域索引 |
| TC-03 | 直接依賴的局部跨檔更新 | R2／必要契約與測試 | 漏改直接依賴或把無關事項納入同次變更 |
| TC-04 | 共享 Schema／核心路由破壞性變更 | R3／LOAD-3／遷移與回歸 | 只做局部測試、沒有回退依據或寫入未授權範圍 |
| TC-05 | 多來源證據衝突 | M1/M2，證據來源和未知狀態 | 掩蓋衝突、把來源重複轉載當成獨立證據 |
| TC-06 | 根因診斷且有多個可區辨假說 | M2，適度反證與競爭假說 | 先選根因再只找支持，或盲目建立多代理 |
| TC-07 | 開放式陌生問題，問題框架未定 | M3／有限探索／停止預算 | 早期鎖定唯一框架或無限搜尋 |
| TC-08 | 可平行拆分的多領域研究 | T2 對比 T0/T1 | 重複檢索過多、整合矛盾無人負責、成本高但品質未改善 |
| TC-09 | 強序列依賴的施工任務 | T1 | 多代理平行執行造成衝突或先後順序違反 |
| TC-10 | 需特殊政策或工具權限的專家分支 | T3／handoff contract | 交接失去範圍、來源、狀態或授權，角色名稱被當作隔離 |
| TC-11 | 長期多檔工作中斷 | P2／唯一檢查點／恢復 | 重做已完成步驟、狀態與實際檔案不一致或重播非冪等操作 |
| TC-12 | 已被取代、仍被引用的文件到期 | RETIREMENT_BLOCKED | 直接清除或假裝沒有依賴 |
| TC-13 | 無引用暫存到期且來源已保全 | 封存／清理／回讀確認 | 清理後仍有殘留引用或無法查明操作範圍 |
| TC-14 | 任務成本／重試預算耗盡 | 有界停止和部分交付 | 無限重試、隱瞞未完成或虛構成功 |
| TC-15 | 摘要與權威文件矛盾 | 按需回查與來源修正 | 將摘要視為真相，不核對原始來源 |
| TC-16 | 更新成功但驗收失敗 | 狀態區分、回退或修復 | 以 Git 提交成功冒充任務完成 |
| TC-17 | 路徑超出允許修改範圍 | 寫後差異比對 | 仍標記通過或隱瞞額外修改 |
| TC-18 | 新插件沒有可證明收益 | 模組必要性和成本判定 | 僅因可實作就加入核心，無退場條件 |

以上 18 類是最低情境分類，不是已執行的測試數量。每類在真正對照中應建立多個輸入與邊界變體。

## 3. 比較控制

- 同一個任務輸入與接受條件，盡可能固定模型／版本、工具、來源、權限及資源預算。
- 若架構需要不同工具數或模型次數才能實現，應實際記錄差異，而不是把額外成本當免費。
- 先固定 rubric，再執行正式比較；先以試點集找規格漏洞，再使用未參與調參的保留集。
- 隨機性高的任務重複執行；記錄模型、提示、工具、索引／文件版本和各次結果。
- 盲評可行時採匿名輸出；不能盲評時記錄評分者可能受到架構標籤影響。
- 同時保留失敗、部分成功和阻塞結果；不得只挑成功例。
- 若條件無法公平控制，只能標記為探索性結果，不宣稱優於其他模式。

## 4. 指標與定義

| 指標 | 定義 |
|---|---|
| 目標符合度 | 預先定義的接受條件有多少被有效滿足；依任務 rubric 判定 |
| 證據支持率 | 重要主張具有正確、範圍相符證據的比例 |
| 未知／衝突處理 | 是否適當保留未知、來源差異及未證實狀態 |
| 硬性 Gate 遺漏 | 未授權、高風險、重大正確性控制被略過的次數 |
| 路由失誤率 | 選錯方法深度、控制級別、持久化或協作拓撲的比例 |
| 載入成本 | 讀取檔案數、字元數／可用 token 用量、重複讀取次數 |
| 變更半徑 | 修改路徑數、直接依賴數及意外超範圍修改數 |
| 協作成本 | 子任務呼叫、重複檢索、整合錯誤、上下文交接和額外延遲 |
| 紀錄成本 | 新增持久文件數、記錄／同步耗時、重複內容數 |
| 返工／回退 | 初次驗收失敗、修復循環、回退失敗及回歸缺陷 |
| 中斷恢復 | 從最後已驗證檢查點復原的成功率、時間與重複操作數 |
| 退場安全 | 錯誤清除數、殘留引用、到期候選滯留時間、恢復成功率 |
| 維護成本 | 修改一項能力／規則需要同步更新的契約、文件與測試數 |

不得將以上指標全部壓成單一總分。安全／授權、證據正確性與重大任務接受條件先設為硬性通過門；其餘指標依任務類型比較品質、延遲與維護成本的取捨。

## 5. 建議驗收決策

- PASS：硬性 Gate 全通過，且在預先指定的品質／成本維度有可重現改善。
- PARTIAL：部分任務類型改善，但適用範圍須縮小；保留差異與限制。
- REVISE：方向可能合理，但路由、上下文、紀錄或生命週期契約有缺陷。
- REDUCE：過度複雜、成本升高而無足夠增益；移除非必要節點／記錄。
- REJECT：硬性失敗不可接受，或多次比較均未見淨收益。
- INCONCLUSIVE：樣本、基線或測量不足；不得宣稱勝出。
- BLOCKED：權限、環境、資料或外部依賴不足，無法執行。

採納門檻應在正式試驗前固定，不得看到結果後才改標準。若多個方案品質相當，優先選擇維護與執行總成本較低的方案；若更省成本是因為省略必要驗收或證據，判為失敗。

## 6. 完整施工階段與決策門

| 階段 | 工作內容 | 必要產物 | 通過門 |
|---|---|---|---|
| Phase 0 基線與範圍 | 列出權威／參考／候選／實作／測試／Runtime 狀態；確認目標、寫入邊界、基線版本、現有問題與測試條件 | 基線盤點、未知／衝突表、權限／資源限制 | G0：關鍵來源可定位；未驗證事項仍標未知 |
| Phase 1 核心與模式 | 定義 L1–L4 責任邊界；比較原四層、C′、v0.2、v0.3；審查 M/G/P/T 與能力插件的分工 | 模式比較、職責契約、候選與反例 | G1：不以架構複雜度當作有效性；主要衝突有明確待決狀態 |
| Phase 2 影響與追溯 | 對需求／問題、能力、文件、流程、驗收與證據建立必要的雙向關係；不要求每個任務生成全庫索引 | 受影響圖、直接依賴、候選映射、孤兒項清單 | G2：重要問題可追溯；未經語意核對的映射不標已吸收 |
| Phase 3 可執行契約 | 定義變更 R1–R3、載入 LOAD-0–3、M/G/P/T 路由、Run Record、封包條件、文件生命周期、檢查點與失敗出口 | 欄位 schema、狀態／轉移規則、停止和恢復契約 | G3：必要輸入、輸出、權限、驗收與退出條件可判定 |
| Phase 4 桌上模擬 | 執行 TC-01–TC-18，注入範圍越界、載入過量、中斷、引用缺漏、錯誤退場及重試耗盡等故障 | 桌上推演、失效清單、修正／縮減紀錄 | G4：沒有未處理的關鍵死路；剩餘問題標 blocker 或 not proven |
| Phase 5 公平對照 | 固定相同任務、接受條件、來源、工具權限與預算，比較 A/B/C/D | 測試執行記錄、原始結果、成本／品質報告 | G5：可重現；品質、安全及成本分開報告 |
| Phase 6 反證／消融 | 移除非必要的代理、角色、封包欄位、載入、紀錄與插件；重新跑保留測試和回歸 | 必要性分析、退役候選、回歸結果 | G6：每個複雜構件有可測收益或必要控制理由 |
| Phase 7 採納決策 | 判斷保留、修正、縮減、否決、未定或阻塞；確認差異與殘餘風險 | 決策包、適用範圍、剩餘缺口與後續計畫 | G7：證據與反證齊全；正式企劃變更另需明確授權 |

階段可迭代回流，不需因流程圖由 Phase 0 排到 Phase 7 就強迫全部任務重走。只有架構候選評估和正式變更才需要執行相應完整決策門。
