## 1. 原則

文件既不能無限累積，也不能只按檔名、年齡或大小任意刪除。每個持久文件物件都要有明確用途、權威狀態、依賴、保留條件、審查時間與恢復路徑；不再需要時要能走到明確結束狀態。

生命週期設計必須同時滿足：
- 可定位：知道文件／產物在哪、由誰引用、屬於哪個主題。
- 可判斷：知道是否現行、被取代、仍被依賴、待審查或可退場。
- 可恢復：中斷、誤刪或改版失敗時，可回到已知有效版本。
- 有終點：候選與暫存資料不會永久停留在「稍後處理」。
- 可控清除：封存與永久清除是不同階段；高風險刪除要有授權。
- 可驗證：狀態轉移成功需實際讀回，不依賴自我聲明。

## 2. 文件／產物生命週期

| 狀態 | 含義 | 可進入條件 | 禁止事項 |
|---|---|---|---|
| DRAFT | 正在形成，非現行權威 | 新建或從任務生成 | 不得被引用為已核准規則 |
| ACTIVE／CURRENT | 現行且有明確唯一責任 | 達成規格要求與適用驗收 | 同一邏輯物件不得有多個互相競爭的 CURRENT |
| REVIEW_DUE | 到達審查時間或觸發條件 | 到達 review_at，或其依賴／來源發生重要變化 | 不可自動判為可刪除 |
| CLOSED | 任務或研究目的已結束 | 完成既定工作、記錄結論與未解事項 | 不代表文件可立即刪除 |
| SUPERSEDED | 已被新內容取代，不再是現行入口 | 新版通過驗收且替代關係可查 | 不可在引用尚未遷移時物理刪除 |
| RETIREMENT_BLOCKED | 仍有依賴、證據或保留需求 | 退場檢查發現阻塞 | 必須記錄原因、阻塞項與下一次檢查條件 |
| ARCHIVE_CANDIDATE | 已符合候選封存條件，等待最終檢查 | 無現行依賴，必要來源已保全 | 不得當作一般現行內容引用 |
| ARCHIVED／BACKUP_ONLY | 已封存，可依來源 ID／版本恢復 | 完成引用轉移、內容指紋與恢復驗收 | 不作一般啟動載入入口 |
| PURGE_ELIGIBLE | 可進一步評估永久清除 | 已滿足保留期、無依賴、來源保全和授權要求 | 不能只因到期或體積大就刪除 |
| PURGED | 已在明確範圍永久清除 | 取得授權並執行清除、驗證範圍、記錄事件 | 不得聲稱仍可從被清除的唯一來源恢復 |

來源事件與原始證據通常應採較強保留規則，不能與可重建的暫存輸出使用同一個清除週期。

## 3. 審查日期、保留期限與終點

每個需要持久化管理的物件，至少應有下列欄位：
- object_id／DOC_ID／SOURCE_ID。
- object_type：MASTER、BRANCH、SOURCE、BACKUP、RUN_RECORD、PACKET、ARTIFACT、TEMP 等。
- lifecycle_state、owner／責任來源、created_at、updated_at。
- review_at：下一次審查時間。
- retention_until 或 retention_rule：最早可考慮退場的時間／條件。
- dependencies／incoming_refs。
- canonical_replacement_ref、restore_ref、content_hash 或版本識別（可取得時）。
- purge_authorization、purge_scope、purge_event_ref（只有適用時）。

期限採差異化規則：
- 暫存輸出：預設任務關閉後進入短期保留期，到期檢查是否被引用／是否支援復現，再清除。
- 候選藍圖／研究提案：有 review_at；到期後必須裁定為繼續研究、更新候選、併入權威文件或封存，不可無限期不決。
- 執行紀錄／工作封包：依交接、稽核、復現或恢復需求保留；任務關閉後仍可有必要保留期。
- 正式主軸／規範：不因年齡自動清除；需有替代版本、引用遷移、來源與授權審核。
- 原始來源、關鍵證據、歷史提交或法律／合規需保留的資料：由適用保留政策決定，不使用通用暫存 TTL。
- 備份：維持既定版本上限，但超出上限前需確認唯一資訊、引用、內容指紋和恢復路徑；輪替成功須回讀驗證。

具體天數尚待用實際儲存量、恢復頻率與法規／專案政策制定，不在缺少基線時捏造統一天數。所有有期限的候選必須有審查終點，即使無法自動清除，也須能在 review_at 時被發現並處理。

## 4. 退場前置檢查

只有全部符合才可以從 ARCHIVE_CANDIDATE 推進到 ARCHIVED；永久清除另需更嚴格 Gate：

1. 使用者／專案要求、法規、稽核與安全保留限制允許退場。
2. 查完所有已知 incoming references、能力依賴、封包引用、未完成工作、測試及故障復現依賴。
3. 若為現行主軸或分支，已指定通過驗收的替代文件；如果是原始來源，已確認保存了足以支持未來稽核的來源或可恢復原件。
4. 所有現行引用已更新到有效目標；未完成掃描的範圍明確標記 PARTIAL，不能宣稱可安全清除。
5. 已保存必要的版本、commit／blob ID、內容指紋、原路徑、大小、來源時間及恢復位置。
6. 已核對不再被必要驗收、重要結論、交接、回歸或尚未結束的任務所依賴。
7. 完成恢復測試或依物件類型驗證可取得替代來源。
8. 寫入退場事件紀錄，標示只是工作樹移除、封存，還是永久清除。
9. 永久清除必須有明確授權、明確清除範圍與清除後驗證。從工作樹刪除不代表 Git 歷史中的內容已永久消失。

若任何條件不成立，狀態應為 RETIREMENT_BLOCKED 並記錄 blocker，不可透過刪除引用或將引用標記為舊版來製造「沒有依賴」的假象。

## 5. 中斷恢復與唯一檢查點

短任務一般不建立正式檢查點。符合以下任一條件時應啟用任務狀態檢查點：跨會話、多階段、多檔案變更、長時間執行、高影響操作、非同步工作、需要交接或可能無法安全重做。

單一權威檢查點至少包含：
- run_id／packet_id 與基線版本。
- 目標、接受條件、允許範圍和目前選用的路由。
- current_phase、last_verified_step、completed_steps、pending_steps。
- modified_paths、每個路徑的寫入／驗收狀態。
- 最近一次成功讀回的 commit／blob／版本指紋。
- evidence_refs、blockers、unknowns、失敗原因及剩餘風險。
- rollback_ref、不可重複執行的外部副作用及其實際狀態。
- checkpoint_time、next_action、closure／resume reason。

更新策略：
1. 執行前記錄安全重試所需的基線與操作識別。
2. 每完成一個具意義的里程碑，更新同一份狀態記錄，而不是新增另一份進度／路徑／狀態文件。
3. 寫入、移除、搬移、清理及外部副作用需記錄預備、執行、回讀驗收狀態。
4. 恢復時先讀最後一個已驗證檢查點，再核對 Repository／外部系統實際狀態；不可盲目重播未確認是否已執行的動作。
5. 若外部動作非冪等，先核對實際結果，再決定是否補做、補償或停止。
6. 發現檢查點和實際狀態不一致時，標記 RECOVERY_CONFLICT，暫停破壞性動作，重新建立一致基線。
7. 只有完整核對接受條件後才標記 DONE；未完成項目明確保留。

## 6. 退場與恢復事件最小紀錄

退場事件至少保存 object_id、退場前狀態、理由、替代來源、incoming refs 檢查結果、保留／清除範圍、授權依據、操作時間、執行結果、讀回驗收和恢復方法。

恢復事件至少保存來源版本、恢復理由、恢復後的新版本／新 commit、差異、引用核對、重新驗收結果。恢復的舊內容應建立新的 CURRENT，不能因取回舊版就略過目前狀態與依賴核對。

## 7. 退場自動化的安全邊界

可逐步自動化：
- 到期提醒和候選清單生成。
- incoming references 與已知依賴掃描。
- 版本數量、字元數、缺少 restore_ref 等結構檢查。
- 無引用暫存的候選判定。
- 封存後的存在性、指紋及恢復位置檢查。

不可直接自動化或不應只依單一條件執行：
- 正式企劃、權威規範、重要來源及具有安全／合規意義的永久清除。
- 仍有未掃描引用、未完成驗收、未決衝突或無法還原的資料。
- 僅因文件過期、體積過大或名稱帶有「舊版」就刪除。
- 在沒有明確狀態核對時重播外部副作用或覆蓋最新版本。

自動化若未經實際測試，只可標記 PROPOSED／NOT_VERIFIED。

## 8. 必測情境與指標

| 測試 | 預期行為 |
|---|---|
| 到期但仍被引用 | RETIREMENT_BLOCKED；指出依賴與下次處理條件 |
| 新版未驗收 | 舊版保持可恢復，不得退場 |
| 工作樹移除但 Git 歷史仍有檔案 | 明確標示 REMOVED_FROM_WORKTREE，不宣稱永久清除 |
| 更新中途斷線 | 由最後已驗證檢查點恢復，核對實際寫入狀態 |
| 不可重複外部操作狀態不明 | 不盲目重試；先查證或阻塞 |
| 暫存到期且無引用 | 進入候選、完成檢查後清除並驗證 |
| 摘要或索引缺漏 | 退場被阻擋，修復引用或標記覆蓋範圍不足 |
| 唯一來源可能消失 | 先完成來源保全與恢復驗收 |

指標包括：到期未處理數、被錯誤清除的物件數、退場阻塞原因、恢復成功率、平均恢復時間、未檢查引用比例、過期候選滯留時間、可恢復來源缺失率與清理後殘留引用數。基線取得之前不虛構 KPI 門檻。
