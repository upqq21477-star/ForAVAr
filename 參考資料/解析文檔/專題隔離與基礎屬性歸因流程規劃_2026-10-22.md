# 專題隔離與基礎屬性歸因流程規劃

- 文件 ID：FORAVAR-PLAN-PROJECT-ISOLATION-ATTRIBUTION-001
- 日期：2026-10-22
- 版本：v0.1
- 類型：PLAN_CANDIDATE
- 狀態：RECORDED / NOT_ADOPTED / NOT_IMPLEMENTED
- 唯一責任：規劃新專題先隔離處理、結案後抽取可遷移的基礎屬性，再評估是否適合納入 forAVAr；不取代正式藍圖、SOP、問題清單或全域索引。

## 摘要

採取「**專題隔離 → 專題內完成 → 結案蒸餾 → 基礎屬性候選 → 既有能力對帳 → 納入決策**」的分階段方式。題目不同，允許使用不同資料結構和分析方法，不在專題開始時就套用同一套結論或直接修改系統。個案資料、推論、方法試驗及局部決策留在專題資料夾；只有經明確抽象、證據回鏈、適用邊界檢查和既有能力比對的內容，才可提出系統採納候選。

本文件是規劃候選，不是已生效的自動化能力，也未修改正式企劃或 SOP。

## 1. 現有能力與唯一責任

不得因新分類而另建一套問題引擎、學習資料庫或全域文件索引。新流程只作跨職責的分階段編排，按唯一責任寫回既有位置：

| 現有責任 | 本方案如何重用 |
|---|---|
| 《版本治理與分流規範》 | 管理 SOURCE、MASTER、BRANCH、版本、路徑及回鏈；專題資料夾不取代全域索引 |
| 《去重與蒸餾規範》 | 區分原始來源、解析證據、分析與蒸餾結果；保存差異、反例、限制與未知 |
| CF-004 | 將可持久化結論寫入唯一責任文件；先查既有文件，避免複製全文 |
| CF-008 | 同步來源、引用、變更事件與回鏈 |
| CF-009／SOP-META-001 | 在具備授權後管理流程採納、風險、驗收與退場；本文件本身不修改其正文 |
| CF-010／SOP-DOC-001 | 只有某個方法已成為可重複、可執行、可驗收的候選時才提出 SOP；不是每個案件都建 SOP |
| 能力覆蓋登錄與 P1／P2 映射 | 系統納入審查時用來檢查重用、擴充、融合或缺口；P1／P2 僅唯讀 |
| 問題清單與執行台帳 | 已知失效沿用既有 PR ID；執行偏差寫進既有事件／台帳，不另設平行問題庫 |

新增資料夾規則只管理專題自己的材料；全域文件的權威、狀態與事件仍由現有索引維護。

## 2. 新專題隔離規則

每個新研究題目或案件，在實質分析前先建立獨立資料夾與唯一專題 ID。專題初期只建立必要的開案契約、來源清冊及題目專屬分析分支，不預先填滿所有模板，也不把待結案的猜測寫進全域能力登錄。

建議位置與 ID：

`專題研究/PRJ-YYYYMMDD-短題目/`

若既有領域有固定且已引用的專題位置，保留既有位置，不為對齊新慣例而搬動或複製；只在需要時補上分類與回鏈。現有南大案件屬這類既有獨立工作資料夾，不搬移。

標準起始結構見[專題工作區與分類模板](../../專題研究/_模板/專題工作區資料夾與分類模板_v0.1.md)。每個資料夾的 README 只管理該專題，不是新的全域索引。

## 3. 文件物件分類

以下分類用來區分文件的證據責任，不是要求每個專題建立八份大文件；依階段和實際需要建立。

| 類型 | 內容與限制 | 唯一存放責任 |
|---|---|---|
| `RAW_SOURCE` | 原始對話、原始檔、外部來源快照；盡量保留原貌 | 專題來源清冊指向的原件／SOURCE |
| `EVIDENCE_ITEM` | 帶有來源位置、證據等級及主張範圍的證據摘錄 | 專題證據清冊／分析分支 |
| `PROJECT_ANALYSIS` | 本題事實整理、假說、比較、推論與未知 | 專題分析分支 |
| `METHOD_TRIAL` | 本題採用的方法、輸入、結果、成本、失效條件與限制 | 專題分析／試驗紀錄 |
| `LOCAL_DECISION` | 只對本題有效的決策、範圍界線或結論 | 專題結案摘要 |
| `PROCESS_EVENT` | 偏差、校正、失敗、變更、驗收及回歸事件 | 專題事件紀錄；若是系統既有問題，連回其 PR／台帳 |
| `ATTRIBUTE_CANDIDATE` | 從本題抽取、尚未證明可跨題通用的屬性 | 專題屬性抽取檔 |
| `SYSTEM_MAPPING` | 候選屬性對照 forAVAr 現有 CF、SOP、PR、能力節點及證據缺口 | 專題系統納入評估檔 |
| `PROMOTION_RECORD` | 經授權後，記錄實際採納、寫回位置、測試與回退 | 實際改動的權威文件及追溯事件 |

不得把來源、推論和結論寫成同一種「已知事實」。所有跨專題主張都須能反查到候選專題與原始證據。

## 4. 專題生命週期

`PROPOSED → OPEN_ISOLATED → ANALYSIS_IN_PROGRESS → CLOSED_LOCAL → ATTRIBUTE_REVIEW → SYSTEM_FIT_REVIEW → DECISION`

- **PROPOSED**：尚未建檔；確認題目是否為獨立工作。
- **OPEN_ISOLATED**：已有專題 ID、目標、範圍、來源權限和專題資料夾。
- **ANALYSIS_IN_PROGRESS**：只在本題範圍內研究；方法按題目特徵選擇。
- **CLOSED_LOCAL**：本題有可追溯結論、未知、限制及未完成事項；這不表示已可納入系統。
- **ATTRIBUTE_REVIEW**：將局部結果拆成專題事實、問題特徵、可重用方法候選、限制與反例。
- **SYSTEM_FIT_REVIEW**：逐項對照既有能力及唯一責任。
- **DECISION**：REUSE、ITERATE、MERGE、CONNECT、NEW_CANDIDATE、STAY_LOCAL、BLOCKED 或 WAIT_FOR_MORE_EVIDENCE。

不得跳過 CLOSED_LOCAL 直接把個案內容升格為系統規則。專題可以在本地先有暫定結論，但暫定結論不自動跨專題有效。

## 5. 結案後的基礎屬性抽取

抽取時不是濃縮整份案件，也不是把本題方法強迫套用所有題目。至少分清：

1. **題目專屬事實**：僅屬於本題，留在專題。
2. **問題形態屬性**：例如資料量、模糊度、來源衝突、風險、可逆性、跨文件程度、時效性、未知程度。
3. **方法適配屬性**：哪些輸入條件下某方法有用、不適用或成本過高。
4. **可遷移機制／控制候選**：可能跨題成立的流程不變量，例如來源追溯、方法與題目特徵匹配、修正後回歸驗收。
5. **邊界、反例與負面證據**：方法在哪些情況失效、會產生何種偏差、成本是多少。
6. **證據成熟度**：單一案例觀察、跨案例重複、受控測試、實際執行、Runtime 觀察須分開。

每項屬性候選至少記錄：屬性 ID、精簡主張、來源專題 ID、證據位置、抽象理由、適用／不適用條件、反例、對應既有能力、信心與未知、驗證狀態、成本／風險、建議處置。

**證據門檻：**
- 只來自一個專題：標 `SINGLE_CASE_CANDIDATE`，不作通用規則。
- 在兩個以上相互獨立專題出現相同機制：可標 `CROSS_CASE_PATTERN_CANDIDATE`，仍需檢查不同情境與反例。
- 要成為可採納方法候選：需有可重複步驟、可觀察驗收、失效／停止條件及代表性回歸案例。
- 要進入正式系統：仍須完成既有能力盤點、影響與回退方案、授權及必要驗收。案例數量不能代替批准，也不能代替測試。

## 6. 系統納入判斷

對每項屬性只選一個主要處置，詳細證據留在評估檔：

| 處置 | 適用條件 |
|---|---|
| `REUSE_EXISTING` | 現有能力已可承載；只需回鏈與使用，不新增能力 |
| `ITERATE_EXISTING` | 現有節點涵蓋部分需求；以證據修正其缺口與驗收 |
| `MERGE_DUPLICATE` | 發現相同唯一責任重複登記；先對帳，再依授權融合 |
| `CONNECT_EXISTING` | 能力已存在但前後流程或觸發條件沒有接通 |
| `NEW_CANDIDATE` | 盤點證明現有節點／契約無法承載，且有證據支持新責任 |
| `STAY_LOCAL` | 內容是專題事實、一次性方法或無跨題效用的發現 |
| `WAIT_FOR_MORE_EVIDENCE` | 依據不足、沒有反例測試或跨題性未確認 |
| `BLOCKED` | 權限、來源、衝突或驗收條件未解，無法安全判定 |

任何 NEW_CANDIDATE 必須先查能力登錄、P1／P2 映射、相關 CF／SOP／PR 與唯一責任矩陣，並說明為什麼重用／疊代／融合／接線都不足。不能以「名稱不同」當成新功能理由。

## 7. 防污染與停止條件

- 不把完整案件摘要貼入全域 README、能力登錄或 SOP。
- 不因一個案例建立新 PR、學習台帳或屬性資料庫；沿用現有權威登錄。
- 同一內容只在唯一責任位置保存；其他檔案用連結與最小必要摘要。
- 專題中出現的錯誤先判斷是題目偶發、方法失配、既有控制未觸發，還是可跨題的系統問題。
- 若兩輪分析沒有新增獨立證據、沒有改變判斷或下一步，停止重複分析並記錄未知／阻塞。
- 原始來源、反例、衝突和負面證據不能為了摘要簡潔而刪除。
- 系統採納是另一道決策閘門；文件建立成功不代表能力已實作、接線、測試或 Runtime 通過。

## 8. 本次案件的既有位置

目前南大案件已有獨立資料夾及第 49／50 號紀錄。本次在該資料夾增補第 51 號分類／屬性紀錄，只作範例性歸位，不搬移、不複製歷史檔案，也不把案件內容直接併入系統。第 50 號保留為早期提案來源；較新的系統職責規劃與本文件分別承擔各自責任，不形成兩份同權威主軸。

## 9. 驗收與未決事項

本規劃可視為文件層建立完成的條件：專題有獨立位置及 ID；來源、分析、決策、屬性候選和系統評估分類分明；索引可定位；每個抽象候選能回鏈來源；本地結論不會未經判斷直接進系統。

仍未完成的工作：未來新專題的開案試行、跨專題屬性比較、既有能力對帳的代表案例測試、規則觸發一致性與 Runtime 驗收。完成前狀態維持 `PLAN_CANDIDATE / NOT_IMPLEMENTED`。
