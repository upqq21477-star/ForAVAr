## 1. 正式裁決與實驗結果的使用範圍

依本次明確升版授權及使用者對實驗階段的確認，先前架構蒸餾、候選比較與實驗性驗證所支持的架構選型，正式納入 v0.7 規劃基線。本版不再將整體架構選型保留為待批准候選。

採納的主方向是：保留既有四層認知核心，以 M/G/P/T 四維控制運行，讓最小必要思考責任常駐，依條件啟動完整證據帳、獨立驗證、依賴追蹤、工作封包、多代理與高保證流程，並重用現有能力登錄、SOP、StateBundle、文件生命週期、Runtime 原型及驗收矩陣。

實驗設計結論的採用，與程式／Runtime 的工程驗收是兩種不同成熟度。現有文件所記錄的 Python contract tests、真實 adapter wiring、授權拒絕與 timeout／unknown side-effect 故障注入，以及尚未附執行收據的跨任務評測，仍須按計畫實作與驗收；不會因本次藍圖升版而被標記為已執行。

## 2. 唯一核心與架構不變量

唯一認知骨架固定為：

`Core → A1–A6 → N01–N18 → F0–F7`

思考仍是唯一核心。A1–A6 六條主軸、N01–N18 十八個骨架節點及 F0–F7 條件式框架保留原有 ID 與唯一責任；五主軸／九責任只作壓縮映射，不取代或複製權威骨架。

核心不變量：目的忠實、框架可修正、知識狀態誠實、方法適配、檢驗有區辨力、結論校準、修正傳播、執行與品質分離、權限獨立、成本有界、終態誠實，以及架構可被否決或簡化。可觀察定義見思考核心分支。

## 3. 自適應運行模式

M/G/P/T 維持四個正交維度：M 為方法／分析深度，G 為治理／安全控制，P 為持久化需求，T 為協作拓撲。不新增第五通用軸；任務類型只作 profile/tag，安全與授權硬門由 G／policy gate 控制。

快速、標準、高保證三種 profile 是執行深度提示，不取代 M/G/P/T，也不要求每個任務跑完整流程。以任務的歧義、依賴、證據衝突、風險、可逆性和資源預算決定升降級；必要條件不足時明確標記 BLOCKED／NOT_VERIFIED，不以反覆檢查次數或模型信心冒充證據。

SOP-META-001 任務流程、F0–F7 認知操作及四梯次施工流程具有不同唯一責任，不合併成平行引擎。

## 4. 支援責任域

| 責任域 | 唯一責任來源／邊界 |
|---|---|
| 認知主體 | Core／A1–A6／N01–N18／F0–F7 |
| 任務流程與施工 | SOP-META-001；四梯次 v1.1 |
| 運行路由／協作 | 既有 M/G/P/T 藍圖 |
| 能力與問題登錄 | 既有 175 項 manifest、19 個分支 JSON、PR 問題清單 |
| 工具／插件與權限 | adapter 契約；實際授權必須在 Runtime／工具邊界執行 |
| 執行狀態、證據狀態、長期記憶 | 三者分離，以 ID 與收據建立必要連結 |
| 持久化／工作封包 | 沿用 StateBundle 契約及文件生命週期規格；StateBundle 不自動取代權威 Current |
| 評測／回歸 | TC-01–TC-33、P01–P12 映射素材及相關 contract subcases；不得建立第二套分母 |

角色數、代理數、插件數或文件數不是品質指標。新增、替換或退役功能，必須先核對現有能力及唯一責任，定義契約、權限、錯誤出口、驗收及退場條件。

## 5. 工程施工及成熟度狀態

架構規劃基線已升版。工程實作與行為驗收維持逐項成熟度管理：
- Python vertical slice 現況仍為 `ADAPTER_SEAM_NOT_INTEGRATED`，不視為完整 Runtime。
- Runtime／工具權限、StateBundle 持久化、Run Record、checkpoint、timeout、恢復與真實 adapter wiring 均不得僅靠規格文件標記完成。
- P1／P2 78 項正式 mapping／decision 仍按原權威狀態管理。
- 54 項 PR 的正式 control→test→evidence→regression/reoccurrence 尚須按權責完成；研究交叉表不自動關閉問題。
- Core／View／SOP／CF 的來源狀態及待決項不因藍圖升版自動改變。

## 6. 四梯次放行規則

1. **PLANNING：** 凍結變更範圍、唯一責任、輸入／輸出、授權、接受條件、依賴、風險、測試與回復方式。
2. **REALIZATION：** 只落實已規劃並獲授權的增量；先做契約／單元測試，再接必要 adapter，保留真實收據。
3. **CLOSURE：** 檢查跨文件依賴、引用、狀態、權限、錯誤出口、中斷恢復、局部失敗與回歸。
4. **FINAL_TEST：** 凍結版本後集中正式驗收，依事前定義的接受條件與實際證據判定。

全批鎖步；需求、架構、依賴或接受條件變動回 PLANNING，舊證據依影響範圍失效。安全、權限、成本和資料完整性 Gate 全程生效。提交成功不等於驗收成功；未執行不得標 PASS。
