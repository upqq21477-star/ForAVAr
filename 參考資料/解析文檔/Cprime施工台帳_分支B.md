## 4. Gate 退出證據規範

所有 Gate 的證據至少記錄：

- gate_id、測試 ID、測試版本；
- 執行時間、程式／模型／工具與設定版本；
- 測試輸入與基準版本；
- 預期結果、實際結果及差異；
- PASS／FAIL／BLOCKED／PARTIAL_PASS 判定；
- 可查產物、日誌、外部讀回或測試輸出；
- 執行者與驗收責任；
- 尚未測試的邊界與限制；
- 失敗後修正以及回歸重跑結果。

如果只有規格文本而沒有執行紀錄，最高只可標記 DRAFTED；如果程式存在但未完成適用測試，標記 IMPLEMENTED_UNVERIFIED；只有在指定範圍有充分證據才標記 VERIFIED。

## 7. 風險登錄維護規則

每個重大風險要有：

- risk_id 與對應問題 ID；
- 失效條件／可能原因；
- 影響、可逆性、暴露面與不確定性；
- 預防控制與偵測控制；
- 測試案例、接受條件及證據位置；
- 責任角色、目前狀態與重新檢查觸發條件；
- 測試失敗後的停止、修正、回復與溝通要求。

風險狀態不能只因文字處理方案已寫入就下降。只有控制已在指定範圍實際驗證，才能更新驗收狀態；問題本身若屬持續風險，仍需保留剩餘風險紀錄。

## 8. 變更與文件一致性清單

每次變更主企劃、契約、能力、狀態機或驗收方式時，按順序核對：

- [ ] 已讀取目標文件的最新版本與基準。
- [ ] 已界定變更範圍、非目標和授權。
- [ ] 已檢查相依文件與使用者可見的狀態。
- [ ] 已評估風險與失敗後果。
- [ ] 已更新需要改變的權威來源，而不是複製到所有文件。
- [ ] 已更新施工台帳和決策台帳。
- [ ] 已更新 README 的導航與文件數量（若適用）。
- [ ] 已更新唯一職責矩陣（若新增或改變文件責任）。
- [ ] 已讀回每個被改檔案。
- [ ] 已驗證相對連結、Schema／格式和檔案路徑。
- [ ] 已執行受影響的契約／回歸測試。
- [ ] 已記錄 PASS、FAIL、BLOCKED 或 PARTIAL_PASS 的實際證據。
- [ ] 已記錄未驗收部分與下一步；沒有把提案寫成實作成果。

## 10. 固定交接格式

每輪工作結束時，至少更新下列欄位：

~~~yaml
handoff_id: stable-id
updated_at: timestamp
master_plan_version: v0.1
ledger_version: v0.1
current_phase: ""
what_changed: []
files_written_or_modified: []
tests_run: []
tests_passed: []
tests_failed: []
unverified_claims: []
known_unknowns: []
blockers: []
authorization_scope_used: ""
next_action: ""
do_not_assume: []
~~~

填寫規則：

- 只記錄實際發生的事情。
- 未執行測試寫 NOT_RUN，不可推斷為 PASS。
- 無法確認狀態寫 UNKNOWN，不補猜測。
- 下一步寫出單一、可執行的第一個動作與所需輸入。
- 若基準版本已變，接手者先重新讀取權威來源再繼續施工。
- 對企劃的建議修改不代表授權改動其他權威文件。
