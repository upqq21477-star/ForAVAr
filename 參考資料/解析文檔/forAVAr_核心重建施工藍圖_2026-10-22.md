## 1. 總結與優先裁定

本輪整合核心重建、運行模式、頻繁更新、範圍擴散、過量載入／紀錄、文件退場、中斷恢復，以及如何在不增加平行驗證層的前提下控制判斷品質與驗證成本。

**最高優先：思考核心是目的，架構、角色、封包、插件、工作流、文件和治理只是達成目的的手段。** 不因層級更多、映射更完整、檔案更多或使用多代理而判定品質較好。

目前最值得測試的候選運行方式是：薄中控、能力契約化、封包按需啟用、協作拓撲依任務選擇、硬性安全／授權控制在實際執行層生效。此為候選，不是已證明的最優解。

優先控制：小批次變更、按需載入／單一任務紀錄，以及有期限、檢查點和明確狀態的文件生命週期。

原藍圖超過長度上限，現收斂為主入口，詳細規格由分支承載；簡化不代表驗收完成。

本版新增的核心原則：**驗證應嵌入既有思考與 VERIFY 職責，而非新增一條每個任務都要完整執行的平行流程。** 驗證深度由問題類型、決策影響、可逆性、證據狀態及現有 M/G 路由共同決定；不另增加第五個全域路由軸。驗證停止規則仍是候選設計，必須先在驗收矩陣中測試，不能視為已啟用的 Runtime 控制。

## 2. 目標、非目標與核心邊界

### 2.1 主要目標
- 保留可反證的思考核心與四層呈現：核心 → 主軸 → 骨架 → 條件式框架。
- 原 A1–A6、N01–N18、F0–F7 暫作基線，是否修改由對照測試決定。
- 分開認知責任與橫向支援，包括治理、權限、證據、工具、狀態、文件、持久化與評測。
- 允許簡單任務短路；只有在任務特性、未知、風險、依賴、交接或驗收需要時，才增加深度和持久化。
- 降低更新擴散、載入與紀錄成本，維持恢復和驗收能力。
- 分開標記設計、文件、實作、測試與 Runtime 證據。
- 只驗證可能改變答案／行動的關鍵主張；以獨立證據、反例或可執行測試降低循環驗證。
- 設置有界停止與合法未解結局，降低無新增證據的重複檢查。

### 2.2 非目標
- 不因新版本比較新就直接取代舊版、v0.2 或 v0.3 候選。
- 不把所有能力服務化、所有操作封包化或所有角色代理化。
- 不要求所有任務讀全庫、留完整紀錄或走完整流程。
- 不為節點、插件、檔案或治理步驟的數量設定成績。
- 不把模擬、文件、Git 提交或索引更新當成 Runtime 成功證據。
- 不把 P1／P2 來源功能映射誤當成 forAVAr 已實作能力。

## 3. 目標運行模式

### 3.1 邏輯架構
1. 思考核心：目標忠實、知識誠實、模型可修正、方法適配、品質／成本分離、可區辨驗證、受控更新、誠實收口。
2. 薄中控：保有任務目標、接受條件、路由理由、資源預算、共通狀態、結果整合及最終交付責任；不包辦每個能力的內部算法。
3. 適應式路由：分別選方法深度 M0–M3、控制等級 G0–G3、持久化 P0–P2、協作拓撲 T0–T3。
4. 能力插件：只有當獨立契約、重用、替換、權限隔離或獨立驗收有收益時才拆分。
5. 工作封包：只供跨會話、長任務、多檔施工、高影響、交接、回復或稽核需要；短任務不需正式封包。
6. 證據與驗收：按事先定義的接受條件核對產物，允許完成、部分完成、未證實、阻塞、拒絕、停止或失敗的合法結局。

### 3.2 路由組合原則
- M：分析深度，不代表安全級別。
- G：操作控制，不得被速度、成本或角色描述抵銷。
- P：狀態保存需求，不代表任務複雜度或風險本身。
- T：協作拓撲；T0 單一主體、T1 受控序列、T2 中控下平行委派、T3 專家接手／事件協作。
- 若子任務不可獨立驗收、無可定義介面或平行收益不足，不啟用多代理。
- 若任務高度序列依賴，優先使用受控工作流；若子任務可分開完成且能整合，才測試平行委派。
- 高風險操作無論選何種 T，都必須通過執行層權限和範圍檢查。

## 4. 變更、載入、紀錄與生命週期政策

### 4.1 變更範圍
- R1 局部：目標文件／能力與必要直接依賴，局部驗收和讀回。
- R2 局部跨檔：只同步同一邏輯變更必需的契約、測試、直接引用與實作。
- R3 全域／破壞性：核心契約、共享 Schema、跨主軸、重大權限、遷移或退場；執行完整必要影響分析、授權、回歸和回退驗收。
- 超出預定路徑，必須能被寫後差異比對發現。發現不相關問題另開任務，不在原任務中順手擴張。
- 小批次不等於盲目只改一檔；實際依賴必須一起維持一致。

### 4.2 按需載入
- LOAD-0：短任務，不讀全庫、不建持久紀錄。
- LOAD-1：單檔工作，載入權威入口（如需）、目標檔與必要直接依賴。
- LOAD-2：多步／多檔／需交接工作，載入相關主軸、分支與必要測試。
- LOAD-3：核心／共享契約／全域遷移，才展開全域索引、版本治理和完整依賴盤點。
- 先用索引／ID 定位，按需讀原始來源；歷史備份與無關分支不得預設全部載入。
- 若摘要與權威來源矛盾，回查來源；不得用摘要便利性覆蓋原始證據。

### 4.3 紀錄精簡
- 短任務預設不建立新檔。
- 一般多步任務用一份精簡 Run Record 集中保存目標、範圍、狀態、已完成／待辦、修改路徑、驗收與下一步。
- 長期／高風險／跨模組工作才用正式封包及檢查點。
- 過程、路徑、狀態、修改、驗收是欄位，不因資訊不同就拆成多份文件。
- 大型原始輸出另存為可追溯產物；主記錄只保存摘要、指紋、路徑和必要證據定位。

### 4.4 文件生命週期與恢復
- 持久文件物件需有唯一 ID、責任、生命週期狀態、review_at、保留條件、依賴與恢復來源。
- 到期只觸發審查，不等於刪除；按類型續存、更新、封存、阻塞或清除。
- 清除前查引用、依賴、未完成驗收、來源保全、恢復路徑與授權。
- 工作樹移除、歷史保留、封存與永久清除分開標記。
- 長任務以單一權威檢查點恢復；核對實際狀態後，才重試或恢復，不盲目重播非冪等操作。
- 自動清理／自動輪替未經 Runtime 測試不得標記為啟用。

詳細契約與反例見[變更／載入分支](./forAVAr_局部變更與按需載入紀錄精簡藍圖_v0.1.md)及[文件生命週期分支](./forAVAr_文件生命週期中斷恢復與退場藍圖_v0.2.md)。

### 主／暫存 repository 資料准入（候選；未採納）

此設計沿用本節的生命週期、範圍控制、證據回讀與退場 Gate，不建立新的全域路由軸、不另設平行 SOP，也不代表自動化已啟用。

- 對預計短期處理並於結案退場的原始材料，先確認所有權／使用權、敏感度、保留要求、唯一原件策略及任務範圍；任一必要資訊不明即標記 `INGESTION_BLOCKED`，不可先上傳再補判斷。
- 同一 repository 內以資料夾分隔，只隔離路徑與責任，不能隔離 Git 歷史。獨立暫存 repository 是候選隔離手段，不代表私有 repository 可接收所有資料，也不保證刪除後永久清除。
- 僅將核准的通用化結論寫回 forAVAr；逐批對帳必須符合「預期項目數＝已處理＋明確阻塞／未處理」，未解差額為零才可完成對帳。主庫寫回失敗、回讀不一致或必要引用未完成時，暫存材料保持不刪，先做局部恢復。
- 刪除前檢查明確授權、完整 owner/repository 名稱、fork、既有引用／依賴、來源保全、恢復需求及寫回驗收；刪除後僅報告可觀察到的結果，不宣稱所有歷史物件或外部副本永久清除。
- 該候選須經至少兩個相互獨立的真實批次才能評估流程成熟度；目前未完成真實批次、成本量測或 Runtime 驗收，不得把候選升格為現行 SOP 或聲稱已採納。詳細條件見[分流提案](./forAVAr_主專案與暫存專案分流設計提案_2026-10-23.md)及[開案／結案模板](./暫存儲存庫開案卡與結案驗收清單_v0.1.md)。

### 4.5 判斷品質、適應式驗證與停止控制（設計候選）

**定位：** 這是思考核心在既有工作流程中的品質控制規則，不是新核心、獨立代理或第五個路由維度。任務方法深度沿用 M、操作控制沿用 G、狀態保存沿用 P、協作拓撲沿用 T；驗證步驟與成本由這些既有選擇和決策風險推導。

1. **先界定判斷對象。** 將重要主張分類為事實／來源、計算、因果解釋、預測或行動／價值取捨。明確指出哪些主張會改變最終答案、操作授權或決策；不把每一句話都當成同等驗證對象。
2. **按主張選方法。** 事實優先核對權威來源和日期；計算使用重算或可執行檢查；因果問題比較可行的替代假說與反證；預測保留概率、期限與事後校準；行動建議比較替代方案、風險、可逆性與價值取捨。對同一答案重述或同一模型內部反思，不視為獨立證據。
3. **按需加深。** 若低風險、可逆、明確且既有方法已能驗收，走最小必要路徑。若重要證據矛盾、關鍵假設未證、已知失敗模式觸發、決策難以逆轉或錯誤後果重大，才擴大到替代假說、原始來源、獨立評審或實際測試。
4. **保留硬性 Gate。** 授權、安全與預先指定的必要接受條件不能被時間／成本預算豁免，也不能由總分抵銷。若這些條件尚未通過，必須阻止受影響的行動或明確標記 BLOCKED／NOT_VERIFIED。
5. **設置停止條件。** 當必要驗收已通過、沒有未解的重大矛盾，且額外檢查不太可能改變合理決策或足以降低風險時，停止追加檢查。研究型任務應有預算；達預算而仍未解時，轉為明確的未解／阻塞／部分完成，不得藉重複分析假裝完整。
6. **阻止原地循環。** 若同一輸入、同一方法重複檢查未產生新證據，不得無理由原樣再跑。下一步必須改用有區辨力的方法、縮小未解問題、取得不同來源／測試，或停止並揭露未知。確有重複抽樣／穩定性測試需求時，須先說明其目的與獨立性。
7. **量測邊際收益。** 記錄每次額外驗證是否發現新的重大錯誤、改變結論／行動、降低實質風險，以及所增加的時間、工具調用與返工；不得只按檢查輪數、文字量或找到問題的數量獎勵流程。
8. **不預設固定數值門檻。** 驗證輪數、時間與成本閾值須由代表性基線和風險類型導出，初期標 UNKNOWN／待測。不得以一次桌上推演指定普遍適用的最優參數。

映射沿用 PR-008、PR-012、PR-023、PR-027、PR-039 與 PR-053；不另建同義 PR、不修改問題狀態，也不直接改寫現行 SOP。

## 5. 施工階段與決策門

| 階段 | 主要工作 | 決策門／輸出 |
|---|---|---|
| Phase 0 基線 | 核對權威、來源、PR 狀態、版本、測試與現況；凍結本次範圍 | G0：基線可追溯，未知不冒充完成 |
| Phase 1 核心與模式邊界 | 核對四層責任及舊版／v0.2／v0.3／C′ | G1：無重大矛盾，分歧保留候選 |
| Phase 2 追溯 | 問題／功能 → 責任 → 流程／能力 → 測試 → 證據雙向連結 | G2：問題無孤兒；無證據不標已解決 |
| Phase 3 契約 | 定義路由、能力、Run Record、封包、變更、生命週期狀態、關鍵主張驗證、停止與失敗出口 | G3：輸入／輸出、硬性 Gate、停止及回退可判定；不另造驗證路由軸 |
| Phase 4 桌上模擬 | 執行代表案例、驗證無收益重跑、停止過早／過晚、來源衝突、範圍外變更、中斷恢復及退場故障注入 | G4：無未處理的關鍵死路／無界驗證循環／越權；停止不掩蓋重大未知 |
| Phase 5 公平對照 | 固定任務、權限、工具與預算，比較 A/B/C/D，分別量測過度驗證、驗證不足與邊際資訊收益 | G5：結果可重現；硬性 Gate、品質、延遲與總成本分報 |
| Phase 6 反證與縮減 | 消融角色、封包欄位、文件步驟及插件 | G6：保留結構有依據，無效部分縮減 |
| Phase 7 決策包 | 依證據採納、修正、縮減、否決、未定或阻塞 | G7：支持／反證齊全；正式企劃另需授權 |

階段不得只因文件完成就自動通過；若發現更上層錯誤，可退回任何前置階段。正式企劃、其他權威規範和 P1／P2 不由此藍圖自動更新。

## 6. 驗收儀表板與採納規則

每個正式測試至少記錄：
- 目標成功度、接受條件通過率、證據支持正確性、未知／衝突處理。
- M/G/P/T 路由錯誤、權限／安全 Gate 遺漏、停止與重試是否正確。
- 載入檔案數、字元／可用 token 成本、重複讀取、工具呼叫、任務延遲。
- 變更路徑數、直接依賴數、意外擴散、驗收範圍、返工與回退。
- 新增持久文件數、記錄／索引同步成本、狀態重建與中斷恢復時間。
- 到期候選滯留、退場阻塞理由、錯誤清除、殘留引用與恢復成功率。
- 基線、工具／模型版本、測試集版本、輸出證據及評分限制。
- **過度驗證率：** 超出預定必要條件、且未增加新證據或決策價值的額外檢查比例。
- **驗證不足率：** 重要主張或必要硬性 Gate 未充分核對即提交／行動的比例。
- **邊際驗證收益：** 每次額外檢查新增的重大證據、缺陷發現或決策改變；另記檢查時間和成本。
- **停止錯誤率：** 必要檢查尚未通過即停止的比例，以及已足夠仍無必要地繼續驗證的比例。

決策規則：
- 安全／授權與重大正確性作獨立硬性 Gate，不允許平均分抵銷。
- 僅在必要 Gate 不退步、預先指定的品質或總成本指標有可重現改善時採納。
- 品質持平而複雜度增加，優先縮減；省下成本若來自略過必要證據或驗收，判失敗。
- 基線無法重現、測試不足或結論矛盾時標記 INCONCLUSIVE，不宣稱全域最優。
- 使用保留案例避免對反覆調整過的熟悉案例過度擬合。

完整情境與量測定義見[運行效率與架構候選驗收矩陣 v0.3](./forAVAr_運行效率與架構候選驗收矩陣_v0.3.md)。

## 7. 風險與停止條件

| 風險 | 控制 | 停止／退回條件 |
|---|---|---|
| 思考核心再次偏移 | 每項結構須指向認知收益或硬性控制需求 | 僅增加文件或流程而無收益時縮減 |
| 變更範圍擴散 | R1–R3、允許路徑、寫後 diff | 出現未授權路徑變更即停止並核對 |
| 上下文過載 | LOAD-0–3，按需載入 | 載入成本升高而品質無改善，重設載入規則 |
| 過度封包／記錄 | 任務分級、欄位合併、短任務不持久化 | 新文件無獨立用途與生命週期時不建立 |
| 無限重試 | 預算、進展判據、合法終態 | 沒有新資訊／新路徑時停止 |
| 錯誤退場 | 檢查引用、保留源、恢復驗證 | 不明確依賴或無法恢復時阻塞 |
| 形式驗收代替 Runtime | 分開設計／寫入／測試／Runtime 證據狀態 | 未實際觀察的能力不得標為已驗證 |
| 架構複雜度沒有回報 | 固定基線與消融測試 | 成本升高、品質無可重現改善則縮減或否決 |
| 驗證成為無限迴圈 | 決策關鍵主張、方法多樣性、邊際收益與資源預算 | 相同檢查無新證據時禁止原樣重跑；重大未知則 BLOCKED／NOT_VERIFIED，不把停止當成通過 |
| 過度／不足驗證互相掩蓋 | 同時量測過度驗證、驗證不足與硬性 Gate 遺漏 | 指標互相抵銷或只有主觀「看起來更謹慎」時，不採納候選規則 |
