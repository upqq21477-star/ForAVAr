## 摘要

本研究探討：當工作由 AI、程式、外部工具與人類共同完成時，如何依任務屬性選擇適當的執行方式，以最低總期望成本達成品質、完整性、可追溯性與安全要求。傳統效率方法主要處理標準化、等待、搬運、返工及流程再造；AI 原生系統還須管理推理／Token、上下文重載、工具呼叫、串行關鍵路徑、能力不匹配、錯誤生成與驗收成本。本研究結合範疇／系統性文獻回顧、設計科學研究及受控任務實驗，建立根源成本分類、任務路由架構與可重現的評估方法。前次 forAVAr 案例中，已知寫入操作由 5 次降至 4 次（−20%），寫入加末端讀回由 9 次降至 8 次（−11.1%）；這是操作數層級的單次重建／桌上模擬，不是實際耗時或跨任務效益的證據。研究將比較順序基線、固定式 AI 工作流程與自適應 AI 原生流程，並共同衡量資源成本、關鍵路徑時間、品質、漏失、返工、復原與維護成本。本文提出待檢驗研究架構，不宣稱已找到普遍最優解。

## 1. 問題與研究缺口

傳統流程改善常以人工工時、產能、等待或錯誤率衡量。AI 可低邊際人工成本執行大量分析、比較與檢查，卻會產生推理、上下文、工具、延遲及驗收成本。照搬舊流程自動化，可能只是更快重現浪費；只追求少步驟、少 Token 或少工具呼叫，也可能增加錯誤、漏失與復原成本。

**核心問題：在品質、安全與完整性約束下，如何把任務分派給成本／能力最匹配的運算機制，使端到端總成本最低？**

研究單位是有明確輸入、目標、交付物及驗收條件的任務，涵蓋結構化資料處理、跨來源研究、軟體維護、企業知識工作與跨檔案變更。缺口不在缺少單一最佳工具，而在尚需整合管理理論、流程工程、軟體交付和 AI Agent 研究，建立可操作的「任務屬性—執行路由—成本／品質結果」模型。

## 2. 歷史演進與外部證據

| 演進脈絡 | 降低的成本 | 對 AI 的可轉移原理 |
|---|---|---|
| 科學管理／時間研究 | 重複摸索、方法差異 | 標準化穩定工作，但先驗證拆解方式 |
| 流水線／批次處理 | 搬運、切換、低產能 | 合併獨立工作，注意瓶頸與排隊 |
| 精實生產／TPS | 過量生產、等待、缺陷擴散 | 只產生需要的結果；異常時停止 |
| 流程再造 | 冗餘審批、舊規則與交接 | 先刪除無價值工作，再談自動化 |
| ERP／流程探勘／RPA | 重複輸入、狀態不透明 | 集中資料和事件紀錄，以證據改善 |
| Agile／CI/CD | 大批次整合、晚發現錯誤 | 小批次、快速回饋、局部修復 |
| AI／Agent | 語意判斷、探索、內容生成 | 模型處理不確定性，程式處理確定性；按需使用 Agent |

初步外部證據：
- Toyota 官方將 TPS 定位為消除浪費、縮短交付時間並維持品質；Jidoka 強調異常時停止，避免持續產生缺陷。
- Hammer（1990）主張不能只用資訊科技加速過時流程，而應重新設計工作。
- 5,179 名客服人員的現場研究發現，生成式 AI 助理使每小時解決問題數平均提高約 14%，但不同經驗／技能組別收益不一。
- DORA 2025 對近 5,000 名技術工作者的研究將 AI 描述為放大器，可能放大組織既有優勢與缺陷；調查不等同隨機因果實驗。
- METR 2025 年對 16 位資深開源開發者的受控研究，發現當時 AI 工具令任務耗時增加約 19%。METR 於 2026 年指出後續測量有參與者與任務選擇偏差；自述生產力與實際耗時不是同一指標。
- Anthropic 建議從簡單、可組合的 Agent 模式開始；OpenAI 文件說明 Prompt Caching 可降低符合條件請求的重複處理成本。

## 3. 根源成本模型

| 屬性 | 可觀察成本／失效 | 候選控制 |
|---|---|---|
| 重複性／可確定性 | 重複推理、輸入 | 規則、程式、模板、快取 |
| 不確定性／語意歧義 | 探索與判斷成本 | 檢索、AI 推理、必要時 Agent |
| 依賴結構 | 串行等待、競爭寫入 | 依賴圖、平行獨立任務、衝突操作序列化 |
| 上下文重複 | Token、重新理解成本 | 按需檢索、結構化狀態、快取 |
| 資訊搬運／重複資料 | 同步工作、版本漂移 | 單一權威來源、衍生索引、資料契約 |
| 可觀測性 | 晚發現錯誤、人工稽核 | 確定性測試、來源標記、差異檢查 |
| 風險／可逆性 | 事故損失與復原成本 | 風險分級、確認閘門、備份／回滾 |
| 例外密度 | 固定流程失敗或 Agent 過度自主 | 標準路徑＋條件式升級 |
| 共享狀態／變更範圍 | 部分提交、不一致 | 變更集、原子提交、部分狀態、局部恢復 |
| 維護壽命 | 規則與索引修補 | 模組化、唯一責任、實測後才定版 |

在品質、授權、完整性及風險門檻通過的前提下，暫定目標函數為：
J = C_model + C_tools + αT_critical + βE(C_rework) + γE(L_failure) + δC_maintenance。
各項分別代表模型／Token、工具、串行關鍵路徑、期望返工、風險加權損失與長期維護；係數須依情境估計。品質與安全作硬約束，不應以低成本交換錯誤成果。

初步預測：少步驟不必然更有效率；平行化只適用於獨立節點；確定性檢查優先交給程式；高風險任務需要更完整驗收；Agent 自主性與效率的關係可能非單調。

## 4. 研究問題與假設

**RQ1：** 如何把任務轉為可觀察屬性，預測適合的執行模式？
**RQ2：** 自適應路由是否比固定順序流程或固定 AI 工作流降低品質約束下的總成本？
**RQ3：** 上下文復用、批次編排、平行化、確定性驗收及局部修復各自貢獻多少？
**RQ4：** 風險、歧義、依賴深度與模型能力匹配，如何影響驗證／自主性的收益？
**RQ5：** 結果能否跨結構化資料、研究、軟體工程和企業流程轉移？

待測假設：
- H1：在品質與風險門檻相同時，自適應路由比固定重型流程降低每個合格成果的總成本。
- H2：結構化工作用程式驗證可降低推理成本且不增加漏失率。
- H3：獨立節點足夠時，平行化縮短關鍵路徑，但不必然降低 Token 或費用。
- H4：高影響／低可逆性任務的額外驗收可能增加直接成本但降低風險加權損失。
- H5：Agent 自主性與系統複雜度對效率的作用非單調，且受任務屬性調節。

## 6. 研究方法與實驗設計

### 6.1 方法

1. **範疇／系統性文獻回顧：** 先界定術語。若宣稱系統性回顧，須記錄檢索式、日期、納排條件、去重、品質評讀與流程圖；PRISMA 2020 是報告規範，不代替實際方法。
2. **設計科學研究（DSRM）：** 依問題與動機、解決目標、設計／建置、示範、評估、溝通六階段發展路由架構和量測工具。
3. **受控基準任務及案例研究：** 用可重現任務比較工作流，並分析操作日誌與失敗案例。

### 6.2 候選對照組

A｜順序基線：記錄現行流程，不故意製造低效。
B｜固定式優化 Workflow：預先規劃、結構化變更集、批次編排、程式檢查、集中驗收。
C｜自適應 AI 原生路由：依確定性、歧義、依賴、風險、可驗證性及能力匹配，選擇程式、單次推理、檢索、平行任務或 Agent。

先導階段先驗證任務和日誌，正式樣本數依先導變異、最小實務差異及檢定力分析決定。條件順序隨機化或區塊化；任務、模型版本與設定固定或完整記錄，不預先虛構樣本量。

### 6.3 任務分層

A 結構化／低歧義；B 多來源／語意研究；C 跨檔案變更與交接；D 軟體除錯／測試；E 高風險／不可逆操作（優先用離線沙箱）。依重複性、歧義、依賴深度、上下文長度、可逆性、驗收自動化程度及能力匹配分層，不用單一平均值掩蓋差異。

## 7. 指標與統計分析

- **總資源：** 輸入／輸出／快取 Token、模型呼叫、工具/API 呼叫、費用、人類介入時間。
- **時間：** 端到端時間、活躍運算時間、串行關鍵路徑；區分等待與可併行工作。
- **品質：** 正確率、完整率、來源忠實度、必要資料漏失率、引用有效率、驗收通過率。
- **可靠性：** 重試、返工、失敗率、局部復原成功率、錯誤影響範圍。
- **長期成本：** 流程維護工時、規則漂移、索引修復、模型／工具切換成本。

主要比較「每個品質合格成果的總成本」與「品質門檻不下降下的時間／資源差異」，不只看速度。對配對任務報差值、效應量及信賴區間，依任務類別檢查異質性，必要時使用混合效應模型。先導後預先登記樣本與分析方案，保留負面結果。

## 8. 論文成型與前置工作

1. 定義研究邊界、研究單位、任務族、成功條件及排除項。
2. 建立研究協定：研究問題、資料庫／網站、搜尋式、日期、納排標準、去重、品質評讀與擷取欄位。
3. 分類文獻：理論、實證試驗、組織調查、官方技術指南、工具文件、案例；記錄樣本、任務、對照、指標、限制。
4. 建證據矩陣：每項主張連到來源，分開事實、推論、假說、未知和衝突。
5. 預定變項、基線、任務集、隨機化、品質門檻、失敗處理和資料保存。
6. 做先導研究，驗證工具及計時日誌、任務難度與評估一致性；先導結果不當正式結論。
7. 進行主實驗與反例分析，同時量測成功／失敗、驗證成本、漏失與復原。
8. 保存任務規格、版本、程式、統計碼、匿名化日誌與偏差紀錄，確保可重現。

建議論文章節：緒論；背景與文獻回顧；根源成本模型；研究方法與實驗設計；先導研究；主實驗結果；跨情境討論；效度威脅、限制與倫理；結論與貢獻；附錄含檢索策略、任務集、資料字典與統計方案。

## 10. 風險與限制

- 基線漂移：模型、工具、設定、上下文或任務難度不同時不可直接對比。
- 選擇偏差：任務自選可能偏向 AI 擅長工作；混合固定任務與真實樣本。
- 量測混淆：自述速度、完成時間、產出價值與品質須分開報告。
- 漏失／失真：將必要資料與獨有證據列入清單；不得以摘要取代對帳。
- 過度自動化：高影響、不可逆操作需獨立閘門，故障測試優先在沙箱。
- 選擇性報告：預先定義主要指標並保留負面結果。
- 停止條件：成功成果不明、基線不公平、核心量測缺失、資料／權限風險未控或無法安全復現時，停止正式比較並修正設計。
