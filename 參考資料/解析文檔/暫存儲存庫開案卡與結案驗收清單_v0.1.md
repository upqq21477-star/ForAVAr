## 1. 使用前提

這份模板只適用於「可上傳至 GitHub、範圍清楚、完成後預計退場」的短期批次。不因有私人 repository 就假設資料完全安全或可永久清除。

以下任何一項成立，不得先上傳再補判斷，先標記 `INGESTION_BLOCKED`：
- 資料所有者、使用權或保存要求不明。
- 含密碼、token、個人敏感資訊，或明確要求不可恢復的資料。
- 唯一原件是否需保留尚未決定。
- 任務沒有明確範圍、必交成果或結案條件。

若主要要求是確保資料不可恢復，GitHub 暫存 repository 不提供該保證；先選擇符合該要求的保存／處理途徑。

## 3. 資料結構原則

只建立實際會用到的項目：
- 原始來源：原件盡量不覆寫；記錄來源位置、版本與可讀範圍。
- 處理／分析：區分直接證據、推論、反證、衝突及未知。
- 候選蒸餾：只放待寫回主庫的通用方法、根因屬性、限制與證據等級。
- 驗收：記錄項目數對帳、主庫讀回及結案阻塞。

不得把 forAVAr 整庫複製進暫存 repository；不得將 P1／P2 的只讀參照內容複製成新副本；可由公開來源重取的材料優先留下來源連結與必要摘錄，不要為了「完整」大量複製原文。

## 4. 狀態必須拆開

**研究批次狀態**：`CREATED → INGESTING → ANALYZING → DISTILLING → MAIN_WRITE_PENDING → CLOSEOUT_REVIEW → CLOSED`。任何前置條件不明、來源不足、主庫寫回失敗或尚有依賴時，使用 `INGESTION_BLOCKED`／`CLOSEOUT_BLOCKED`，不可跳到 CLOSED。

**退場觀察狀態**：
- `NOT_REQUESTED`：尚未刪除。
- `DELETE_REQUESTED`：已送出刪除操作，尚未驗證。
- `REPOSITORY_UNAVAILABLE`：已確認 repository 目前無法按原連結取得。
- `HISTORY_PURGE_NOT_VERIFIED`：歷史物件、平台端保留、快取及外部副本沒有獨立清除證據。

刪除 repository 不得直接記為 `PURGED`；「目前連結無法讀取」也不是 GitHub 後端資料回收或所有副本消失的證明。

## 5. 刪除前結案閘門

- [ ] 預期項目數＝已處理項目＋明確標記的未處理／阻塞項目，差額為零。
- [ ] 必要成果與通用化結論已寫入 forAVAr 的指定權威位置。
- [ ] 主庫內容已讀回，內容、引用及必要索引無已知錯誤。
- [ ] 已比對現有 PR／CF／SOP／MASTER；不為同義功能新增平行文件。
- [ ] 原始唯一來源、反例、限制、未決事項有明確去向，不會只存在於待刪 repository。
- [ ] 所有未完成任務有保留位置或阻塞說明。
- [ ] 不必要的個案名稱、原路徑、全文或識別線索未複製進主庫。
- [ ] 已核對完整 owner/repository 名稱、可見性、fork／依賴及刪除授權。
- [ ] 已明確分開「主庫未保存原始資料」「repository 已刪除」與「永久清除未驗證」三個結論。

任何一項未通過，狀態為 `CLOSEOUT_BLOCKED`，不得刪除。

## 6. 失敗與恢復

- 主庫寫回失敗：暫存 repository 保持不刪；重新讀取主庫狀態，避免重複寫入。
- 數量或引用有差額：暫停結案，只檢查未對帳項目。
- 權限或刪除操作被阻擋：記錄回傳結果並停止；不使用其他寫入接口繞過安全／權限檢查。
- repository 已刪除但需恢復：依 GitHub 實際可用的復原能力處理；不得承諾任何刪除 repository 都能恢復。
- 發現敏感資料已提交：停止擴散；憑證立即撤銷／輪替，資料清除依官方流程另行處置。

## 7. 以 GitHub 網頁介面操作的最小路徑

這是候選人工流程，不依賴 GitHub Actions、付費服務或額外自動化；介面標籤可能隨 GitHub 版本變更。

1. **先判斷准入**：未通過第 1 節前提，不上傳。
2. **開案**：確認 repository 為 Private；新增根目錄 README.md，填寫 BATCH_ID、範圍、來源與結案條件。
3. **上傳**：只加入本批次必要的來源與分析材料；提交前檢查是否意外包含敏感資訊。GitHub 瀏覽器上傳單檔上限為 25 MiB；超限標記 BLOCKED，不擅自改用不允許的工具／服務。官方：[新增檔案／瀏覽器上傳](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。
4. **研究與蒸餾**：原始來源、推論、反證、未知分開；只把核准的通用化結果寫回 forAVAr。
5. **驗收**：重新開啟 forAVAr 寫入位置，讀回正文並檢查索引、回鏈及未完事項；不能只憑提交成功判定通過。
6. **刪除前停點**：所有勾選項通過才由使用者手動刪除；有依賴、數量差額或來源疑問即保持 BLOCKED。
7. **刪除與回查**：先核對完整 owner/repository 名稱、fork 與仍需保留的依賴，再由使用者在 Settings／General／Danger Zone 手動確認刪除。GitHub 說明刪除私人 repository 會刪除其 fork，因此必須先確認無需保留的 fork。事後可檢查原網址是否仍可存取，但不可宣稱後端物件／外部複本已永久清除。官方：[刪除 repository](https://docs.github.com/en/repositories/creating-and-managing-repositories/deleting-a-repository)。

GitHub 說明部分已刪除儲存庫可在 90 天內恢復，但條件並非對所有儲存庫一概相同；詳見[復原已刪除 repository](https://docs.github.com/en/repositories/creating-and-managing-repositories/restoring-a-deleted-repository)。不要把刪除視為不可恢復的安全清除。

## 8. 本模板驗收狀態

目前只完成文件設計，尚未以真實批次試行。先以一個低風險批次試行，記錄人工作業步數、資料對帳差額、主庫寫回讀回、引用漏失及結案返工；再以第二個獨立批次驗證。只有模擬而無實際試行時，狀態仍為候選，不提升成現行 SOP。
