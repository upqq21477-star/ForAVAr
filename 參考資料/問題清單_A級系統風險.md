## 3. A 級：高影響系統性風險

| ID／問題 | 發生原因／原理 | 目前處理方式 | 狀態 |
|---|---|---|---|
| **PR-014 變更波及面過大、依賴爆炸** | 隱性依賴、共用狀態或核心資料變更會影響大量下游元件。 | 明確依賴方向與模組責任；先分析直接依賴及共用契約，再依影響範圍做回歸；記錄實際變更半徑。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-015 接口過多、隱性耦合、Schema／語意漂移** | 每對功能自行整合會增加相依數；資料格式仍合法，但同名欄位或狀態含義已變。 | 少量共用契約、明確版本及依賴方向；測試實際交互；避免把所有內部細節都變成公開接口。 | PARTIAL |
| **PR-016 能力選錯、能力描述被誤當成可執行功能** | 索引名稱不代表能力已實作、已接線、依賴可用或有驗收證據。 | 能力卡列觸發／禁止條件、輸入、輸出、依賴、版本與測試；沒有實作或 caller 時不得路由為可用能力。P2 R3d130j 快照另發現 F15／F16 引用的測試路徑不存在、F27 的程式與測試引用位於 archive 路徑；詳見 2026-10-21 封包分析主報告 REF-01／REF-02。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-017 升級不相容、部分發布或回退失敗** | 新版只更新部分契約、插件、索引或測試；其餘元件提前使用新版本。 | 先驗證完整依賴集合，再切換路由；明確相容政策、版本指紋與回退版本；中途失敗時保持舊版有效。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-018 權限過大、插件副作用或供應鏈風險** | AI／工具獲得超出任務需要的讀寫及外部操作權限；不可信套件或資料可能帶入風險。 | 最小權限、明確寫入範圍、外部工具及來源審查、不可逆操作授權與工具前後政策檢查。 | PARTIAL |
| **PR-019 Current、藍圖、索引與派生視圖衝突** | 不同文件各自維護現況，造成多份互相矛盾的真相。 | 每種狀態只指定一個權威來源；README、索引與圖表屬派生視圖；衝突時回查權威並阻擋受影響工作。P2 R3d130j 快照實例：Current／Active Work 指 B1–B8 IN_PROGRESS，HANDOFF 仍指 R3d130k 的 W0／W1–W8；根 README 保留相衝的凍結舊投影，docs/README 對同一 Roadmap 同時寫「已被取代」與「唯一企劃」，並把藍圖版本標為 v1.1、而實際檔案標題為 v4.0。相關 OPEN-ISSUES 002c 仍待收斂；本次只讀取證，未修改 P2。詳見主分析報告。 | PARTIAL |
| **PR-020 確認過的差異與實際寫入內容不一致** | 確認後方案或基準又改變，或模糊的「更新」被解讀成授權全面修改。 | 寫入前重核基準、批准範圍與版本；任何變更須列差異、原因、影響及授權；超出範圍即停下重確認。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-021 規則寫入文件，但新會話沒有載入或遵守** | 文件存在不會自動改變執行行為；啟動入口、版本核對及失敗阻擋未必接線。 | 定義啟動載入及版本記錄，並將高影響更新前的職責／衝突掃描設為觸發式檢查；以新會話及同會話案例測試規則是否被實際採用。P2 離線案例已建立 State Bundle 草案與快照實例，但僅通過 JSON 結構核對；自動載入、過期偵測、衝突阻擋和跨會話行為均未測，不能視為 PR-021 已解決。詳見主報告、State Bundle 驗收紀錄及[本次根因診斷](./解析文檔/AI主動問題發現不足與治理閉環缺口_根因診斷紀錄_2026-10-21.md)。 | OPEN |
| **PR-022 角色分工名義獨立，實際權限與認知不獨立** | 不同角色若共用同一模型、同一上下文及同一錯誤前提，可能彼此複誦；角色名稱本身不構成存取控制。 | 用實際權限、資料邊界、不同驗證來源與外部可觀測證據建立獨立性；只增加角色數不算控制措施。 | PARTIAL |
| **PR-023 測試集錯誤、基準過擬合或指標被美化** | 測試可能共享錯誤假設；只追求速度或通過率，會誘導跳過查證或關鍵負例。 | 先定接受條件；加入負例、邊界及保留案例；審核測試本身；分開呈現品質、安全、成本和回歸率。P2 快照有 90 個局部案例全為 NOT_RUN，57 個未綁定 test_method；官方整批測試名單仍為空。不得由案例登錄、測試檔存在或歷史結果推論目前通過。另需參照 [治理更新對抗測試](./解析文檔/治理系統自我改善與一萬次更新壓力模擬_2026-10-21.md)，確認評估集與更新者的共因失效。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-024 無限研究、遞迴重試、成本失控或任務卡死** | 缺少停止條件、重試上限、預算或明確阻塞出口；研究也可能永遠不收口。 | 依資訊增益、目標、風險及預算決定是否深入；設停止／阻塞條件、重試限制和回退位置；允許維持現況。 | PARTIAL |
| **PR-025 能力關係分析規模爆炸或未知關係被當成相容** | 若新增能力都與全部舊能力逐一比較，關係數可能二次成長；證據不足也可能被錯判為「無衝突」。 | 先做相關範圍檢索；關係邊附來源、方向及版本；未知關係保持 UNKNOWN，不可自動判相容。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-026 有版本紀錄但不能真正恢復** | Git 回退只能還原部分檔案，不一定能撤銷外部 API、資料庫、遠端服務或其他不可逆副作用。 | 區分可追溯、可重現、可補償、可復原與可回退；對外部副作用設補償或人工恢復方案。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-027 無基線，無法證明新框架比簡單方案更好** | 文件完整、節點更多或流程更嚴謹，不能證明實際任務品質／成本改善。 | 用相同代表性任務比較簡單基線、固定流程及屬性導向方案；測量錯誤、返工、成本、延遲及維護負擔。 | OPEN |
| **PR-028 多檔更新只完成一部分，形成不一致版本** | README、責任矩陣、規格與能力索引可能依序更新；中途失敗會留下部分新、部分舊的狀態。 | 將一批相依更新視為同一變更單位；預先列更新清單；寫後逐檔讀回、核對引用與樹狀檔案；失敗明確標記未完成並修復。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-029 外部資料／工具行為改變而本地知識未更新** | 內容雜湊不等於語意新鮮度；API、授權、服務行為可能在本地文件未變時改變。 | 記錄來源與觀察時間；依資料易變程度設定重核條件；重大外部依賴必要時直接測試。 | PARTIAL |
| **PR-030 風險分級、變更優先序缺乏一致判準** | 只依檔案數、行數或主觀的「看起來複雜」分級，可能讓小而高風險的寫入走捷徑，或讓低風險改動承受過重流程。 | 依語意影響、權限、不可逆性、依賴範圍與失敗代價判級；安全、授權及資料完整性是硬性 Gate，不能被速度抵銷。 | DESIGN_DEFINED_UNVERIFIED |
| **PR-052 無 GitHub 可用上下文包，藍圖／舊交接被迫代替 Current，造成狀態重建偏差** | 無法讀取最新儲存庫時，沒有綁定來源版本、Current、Active Work、核心限制、證據及下一步的自足狀態包；模型以初始藍圖／部分摘要繼續推理，Current、README、HANDOFF 矛盾又放大偏差。這是 PR-001／004／005／019／021 的特定操作失效組合，不重複定義目標漂移本身。 | 建立由既有權威來源派生的可攜式 State Bundle，包含 Core Anchor、Current State、Task Contract、來源指紋、證據狀態及交接；缺失／過期／衝突時 fail-closed 為 BLOCKED_CONTEXT／STALE_CONTEXT；局部修改經 Core-Drift Gate 並以跨會話反例驗收。研究已提出，尚未驗證唯一產生／載入程序與跨會話行為。 | OPEN |
