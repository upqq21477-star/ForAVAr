# 壓縮檔與多格式文件解析步驟流程

- **版本：** 1.0
- **建立日期：** 2026-10-20
- **適用範圍：** 參考資料內的 ZIP／其他封裝檔、封包交接、多格式文件、程式碼與配套證據。
- **唯一目的：** 讓每次解析都可追溯、可分批續做、可驗收，並避免把「讀取失敗」誤判成「檔案損壞」或把「部分比對通過」誤稱為「完整無遺漏」。
- **專案權限：** 本專案只允許新增或修改 `upqq21477-star/forAVAr`。P1、P2 只能讀取，不得寫入、覆寫或刪除。

## 1. 標準流程總覽

```text
P0 盤點工作範圍與既有文件
 ↓
P1 登錄來源身分、保存原件
 ↓
P2 取得可解析的原始位元組
 ↓
P3 驗證封裝結構與安全限制
 ↓
P4 建立成員清冊及完整數量帳
 ↓
P5 依檔案格式抽取內容
 ↓
P6 分批分析並即時記錄
 ↓
P7 多格式差異與語意完整性檢查
 ↓
P8 去重、責任歸位、來源追溯
 ↓
P9 初步蒸餾與未知項整理
 ↓
P10 全批驗收、更新索引、交接續做
```

任一步驟未取得直接證據，都必須保留目前狀態與阻塞原因，不可跳級宣告完成。

## 2. 每次開工的必要規則

1. 先讀取 `參考資料/README.md`、`參考資料/去重與蒸餾規範.md`、`參考資料/解析文檔/跨文件重疊與唯一職責矩陣.md` 及主分析紀錄。
2. 先查既有文件是否已承擔該內容；優先補入既有唯一責任文件，不複製整段舊摘要。
3. 先確認要處理的原始來源、版本、Git commit／tree、檔案路徑與權限邊界，再開始抽取。
4. 不修改原始壓縮檔；所有抽取文字、檢查輸出、比較結果與蒸餾內容另存於分析文件。
5. 每次工作開始時寫出批次 ID、預期範圍、目標和驗收條件；結束時記錄成功、阻塞及未支援項目。
6. 結論必須區分直接檢查、已執行驗證、交接主張、推論、未驗證及阻塞。

## 3. P0–P2：來源盤點與原始位元組取得

### P0｜盤點範圍

- 取得目標 repository 的完整遞迴檔案樹，記錄查詢分支／commit、總檔數、封裝檔路徑及相關文件。
- 依副檔名盤點常見封裝格式，但須明確說明：副檔名掃描無法證明沒有無副檔名或偽裝副檔名的封裝。
- 查索引、原始檔案清冊、交接文件與既有解析紀錄，建立預期輸入清單。

### P1｜來源身分與保全

至少記錄：
- 原始檔名與目前儲存路徑。
- 來源 repository、分支／commit 或其他可核對版本。
- Git Blob SHA、GitHub 回報大小、檔案格式。
- 原始來源與解析副本的對應關係。
- 取得時間、工具／管道、結果與錯誤訊息。

**雜湊區分：** Git Blob SHA 是 Git 物件識別碼，不等於裸檔 SHA-256，也不等於 ZIP 成員 CRC32。未取得原始位元組前，不得聲稱已計算裸檔 SHA-256。

### P2｜取得實際位元組

依序嘗試可用且授權的取得方式：
1. 使用已核對的 repository 與檔案樹路徑。
2. 使用正式檔案內容／raw 取得路徑。
3. 使用可直接取得附件位元組的替代管道，並在取得後重新核對來源身分。

每次嘗試都記錄精確 URL／路徑、工具、錯誤、是否取得位元組及後續動作。不得將二進位內容強制當 UTF-8 文字讀取後，把解碼錯誤解讀為檔案毀損。

**404 判讀規則：** 若工具用的 repository 名稱大小寫、編碼路徑或 URL 與已核對的正式檔案樹不一致，該次 404 不能證明檔案不存在。應標記為「取得路徑驗證失敗」，先比對權威檔案樹。只有正式路徑仍無法解析且有對應證據時，才可記錄資源未找到。

原始位元組尚未取得時，狀態標記為 `BLOCKED`；不得列出猜測的成員清單、CRC、程式功能或測試結果。

## 4. P3–P4：封裝結構與防漏清冊

### P3｜結構驗證

ZIP 等封裝檔應在不執行內部程式碼的情況下檢查：
- 檔案實際大小與來源清冊是否一致。
- 封裝簽章、中央目錄、結束記錄（EOCD）及必要時的 Zip64 結構。
- 壓縮方法、加密旗標、成員數、路徑、壓縮／解壓大小及目錄記錄。
- 解壓路徑安全、檔案數與總解壓大小限制、巢狀封裝深度；拒絕路徑穿越與超出限制的輸出。

結構讀取失敗、解壓失敗、CRC 不符與內容格式不支援是不同錯誤，必須分開記錄。

### P4｜成員清冊與數量守恆

先建立每個封裝成員的逐項清冊，至少包含：批次 ID、成員原始路徑、大小、壓縮方法、預期 CRC32、實算 CRC32、格式、抽取狀態、解析文件位置及問題備註。

每批必須符合：

`預期成員數 = 成功解析數 + 明確阻塞數 + 明確不支援格式數`

若數量不相等，批次不得結案。巢狀封裝要建立子清冊，並清楚區分外層封裝成員與內層成員，避免重複計數。

## 5. P5–P6：格式抽取與分批解析

### P5｜依格式抽取

- **Markdown／純文字：** 保留標題層級、清單、表格、程式碼區塊、連結與原始順序。
- **DOCX：** 檢查 OOXML 套件；至少界定主文件正文抽取範圍。若要求完整驗收，需評估頁首頁尾、註解、文字方塊、超連結關係與其他相關部件，不可只靠主文件正文宣告完整。
- **原始碼：** 保留相對路徑、模組邊界、入口、匯入／呼叫關係、測試及配置關係。靜態閱讀與實際執行必須分開標記。
- **JSON／YAML／清冊：** 保留鍵名、型別、版本欄位、引用路徑與結構錯誤。
- **圖片、二進位資源或不支援格式：** 登錄存在、大小、來源和待處理原因，不可靜默略過。

每份解析副本都要標註來源封包、成員原名、抽取方法、抽取日期及原始範圍。

### P6｜分批處理

依內容性質分批，避免一次載入過量：
1. 啟動規程、manifest、索引及版本資訊。
2. Current／權威藍圖／核心規格。
3. 程式模組、模組依賴與主要入口。
4. 工具、腳本、設定與自動化流程。
5. 測試、驗收輸出及失敗紀錄。
6. 交接、歷史紀錄與待辦清單。
7. 其他資源、巢狀封裝及未分類項目。

每批完成後立即寫入分析紀錄：已讀成員、核心發現、來源位置、證據等級、與既有結論的差異、未讀項目及下一批 ID。不可等所有批次結束後才補記，避免漏掉過程中的阻塞與判定依據。

## 6. P7：多格式與語意完整性檢查

驗收分成不同層級，不得互相代替：

1. **位元組／封裝層：** 原件身分、結構、成員數、CRC。
2. **抽取層：** 預期成員均被讀取或明確分類。
3. **結構層：** 標題、章節、清單、表格、欄位及順序。
4. **文字層：** 正規化文字、段落及區塊的雙向比對。
5. **語意層：** 對差異逐段裁定是否屬實質缺漏、措辭變更、格式轉換、連結遺失或來源範圍差異。
6. **執行層：** 只有真的執行才可標記實際執行通過；靜態檢查、模擬與推論不能升級為執行證據。

Markdown／DOCX 比對需保留兩端原文、位置、差異類型、判定理由及未決事項。標題覆蓋、表格相同或文字相似度指標，都不能單獨證明全文沒有遺漏。

## 7. P8–P9：去重與蒸餾

### P8｜重複判定

- **位元組相同：** 以適當雜湊辨識；保留原始來源規則，不因已有摘要而刪除證據。
- **不同格式同內容：** 正規化後逐段比較，明確指定搜尋用 canonical 文字來源；仍保留原始格式與差異紀錄。
- **部分重疊：** 列出共用主張與各自獨有資訊，只合併摘要中的重複說法。
- **概念相似但職責不同：** 保留並建立交叉引用，不當作可刪除的重複文件。
- **不同版本：** 保存版本鏈與差異，不自行把最新版本等同唯一權威。

### P9｜初步蒸餾

每個核心項目至少保留：
- 一句核心結論與明確適用範圍。
- 必要機制、因果關係、前置與失效條件。
- 可驗收條件、反例或未解衝突。
- 原始來源位置、證據等級、推論／假設標記。
- 未知項、後續驗證任務與目前責任文件。

刪除重複背景、空泛修辭與沒有可驗收含義的宣稱；不得刪除限制、反例、版本資訊、負面證據或來源歸屬。

## 8. P10：結案與索引更新

每批結束必須更新：
1. `參考資料/解析文檔/壓縮檔逆向分析與蒸餾紀錄.md`：當前狀態、證據與下一步。
2. 封包專屬差異／完整性稽核：成員表、CRC、比對方法、差異與殘留缺口。
3. `參考資料/原始檔案/清冊.md`：來源身分、大小與解析狀態。
4. `參考資料/README.md`：每個正式分析產物的連結與 100 字內簡介。
5. 必要時更新文件唯一職責矩陣與整體完整性稽核，避免檔案樹、文件總數、索引與狀態彼此矛盾。
6. 發現錯誤、內容矛盾、格式損失或未解缺口時，建立穩定標記 ID，登錄證據、影響、狀態及下一步；在專屬稽核文件與主分析中交叉引用。已排除的工具假陽性也要記錄，避免後續重複誤報。

### 批次完成條件

只有在預期項目數量完全對帳、所有來源均有狀態、重要差異有判定、未知項有明確記錄、原始來源未被修改、索引及交接已更新後，才可將批次標記完成。整份文件的語意完整性仍須依其明確定義的驗收範圍另行通過。

## 9. 證據標記

| 標記 | 用法 |
|---|---|
| `DIRECTLY_INSPECTED` | 已直接讀取原始檔或確定來源的解析成員 |
| `PROGRAM_EXECUTED_PASS` | 有實際執行紀錄且檢查通過 |
| `SIMULATED_PASS` | 僅模擬或模擬測試通過 |
| `HANDOFF_CLAIM` | 交接文件的主張，尚未由原始來源重驗 |
| `INFERRED` | 依據明列事實作出的推論 |
| `NOT_VERIFIED` | 沒有足夠證據完成驗證 |
| `BLOCKED` | 已辨識阻塞，關鍵來源或執行條件仍不可用 |
