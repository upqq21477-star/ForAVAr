## 4. 歸檔／保全規則

1. 不修改兩個原始 ZIP 的位元組；分析與差異紀錄另存。
2. 任何解壓副本需記錄來源封包、成員原名、取得版本及 CRC32，不得冒充原始檔。
3. Git Blob SHA 用於辨識儲存庫中的物件；只有直接讀取位元組後才可計算裸檔 SHA-256、檢查 ZIP CRC，並驗證成員清單。
4. 原始來源更新時需新增版本紀錄，不得無記錄直接覆寫。
5. 「檔案存在」「可以讀取」「可以解壓」「CRC 通過」「文字等價」「語意完整」「實際執行通過」是不同驗收層級。
6. 解析程序的預期成員數必須等於成功解析數、明確阻塞數與不支援格式數的總和；對不上的批次不可結案。
