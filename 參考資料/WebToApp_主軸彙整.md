## 1. 核心發現

WebToApp 不只是以 WebView 載入網站；其架構涵蓋應用定義與編輯器、APK 建置／修改／簽章流程、生成應用的 Shell 執行環境，以及多種平台執行能力。關鍵資料鏈是統一的 `WebApp` 設定經映射形成 APK 設定，再序列化為 `app_config.json`，由生成後的 Runtime 讀取並執行。

重要工程觀察：

1. 開發工具與生成後的應用分離，降低編輯器和執行環境的責任耦合。
2. 跨層資料契約是高風險點：匯出端和執行端欄位命名不一致時，功能設定可能被忽略或落回預設值，而 APK 建置仍可能成功。
3. 設定欄位漂移檢查、序列化／反序列化測試及實際 Runtime 測試是不同驗證層，不能互相代替。
4. APK 重建涉及 Manifest／資源表調整、資源注入、原生程式庫及簽章；不等同於簡單包裝網站。
5. 增量建置、內容指紋與同套件併發互斥有助於控制成本和競態，但指紋是否涵蓋所有產物依賴仍需完整測試。

這些是依指定原始碼快照和專案文件形成的靜態分析，不代表所有功能均已實機驗證，也不代表 forAVAr 已具備相同程式或行為。
